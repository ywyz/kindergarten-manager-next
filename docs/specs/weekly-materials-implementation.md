# 周计划材料候选、采用与W6补验实施规格

状态：2026-10-03规格收敛。用户已确认：**采用AI材料候选后负责人可编辑／清空；无候选时继续保留空栏。** 来源改选后的触发方式见实施索引P3。材料尚未实现／产品验收未通过，不因规格落盘转为通过。依据：[周计划Contract](../modules/weekly-plans.md)、[最小规格材料规则](manual-plans-and-word-export.md)、[用户阶段决定](../bootstrap/i5-evidence-closeout-and-scope-decision-2026-10-03.md)、[原文参考提取](../bootstrap/i5-material-reference-extraction-2026-10-03.md)。

## 1. 已确认业务边界

AI根据所选游戏／重点区域名称、目标、指导、支持策略及班级年级，优先提取明确用品，不足时生成补充建议。提取和补充均先形成候选，负责人采用、编辑并确认；只存周计划，不回写日计划。不把支持策略全文当材料，不从原文未提及的差集推断“AI建议”。

材料填入现有周模板重点区域的材料栏，不增加Word正文来源说明或新增模板。可空、不完整确认和旧已确认导出规则保留；AI失败保留现有材料和人工内容，材料空不强制等待AI。管理员可编辑已经采用的材料，产生待确认草稿，仍不能替负责人采用候选或确认。

同类别同名游戏单名额、选择一个完整来源、组共用目标指导和负责人改选规则不变；材料不能将A目标与B指导拼成虚构来源。来源改选后已有材料保留真实依据并标陈旧，不静默标成基于新选择。

## 2. 输入快照和生成顺序

`MaterialBasis`由服务端构建：weekly_plan_id、draft_version或不可变games_candidate_id、owner_epoch、班级年级值及配置版本、所选outdoor槽与focus_area的完整内容、日引用的plan／content id＋version／group／game／section；手工／AI补充游戏保留真实kind和稳定item_id，没有日引用则为null。

材料用于重点区域栏目，必须有明确focus_area；无重点区域不猜选一个，任务暂停为`MATERIAL_CONTEXT_REQUIRED`，保留已有值。其余所选游戏可作为补充上下文，但每个明确提取项标明实际依据位置，不能把晨间／重点区域用品混称同一引用。

周游戏自动重选成功时先持久保存游戏候选，随后登记依赖该候选ref的材料任务；材料按该**确切选择候选**生成，不能抢读当前人工草稿当作同一个来源。负责人可先采用游戏，再等材料；游戏候选未采用时，材料候选仅可在同时明确采用其游戏组合或当前选择精确匹配时采用。改选另一个来源后旧组合材料不能当最新采用。

负责人明确发起材料任务时从已保存草稿选择构建输入；本地dirty游戏／支持策略先显式保存，不把本地未保存内容暗中提交生成。材料候选绑定选择输入hash，主题／其他无关栏目改动不单独使材料陈旧；整份草稿采用仍遵守expected_draft_version。

## 3. 输出字段与证据校验

系统输出为`items`列表，每项含`text`、`origin`（`extracted`／`suggested`）、`evidence_refs`。origin=extracted的每个ref含启动快照中的source_ref、field_path、原文quote；origin=suggested不伪造引用，可说明建议理由。数量或“足够”的固定标准没有已确认值，不按技术便利补造强制清单。

服务端必须校验ref确实存在且quote是该字段原文片段；材料名称与片段依据可追溯。引用存在只能证明文本有依据，不能保证AI语义提取正确，仍由负责人预览。无具体用品原文可以没有extracted项并给补充建议，不把泛称“材料／工具”猜成具体用品。

工程限额：最多100项，每项材料text 300字符、quote 2000字符，候选合成材料文本总长最多20000字符；超出拒绝完整候选，不截断采用。供模板的文本保持多行字符串，项目顺序保留；相同材料允许预览编辑合并，不自动跨来源丢证据。

## 4. 业务存储与兼容

`weekly_ai_candidates`保存task_type、execution_id唯一、basis快照／hash、实际配置／提示词版本、结构校验后payload及来源过期状态；候选append-only，正文归周计划模块。采用事件记录candidate_id和采用者／时间。task表只存候选ref。

草稿及确认content扩入：

- `materials`：null或最终采用并编辑后的纯文本，沿用I5 view model已有字符串映射。
- `materials_provenance`：null或candidate_id、原生成basis、提取／补充项及证据、original_candidate_text、是否人工改动、采用者、采用时版本。编辑后不把新增手工文字标为AI提取项；保存实际人工编辑标记和候选原项对照。

材料正文与依据均进入每次新草稿和**自包含确认快照**，不能只存指向可变草稿的ref。历史I4无这些字段按materials=null／provenance=null解释；不得批量更新历史确认JSON。I4中`apply_patch`将materials强制置null、`build_facts`非空即拒绝的规则只在材料实现授权后最小扩展；历史文档保留其当时限制。

普通PATCH只可对已有materials_provenance的当前草稿编辑／清空materials，客户端不可写provenance、basis或“最新”标志。无候选直接填非空材料拒绝422；采用候选端建立可信provenance。清空后仍保留采用与编辑历史，不将空字符串算完整材料。普通保存不能意外把旧材料归零或吞掉依据。

## 5. 采用、修改、陈旧与确认

拟定`GET /api/weekly-plans/{id}/ai-candidates`／`.../{candidate_id}`；`POST .../{id}/adopt-ai-candidate`输入candidate_id、expected_draft_version、selected_fields／期望来源hash。材料采用仅负责人，按现有I4锁序重新校验当前选择、来源、owner_epoch、候选schema；不接收客户端完整材料依据。

采用创建新草稿版本，不创建确认。已经采用同一候选且业务版本未变时同一client_request_id幂等返回；旧版本409保留输入。负责人可预览提取／补充与原文位置后采用；游戏允许覆盖人工游戏，其他栏目／材料需明确选定替换，未选字段保持原样。

`facts.missing`仅当最终材料null／空白时列materials；`facts.stale_sources`扩入`materials_basis_changed`（当前选择／相关文本／来源版本／年级与原basis不同）、`materials_source_missing`（实际引用已删除或不再有效）等服务端事实。候选过期不能作为最新采用，但已采用旧材料可与当前已有内容一并显式ack_stale确认，保留旧basis；ack不把陈旧标志清零。

确认继续I4已有草稿版本、来源重读、facts重算、409后重新展示和ack_missing／ack_stale协议。新事实参与expected_context／并发校验，不能沿用用户未见过的旧ack直接通过。日来源再次变化需要再次409，dirty表单不自动重基；管理员修改材料新草稿仍须负责人确认。

手工改材料不会改变实际生成basis；负责人改选A→B、支持策略改动或来源升级时保留旧正文与依据，页面显陈旧。是否自动排队重生成按P3确认；无论采用何方案，新返回材料都只进候选，不覆盖人工编辑。

## 6. 原文样例的使用

[仓库JSON参考](../bootstrap/i5-material-reference-fixture-2026-10-03.json)包含11个日计划游戏组与5份周计划材料，D01／D08同名蜜雪冰城不同来源可供依据改选；W02／W03可供非空材料栏版式参考。保留原文定位，不将原文件日期当验收计划身份；不复制旧业务实现或旧生产数据。

这些原文不是AI候选、真实调用或运行默认值。制作夹具时通过正式日计划API保存合成内容、服务端分配id，随后AI候选→采用→编辑确认，不直写确认快照。需要模拟AI时明确标“模拟”，仅作为确定性自动测试；产品能力真实AI补验必须记录供应商实际输出和依据，不能用参考清单充当输出。

| 编号 | 动作与通过条件 |
| --- | --- |
| M1明确提取＋补充 | 使用带明确用品原文和补充需要的正式输入；真实候选保留extracted／suggested区别，提取ref可追溯，负责人预览采用、修改并确认 |

| M3同名A→B依据 | 合法选择完整A来源、采用材料，改选同名B，目标指导完整跟随B；旧材料仍basis=A且facts陈旧，不冒充B；显式重新生成／采用后basis=B，历史A确认不变 |
