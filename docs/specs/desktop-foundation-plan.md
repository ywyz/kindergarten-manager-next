## 2. 下一步的目标与理由

优先验证 **Windows 11 桌面窗口 → 本机 API → SQLite 保存 → 完整退出后重读 → Word 文件落盘**。通过后再接入实际本地档案和手工日计划流程，随后完成 AI 闭环。这样可先获得桌面容器、打包、数据位置和文件保存的直接证据，再投入业务适配。

D0 采用合成数据和明确的技术验证入口，不冒充每日活动计划已完成。D1 必须使用真实业务模型、配置、日计划页面与导出链路；D2 才完成拆分、适龄调整和其他活动生成。两者验收不能由 D0 探针代替。

复用审查结论：Vue 页面与组件、内容映射、Word 生成器有保留基础；主要改造集中在启动入口、身份和配置权限、数据库约束与事务、任务执行和文件保存。不做全量 UI 重写，也不估算未经验证的“复用百分比”。

## 5. D0 最小工程范围

### 5.1 实现边界

- 使用隔离的桌面验证入口与合成数据目录，不挂载旧管理员／账号／计划业务接口，不启动旧 MySQL 服务。验证结果不得写入实际教师数据目录。
- 验证 pywebview＋WebView2、Python／FastAPI／Uvicorn、本地 SQLite 及现有 Vue／Element Plus 构建产物的组合；新依赖版本及原生运行条件由 OpenCode 先列清单并锁定，沿用当前语言和一级技术栈。
- 以本机 HTTP 提供前端与 API 同源入口，绑定回环地址，服务就绪后再打开窗口。pywebview 加载本机 URL；不将 FastAPI 当成 WSGI 对象直接传给容器。端口选择、失败提示及退出清理必须可验证。
- 使用每次启动的应用会话材料验证 API，并精确校验允许的 Host／Origin；GET 读取合成状态与写入均不得因无登录界面而开放为无保护数据接口。引导页或健康检查若无需会话，不得暴露业务内容与凭据。令牌不写 URL、业务库或日志。
- SQLite 探针保存一条合成记录及版本，提交后返回成功，完全退出再启动仍能读回。记录驱动与 SQLite 版本、外键开关和事务方式；该探针不替代 D1 真实表约束与竞态验证。
- 使用现有日 Word 生成器和合成映射输入、仓库模板生成有效 DOCX，通过验证窗口执行真实保存。若浏览器下载方式不能可靠报告结果，评估最小宿主保存接口；不提供任意文件读取或任意命令执行桥接。
- 首先验证 PyInstaller 目录式测试包，打包 Vue 资源、Word 模板与所需运行资源；输出目录与前端构建目录分开。普通用户运行时不能要求教师自行运行 Vite、安装 Python 或手动启动 API。安装器、签名发行与自动更新不在 D0 中完成。
- 验证启动、窗口关闭、完整退出与异常结束后的资源回收。D0 没有真实 AI 请求，不能据此宣称 AI 取消、休眠恢复或任务恢复已通过。

pywebview 的本机服务方式、会话令牌和 Vue 资源打包有官方说明；它们支持这条验证路线，不构成当前组合已通过的证据：[应用结构](https://pywebview.flowrl.com/guide/architecture.html)、[API 防护](https://pywebview.flowrl.com/guide/security.html)、[打包](https://pywebview.flowrl.com/guide/freezing.html)。

| D0-5 | 生成合成日 Word，选择含中文及空格的路径保存 | 非空 DOCX、ZIP 完整、可在 Windows Word／WPS 打开；记录取消和真实保存结果 |
| D0-6 | 取消保存、选不可写位置／被占用目标、失败后重试 | 取消不报成功，失败不留下误导文件或损坏已有文件；重试可完成 |
| D0-7 | 在不依赖本仓库工作目录及开发环境的条件下启动测试包 | 资源与模板路径正确；WebView2 条件满足或给出明确缺失提示；验证环境边界如实记录 |

D0-5 是容器文件交付验证，不代替 D1 的范围、缺项、版本、标红、分页和真实日计划全流程验收。自动测试、Windows 操作、打包及 Word／WPS 检查分别记录；缺少桌面操作能力时保留未执行项，不能以纯 API 或模拟页面冒充通过。

## 6. D1 已落定的工程契约与切片

Codex 已完成[五项技术核查](../bootstrap/desktop-d1-technical-review.md)，具体实现与验证以[D1 规格](desktop-manual-daily-plan.md)为准：

1. **本地上下文。** 稳定单档案 ID、首次资料一次原子提交、初始化重试幂等；不复用旧账号、管理员或分班。
2. **SQLite 新基线。** 独立本地 metadata 与 Alembic 迁移链；复合延迟外键、非空版本指针、有效日计划局部唯一索引；D0、旧 MySQL 和正式业务库隔离。
3. **事务与错误。** 每连接 FK、显式短写／读事务、有限忙等待、预期版本拒绝、约束分类及整体回滚。内存原语实验通过，真实模型、Alembic、文件库竞态须在 D1A 编码后验证。
4. **日计划与周来源。** 写入、读取 DTO 和后续页面一起解除旧全班周投影依赖，保留本人日内容版本，不提供假同步状态。
5. **离开和导出。** 用户确认关闭／切日期／离开编辑页先自动保存、失败留页；D1B 实现统一页面与宿主协调。导出仍读数据库已保存版本，不因离开规则变成导出自动保存。

当前先编码 D1A 本地数据与手工日计划 API；D1B 再做配置维护、真实页面和 Word 交付。D1A 通过不等于教师桌面闭环完成。配置维护交互及已有计划后的修改／切换范围在 D1B 前细化，不能照搬第一份计划后永久冻结配置。真实 SQLite 约束、回滚、重复创建、过期保存和一致读取按新规格验证；已有 MySQL 或 D0 测试不替代这些证据。

## 7. D2 的 AI 验收重点

既有 AI 1A–1C 是配置与提示词能力，不能因为设置页面已有就把真实调用、持久任务和候选采用视作完成。D2 先明确供应商协议、凭据保管、持久任务与会话生命周期，再实施日计划三类能力。

真实调用须记录排队／连接／供应商响应／总耗时等可获得阶段时间，并区分网络等待与界面阻塞；不对尚未测得的响应时间承诺固定数值。验证运行期间仍能编辑、失败内容保留、结果不明不自动重发、候选不覆盖人工输入，以及实际拆分基准用于最终 Word 比较。供应商不提供的阶段数据标为不可得，不推测。

真实付费调用使用获授权的私密配置，不从旧服务器提取密钥。WebDAV、遥测与更新不可用时，本地手工流程仍可运行。
