## 2. 三类AI能力的边界

Q2已确认三类能力分别由教师明确触发；不自动串联，也不因保存正文、采用候选或修改设置自动调用下一类AI。三类能力按需使用，不强制每次全做。

| 能力 | 可沿用的输入／输出边界 | 必须保留的保护 |
| --- | --- | --- |
| 教案拆分 | 输入完整原文及适用年级；输出集体活动六字段。按已审查默认指导摘取，原文未写的字段可为空，不顺带补写新教案 | 保存输入来源与未经教师修改的拆分结果；即使预览中改过过程，也不得将改后过程存为原始拆分基准 |
| 过程适龄调整 | 输入明确的拆分过程或已保存过程、适用年级；仅输出完整过程建议 | 不改原文和拆分基准。手工计划可用当前过程调整，但无原始拆分基准仍不能宣称有原文标红依据；新旧年级选择见Q5 |
| 其他活动生成 | 输入目标日期、周次／星期、有效日历与节假日上下文、游戏配置版本、该日内容快照；输出四板块 | 保留游戏组共用内容；不输出反思、不改集体活动六字段、不伪造来源ID或实际教学事实；游戏配置见Q4 |

原始材料、个人指导和模型回复均不能改写系统结构、权限或保存规则。候选与业务保存schema分开，组／游戏等业务ID由服务端产生；模型返回的ID不可信。原始回复只在业务候选需要的范围内保留，不复制到诊断日志。

## 4. 已确认方向下的流程与工程细化

本节落实§3已确认流程；候选编辑、版本复核和任务恢复的工程细化见§9–11，仍不构成编码授权。

1. **设置一次即可使用。** AI设置维护地址、模型和密钥；三类任务有默认指导及个人修改入口。设置保存不暗中试调用。班级游戏配置按Q4维护，不重新要求初始化档案。
2. **读取目标计划。** 显示日期、现有内容及适用年级。粘贴或编辑原文后，点击AI操作时先完成当前正文的保存，再固定输入快照；保存失败不发请求。继续编辑不会更改已经固定的输入。
3. **任务运行与反馈。** 页面显示等待、处理中、候选可查看或失败原因；不显示虚构百分比。允许编辑正文和按Q6离开页面；任务通知不重置编辑器的未保存文字。
4. **查看与编辑候选。** 对照所用原文／过程和候选。原始拆分结果不可变，教师预览编辑另存为采用内容。关闭预览不等于采用；已完成候选可再次查看。尚未采用的候选编辑有改动时阻止直接离开并保留输入；教师可采用并保存，或明确取消本次预览编辑后离开。原候选保持可查，不静默丢字，也不增加完整崩溃草稿恢复。
5. **采用并保存。** 采用前先保护当前编辑草稿，再核对候选实际依赖的输入、将替换的字段与当前内容版本。依赖或目标字段已变化则保留候选及人工内容、提示重看／重新生成，不能自动强行覆盖；无关字段变化不必重做收费请求；依赖变化与目标变化分别按§9.3处理。
6. **继续备课。** 可以再手改、按需做适龄调整或其他活动；AI故障不影响已经保存的内容。采用拆分才建立该次原文与拆分基准的关系；以后手改或适龄调整均不覆写基准。后来修改原文也不偷偷改掉已采用基准，需明确显示其来源，采用新拆分后才切换关联。
7. **比较与导出。** 最终已保存过程与同一版本关联的原始拆分基准比较，再沿用D1原生另存为和固定Word模板。不会导出尚未采用候选，也不会因导出自动保存正文。

采用成功应原子追加内容版本、保存来源／基准关系和操作记录。多次点击或响应丢失后查询不能再采用一次。手工PATCH仍禁止提交`split_baseline`，不能为了AI功能取消服务端来源校验。

## 5. 由Codex与OpenCode收敛的工程方案

以下工程方案已在[工程规格](desktop-ai-engineering.md)完成E1–E5设计核查，不是要求用户决定技术细节，也不是现有实现事实。

| 项目 | 本轮建议／必须细化的内容 |
| --- | --- |
| 执行组织 | 主进程单协调线程＋每次尝试一个spawn子进程，Job Object收口；SQLite持久状态、全应用一个在途请求，网络在事务外；具体许可／IPC／退出见工程规格§4 |
| 本地凭据 | 现有AES-256-GCM＋Windows当前用户DPAPI，独立凭据目录／受限ACL；明确清除及损坏重填，换机重新填写，具体见工程规格§3。无新增运行时依赖，不使用旧`.env`加载链，不启动WebDAV密钥同步 |
| 最小协议 | Q7已确定OpenAI兼容方向；`chat_completions_v1`文本JSON子集已按2026-10-21确认需求扩展流式思考展示，详见§11。供应商和模型可配置，工程保护与错误映射按规格记录；不宣称真实兼容通过 |
| 状态与恢复 | 区分排队、已领取未发送、可能已发送、成功候选、失败、暂停、结果不明；“用户停止等待”和供应商处理结果分开。发送标记先落库；发送窗口中断按可能发送处理；候选入库与任务成功同事务，迟到响应不能复活已退役执行 |
| 取消与重试 | 未发送可以取消；已发送只停止本地等待并保留真实结果状态。最多初次＋2次，间隔5／30秒，仅可证未发出的暂时错误；基础适配器不把429／5xx当未处理证明。具体错误及超时见工程规格§4 |
| 版本与来源 | 分开管理本地配置、AI配置、提示词契约／默认／个人指导、输入快照、任务执行、候选和内容版本。拆分／适龄／其他活动各定义实际依赖字段，不能只看“任务成功”或粗略全局版本。旧计划周次和表头继续读取计划自身快照，不因AI更新改归属 |
| 候选采用 | 只接受受校验候选引用及允许的教师编辑；服务端校验来源、目标字段、编辑版本和幂等键，分配组／游戏ID，原子提交。原文变化、基准变化、班级游戏配置变化、重复结果及采用冲突均有确定行为 |
| 游戏配置与提示词 | 根据Q4新增真正可维护且有版本的配置；只暴露D2三类任务指导。新默认指导建议随应用版本提供，支持接受已查看修订、拒绝和必需字段适配；不增加在线模板管理后台 |

## 9. 输入、数据和采用契约

本节为落实已确认流程的工程设计。具体物理表／约束、API和迁移要求以[工程规格](desktop-ai-engineering.md)为准；W1已实现数据及凭据基础和最小配置接口，其余任务／候选／采用接口仍待后续工作包。

### 9.1 配置和任务输入

**班级游戏配置的最小字段：** `locations`为地点列表，每项含`kind=area/special_room/outdoor`、`name`和可空`guidance`；另有可空`game_scope`（游戏范围）和`guidance`（通用限制／指导）。空配置即空列表与空文字，明确显示“未设置班级游戏配置，本次生成一般建议”，仍可发起任务。先采用每类最多30个地点、名称1–80字、单项指导最多2000字、两项总体文字各最多8000字的工程输入限额，不截断保存；无星期排班、材料库存或新身份对象。

配置随当前班级维护，按既有预览／确认应用路径扩展`class_games`变更类型；应用时增加配置版本，并产生可被任务引用的不可变`game_config_revision`。当前姓名等无关配置变动不应仅凭全局版本变化使候选失效；依赖复核比较实际游戏配置修订。配置改变不重写旧计划或自动生成新候选。地点名单与指导原样进入受控业务输入；自然语言限制不是已完成的机器规则引擎，候选仍需教师审阅。

**AI配置：** 单套当前配置包含`protocol_id=chat_completions_v1`、`base_url`、`model`、加密凭据引用和独立`ai_config_version`。模型是可编辑的供应商模型标识，不预填具体型号或维护供应商品牌白名单。保存只做格式／安全及加密验证，不执行模型调用，不要求供应商提供`/models`接口。返回`has_secret`、`configured`和`ready/reason`，不返回密钥尾码或密文；“配置就绪”不等于已连通或模型已实测。

**输入固定：** 点击AI操作先保存当前正文；无修改不新增版本，保存失败不登记任务。请求带计划当前版本和本次`target_grade`（默认计划快照年级）；服务端读取真实内容并生成不可变输入。任务排队期间正文可继续修改，不能暗中把新正文替换到旧任务。开始前依赖已变则暂停为`source_changed`，由教师重新发起；AI配置／个人指导则按已确认规则在开始时取最新有效版本。

| task_type | 生成所需的业务输入 | 将替换的目标 |
| --- | --- | --- |
| `daily_lesson_split` | 非空原始教案、明确目标年级；来源为保存后的原文版本／hash | `group_activity`六字段整体；同时建立未经预览编辑的拆分基准和对应原文引用 |
| `daily_process_adapt` | 当前已保存的非空过程、明确目标年级；保留其基准关联供比较，不自动回退到更早过程 | 仅`group_activity.process`，不改主题、原文或基准 |
| `daily_other_activities` | 计划自身日期／周次／星期、明确目标年级、当前适用的已持久日历上下文、前后7日节假日、游戏配置修订、集体活动和四个活动板块的保存快照 | 由教师从`morning_games`、`morning_talk`、`post_group_games`、`afternoon_outdoor`选择；不含反思 |

其他活动不要求先完成拆分；集体活动为空时按现有信息生成一般建议。其输入不重复发送与生成无关的反思、姓名、密钥、整段原文或其他日期教案。缺少某板块的候选不能被当作“清空该板块”；省略板块不可勾选，明确空值按schema校验并在采用预览显示。

### 9.2 持久对象与不变条件

| 逻辑对象 | 必需保存的事实 |
| --- | --- |
| AI配置／个人指导版本 | 本地档案归属、不可变版本和当前指针；执行引用的版本保持可追溯。字段契约／默认指导／个人修订分别记录；无账号与管理员依赖 |
| 业务输入快照 | 计划ID、内容版本、任务类型、目标年级、实际使用的内容与依赖修订、规范化hash；只能由服务端从本地业务数据建立 |
| 任务／执行／尝试 | 提交幂等键、运行代次与执行许可、状态／原因、开始时AI配置和指导版本、尝试编号、发送标记、可获得的耗时和脱敏错误；任务不以浏览器存储为权威 |
| 不可变候选 | 执行唯一引用、任务类型、输入来源、校验后的原始候选及schema版本；教师预览编辑不修改此对象 |
| 内容来源关联 | 新内容版本与采用候选、输入原文、拆分基准的绑定；人工保存沿用既有基准关联，不得从最新可编辑原文重建旧基准 |
| 操作回执 | 同档案D2 AI操作全域唯一`request_id`、规范化请求指纹、实际结果版本／对象；同键同请求读回原结果，不同域或请求409；含secret用HMAC且不保存明文摘要，见工程规格§3；采用／任务提交不能重复执行 |

继续使用SQLite短事务、FK、唯一键和条件更新；所有网络及用户等待都在事务外。旧D1内容保持`split_baseline=null`且原版本不变；非null基准只有同时具备有效来源关联和正确结构才合法。不能把D1“拒绝所有非null”简单改成“任意JSON均可”。基准损坏、跨计划候选、失效执行或来源关系不一致仍拒绝读取／采用，不静默清空。

### 9.3 预览、人工修改和采用

1. 候选生成时记录输入依赖和目标字段的原值指纹；打开候选时显示候选及当前正式字段。前端的候选编辑与正文编辑分别维护dirty状态，模型结果通知不推进任一编辑基线。
2. 有正文草稿时，采用前先按D1保存并等待成功；未保存候选编辑则留在当前预览，不因重取任务状态丢失。候选预览的关闭／离开保护沿用明确取消思路：采用并保存，或取消本次候选编辑恢复原候选后离开。
3. **生成输入已变化：** 原文／适龄所用过程／其他活动所用内容、日历上下文或游戏配置发生实质变化时，原候选仅可查看，返回`AI_SOURCE_CHANGED`；重新生成必须由教师点击，不自动收费重做。
4. **仅待替换目标变化、生成输入仍有效：** 不允许用旧预览覆盖新内容；重新展示当前目标与候选，教师可再次明确采用，不强制重跑模型。拆分场景中编辑六字段而不改原文属于此类；适龄的过程同时是输入，过程变了按上一条处理。
5. **无关字段变化：** 如拆分期间修改反思，保存该修改后可重新获得当前版本的采用预览，无需重发AI；采用只替换确认目标，未选板块保留。
6. 后端给出绑定候选、选定板块、候选编辑payload hash、输入依赖、当前内容版本／目标指纹的短期预览凭证。采用提交带`request_id`、该凭证及预期版本；在写事务内重验、分配新组／游戏ID、追加内容／来源关联和操作回执，提交成功才响应。预览过期／任何事实不符返回冲突，保留两边内容；不得接受客户端任意基准或来源ID。
7. 拆分采用的基准使用模型未经人工编辑的原始拆分过程；正式六字段用教师预览后版本。适龄、其他活动和后续手改均保留基准。修改原文后旧基准仍注明其已采用来源；采用新拆分才切换基准引用，历史内容不改。
8. 采用响应丢失时先查同`request_id`回执；查不明就保留状态，不换键再次采用。回执返回当时结果版本，若当前正文已推进，应读回最新并提示，不把旧回执覆盖当前编辑器。

| 接口 | 主要输入／输出与行为 |
| --- | --- |
| `GET/PATCH /api/local/ai/config` | 读取脱敏配置；写入`request_id, expected_ai_config_version, base_url, model`及可选新secret。省略secret保留，空值不冒充保留；清除用独立操作。配置版本独立于班级配置版本 |
| `POST /api/local/ai/config/clear-secret` | 明确清除、预期版本与幂等键；生成未配置新版本，不修改已发送执行所钉住的历史版本 |
| `GET /api/local/ai/prompts`及各任务详情／保存／接受默认／拒绝／适配操作 | 只列日三类任务，沿用已确认字段指导和默认修订规则；写入有幂等键及个人预期修订；具体payload沿既有1B契约做本地化映射，不继承旧身份权限 |
| 既有`/api/local/config/preview`、`apply`扩展`class_games` | 游戏字段与修订预览、确认后应用；保留现有草稿关闭保护和结果查询；不得因增加AI设置改变原D1操作含义 |
| `POST /api/daily-plans/{id}/ai-tasks` | `request_id, task_type, expected_content_version, target_grade`；202返回任务／执行／状态。只读回执重传不登记第二份；不同键对同计划同类尚活跃任务返回`AI_TASK_ACTIVE`，不暗中多排一次 |
| `GET /api/local/ai/tasks`、`GET /api/local/ai/tasks/{id}` | 有界分页及计划筛选；返回状态、原因、可执行动作、实际版本和候选引用；不返回密钥或日志正文 |
| `POST .../tasks/{id}/cancel`、`resume`、`retry` | 带`request_id, expected_execution_id`；分别停止、恢复明确未发送任务或创建新执行。结果不明重试另需显式费用风险确认；恢复不是重发已发送任务 |
| `GET /api/daily-plans/{id}/ai-candidates`及候选详情 | 读取本计划候选、实际来源、当前可采用状态；已完成候选重启后可查；不自动刷新正文 |
| `POST /api/daily-plans/{id}/ai-candidates/{candidate_id}/preview-adoption`、`adopt` | 预览带当前版本、选定板块与教师候选编辑；采用带预览凭证和幂等键。成功原子追加一个内容版本；冲突保留输入 |
| `GET /api/local/ai/operations/{request_id}` | 查询配置／任务／采用等实际回执，限定本地档案、D2 AI键跨操作域唯一；只读、不重放供应商请求 |

任务存在但运行失败通过任务的`status/reason`表达，不把状态查询本身返回为HTTP失败。业务请求继续使用422参数错误、409版本／来源／状态冲突、503存储或本机运行不可用；完整字段、错误字典、指导操作和预览凭证见工程规格§5。

## 10. 任务状态、退出和恢复契约

状态服务端持久化；候选是否已采用和任务是否成功分别记录。下表的“发送”是应用有证据可能发出的边界，不能推断供应商实际开始或收费时点。

| 状态 | 进入条件 | 允许动作与恢复 |
| --- | --- | --- |
| `pending` | 已持久登记，未领取 | 可取消；应用当前正常会话内等待调度；重启后改为等待手动继续，不自动调用 |
| `claimed` | 短事务领取、钉住配置／提示词，尚无发送标记 | 可撤销许可；中断且可证明未发送则暂停等待继续，不能让失效执行稍后发送 |
| `dispatching` | 发送标记提交，准备发送或正在等待 | 可停止本地等待；中断且无已提交候选时进入`outcome_unknown`；候选校验并落库成功才转`succeeded` |
| `retry_wait` | 有证据证明未发送／未处理的临时失败，尚在限次预算内 | 会话内可有限重试；关闭／重启后暂停，需手动继续；每次发送前重新核查许可与业务来源 |
| `paused` | 未配置、未适配、来源变化、正常退出／重启等待等 | 显示具体reason；只在原因已消除且用户明确继续时恢复未发送任务。来源变更需重新发起，不能用“继续”暗中换输入 |
| `succeeded` | 受校验候选与任务成功在同事务提交 | 可查看／预览采用；不自动写正文；关窗及重启不回退为待发送 |
| `failed` | 输出错误、明确不可恢复错误或安全重试耗尽 | 保留已有内容；可明确新执行重试，不自动切供应商／模型或付费修复JSON |
| `outcome_unknown` | 可能已发送，无已提交确定结果 | 无自动重发；用户明确接受可能重复处理／计费后方可新执行；配置修改或重启不解除该限制 |
| `cancelled` | 用户取消且已确认没有未决外部处理 | 终态；不能将“可能已发送”的停止伪装为此状态。若已有一次安全失败的重试等待被取消，保留历史尝试记录 |

执行许可必须具有代次或token，发送前及结果落库时均复核；同执行候选唯一。进程误重复启动、失去许可后晚到结果、取消与完成竞争都由SQLite条件更新／唯一约束裁决，不能只用前端disabled或内存布尔量保证。旧候选可查看但已过期的来源另用候选适用性表示，不把“任务成功”改写成“可强制采用”。

**正常离开：** 切日期／回工作台仍先完成D1保存，已登记任务继续；未采用候选编辑先按§9.3解决。页面卸载不取消或丢失任务，重新进入从数据库查询。

**正常关窗：** 进入关闭协调后先阻止新任务调度，继续D1正文／设置／候选草稿检查；有未解决草稿或保存失败则留页。任务仍在时显示已确认的两个选择：“继续等待”取消本次关窗并恢复正常调度；“停止等待并退出”撤销执行许可，将未发送任务暂停、可能已发送未确定任务记为不明，然后停止本地等待并收尾。若候选提交先赢得竞争则保留成功，不再改为不明。状态持久化失败不能报正常关闭成功。关闭超时／失联保护仍沿D1协议，不绕过旧防误关流程。

**重启／休眠：** 先按实际持久状态恢复，不将所有running重置pending。重启后的未发送任务须手动继续；可能已发送的中断不重发；已提交候选保留。休眠后若原执行仍能取得确定响应并持有效许可，可正常提交；无法确认结果或许可失效时保守处理，不靠租约过期重复发费请求。不能保证恢复供应商端尚未返回的调用。

**取消后迟到响应：** 许可已撤销的旧执行不得写新候选或覆盖状态；此前已提交成功则返回实际成功。用户“停止等待”意图和外部结果状态分别保存，界面不能只显示一个“已取消”掩盖可能处理的事实。

## 11. OpenAI兼容接入边界

2026-10-21用户确定应用使用DeepSeek官方API与MiMo标准API，不使用Token Plan／Go；确认思考默认展开、可折叠并展示阶段／已等待时间，详见[流式思考与等待反馈](desktop-ai-streaming-progress.md)。OpenCode已实现，当前Windows 11合成工程核查已通过，见[独立结果](../bootstrap/desktop-d2-streaming-review.md#11-最终交付限定合成工程核查通过)；真实供应商仍未验。不设计预算，120秒／1MiB既有保护及不明请求恢复规则保持。

Q7的用户决定是兼容方向。本节选择首片工程子集，不绑定品牌或型号。2026-10-17已查阅[OpenAI官方Chat Completions参考](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)：它定义`POST /chat/completions`、模型与消息输入、流式选项和`choices`消息输出；不同模型支持的参数可能不同。该官方文档不能证明第三方服务兼容，以下限制是本项目的接入选择。

- **地址与模型：** `base_url`是供应商HTTPS API前缀，可含供应商要求的`/v1`等路径，应用只追加一次`/chat/completions`，不擅自插入或重复`/v1`。界面显示拼接后的目标供检查；若填了完整completion路径则提示改填API前缀。模型字符串按配置发送，不自动改成别的型号，也不以命名含“GPT”判定可用。
- **请求子集：** Bearer密钥、JSON POST、`model`、文本`messages`和`stream=true`；系统结构／个人指导与业务材料分开组装。不依赖`response_format`、temperature、thinking参数、tools或额外供应商私有请求字段，不发浏览器搜索／文件上传请求；不兼容此文本子集的模型明确报错，不静默再发另一种协议尝试。
- **结果：** SSE中`delta.reasoning_content`仅作有界临时纯文本展示，`delta.content`累计最终答案；要求单一正常文本choice、`finish_reason=stop`及完整HTTP framing，`[DONE]`不能代替正常结束。最终正文为单个严格JSON对象，再做任务schema和业务校验；同一请求返回合法非流式JSON时兼容校验`message.content`，不补发。拒绝截断、拒答、工具调用、缺字段／未知字段、非法UTF-8等结果；围栏／自由文字不猜测修补，不自动追加收费纠错。返回模型／request_id／usage保留真实性，缺失记不可得；思考不入正文、日志、Word、备份或下一次上下文。
- **最初工程限额：** 沿已有设计采用连接10秒、单次调用120秒、序列化请求和响应正文各最多1MiB，后续实际兼容验证可凭证据调整并记录版本；这些是限额，不是响应速度保证。超过限额明确失败且不静默截断材料；发送后的超时／中断按不明规则处理。
- **重试：** 首次加最多2次，仅限可证未发出或被明确拒绝处理的临时错误，初始等待5／30秒；单凭429或5xx不声称已证未处理。401／403／额度／协议问题暂停并说明；JSON错误终止本次。禁止HTTP库／SDK重试绕开任务记录；供应商地址或模型变化不触发补发。
- **安全与设置：** 每次连接做实际公网目标／TLS检查并拒绝重定向，沿已有地址防护要求；不继承未知环境代理。模型与地址保存不做付费连通测试；不完整回显密钥、不写前端持久存储／日志。公网HTTPS边界不因“兼容”开放内网或本地模型。

实际验收记录供应商、API前缀形态、配置模型／响应模型、所用协议版本、三类任务的成功和失败例子。模拟服务验证状态与协议，真实服务验证兼容与输出；两者不相互替代。当前没有真实凭据或调用授权，不要求现在补齐。
