# D2 实时思考过程与等待反馈设计

日期：2026-10-21。**已由OpenCode实现并通过Codex当前Windows 11合成工程核查（[最终证据](../bootstrap/desktop-d2-streaming-review.md#11-最终交付限定合成工程核查通过)）；真实供应商仍未调用。** 应用准备接入DeepSeek官方API与MiMo标准API，不使用MiMo Token Plan或OpenCode Go；不设计预算限额，不实际调用真实AI或发布。

本项落实用户的两个目标：等待期间能看到供应商正在返回的内容；避免把等待误认为失败而重复发起同一任务。用户已进一步确认：思考默认展开、可折叠，显示阶段与已等待时间；不使用Go仅指应用运行时，实现工具仍沿用OpenCode的Go套餐DeepSeek V4.1 Flash。按本方案继续实施及Codex独立核查，不把设计或实现者自测写成已验收。

## 1. 官方支持与现状

DeepSeek官方示例通过`stream:true`读取`choices[0].delta.reasoning_content`与`delta.content`，分别为思考过程和最终答案。[DeepSeek思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)

MiMo的Chat Completions参考同样定义上述两个流式增量字段；深度思考指南说明可通过流式输出实时查看思考过程。[MiMo接口参考](https://mimo.mi.com/docs/en-US/api/chat/openai-api)、[MiMo深度思考指南](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/other/deep-thinking)

这只能证明接口具备所需能力，不能保证第一段思考立刻到达、持续有文字或网络一定正常。应用不编造思考、百分比或预计完成时间，不另发一次模型请求来生成进度说明。

实施前基线（31a3c9a，作为本次设计原因保留）：

- `backend/app/local/ai_transport.py`的`build_request`发送`stream:false`，`send`完整读响应后才解析；没有实时输出通路。仅在最终响应后显示思考不能解决等待反馈问题。
- `ai_worker.py`只发ready／最终result；`ai_executor.py`当前等待一个最终result。流式实现需新增有界进度帧并连续消费，不能把进度帧误判为失败或完成。
- `frontend/src/d1/views/AiTaskPanel.vue`已有同类型活动任务阻止、提交中的方法重入保护、结果不明时保留原请求ID／请求体及回执查询；后端另有重复活跃任务及幂等保护。当前资料不能证明“重复点击导致调用失败”的根因，不重开历史R03事件。
- 当前任务列表在显示页面每2秒、隐藏页面每5秒查询；查询失败保留原任务列表，不改变任务持久状态。

本轮使用已读codebase-memory技能，项目查询及六个证据文件覆盖工具均返回`Transport closed`；已限定到以上已知源码直接读取，未重建索引或开展全仓审计。

## 2. 教师看到的反馈（已确认方案）

| 真实阶段 | 界面反馈与判断依据 |
| --- | --- |
| 点击提交／本地保存 | 立即显示“正在提交”，同类型入口保持禁用；未保存成功不创建AI任务 |
| 已登记待调度／准备连接 | 显示“等待处理”或“正在连接服务”，根据本地任务与执行状态，不冒充供应商已开始思考 |
| 已发送，尚无思考／正文 | 显示“等待服务响应，已等待…秒，请勿重复提交”；无文字本身不判失败 |
| 收到非空思考增量 | 显示“正在思考”及供应商实际返回文字；用户已确认默认展开、允许折叠，固定高度内滚动 |
| 收到最终正文增量 | 显示“正在生成结果”；思考文字仍可查看，半成品JSON不进入教案或候选编辑器 |
| 完整流结束且本地校验中 | 显示“正在校验结果”；完成严格JSON／任务schema／业务校验并原子提交后，才显示候选可查看 |
| 超时／失败／结果不明 | 显示原持久状态及具体说明；已收到的思考不代表成功，不自动重发或假装供应商已停止 |

持续显示本次尝试已等待时间，并能说明最近一次实际收到数据距今多久。收到连接心跳只能表示连接有数据，不伪装成思考文字；没有数据时不写“网络正常”。本地状态查询失败与供应商请求失败分别显示。

“AI思考过程”应标明是供应商返回的中间内容，最终结果尚待校验。用只读纯文本呈现，不执行HTML／脚本，不将其中指令作为程序动作；不据此修改教师正文。

仅作当前运行的临时显示，不写业务库、日志、Word、备份或下一次模型上下文；不新增思考历史管理功能。退出／重启后只恢复已有持久任务与最终候选，不声称能接续供应商流。后端保留当前尝试及至多一份最近完成尝试的有界快照，新尝试开始替换旧快照；页面可暂存已展示文本到组件卸载，终态刷新不突然抹掉已经看到的文字。没有快照时如实显示未保留，不因此恢复或重发任务。无需持久化迁移。

## 3. 技术实现边界

保持现有教师电脑→Python执行器→供应商、受控spawn worker／Job、JSON bytes Pipe及本地HTTP查询机制。不新增WebSocket、前端直连供应商、代理、队列服务、依赖或多供应商配置。只是扩展同一AI模块内的响应解析与进度投影；不改变系统层级、模块归属或数据权威来源，无需修改ARCHITECTURE.md。若实施发现必须改变这些机制，则按AGENTS.md先提出ADR，不直接扩大实现。

1. **外部接收：** 请求改为`stream:true`，用现有标准库网络层增量解析SSE；兼容拆开的UTF-8／CRLF／事件边界、注释心跳及正常结束事件。保留公网DNS钉住、TLS、无重定向／未知代理、HTTP framing、编码与响应大小防护；不得调用一次失败后再静默用非流式补发。
2. **内容分离：** 思考增量只进展示缓存，最终content增量只进最终答案缓冲。完整流终止后再严格验证一个正常结束的文本选项和任务JSON；流中错误、工具调用、拒答、截断、重复choice或非法JSON不自动修补。缺少usage仍如实记不可得，不为补usage另发请求。
3. **进度传递：** worker使用现有Pipe新增小型progress帧，按现有控制帧上限分段、合并高频更新；最终result保持独立。父进程循环消费，每次均复核绝对期限、当前attempt／execution／permit及退出状态，迟到或旧代次进度不得覆盖新任务。
4. **本地投影：** 新增同一HTTP API下受现有session／Host／Origin保护的只读任务进度GET（优先`/api/local/ai/tasks/{id}/progress`），前端沿用现有轮询并只取当前可见活动任务；无供应商密钥流入前端。进度附task／execution／attempt身份、单调seq、phase、elapsed_ms、last_data_age_ms和思考纯文本；缺少缓存时返回明确空快照，不启动执行器或发网络请求。检查持久任务归属／当前execution后才返回，前端同样拒收旧代次。缓存严格有界，新的尝试和退出时释放；不得让全部历史分页每2秒重复附带多份长思考正文。
5. **成功边界：** 进度不是候选，不推进业务版本，不变更allowed_actions；只在最终验证通过并持久提交后提供采用。停止等待／退出的permit撤销、Job收口与成功竞争保持原语义。
6. **工程期限：** 当前连接10秒、整个尝试120秒及响应总量1MiB保持；思考／心跳不重置总期限，不让小片段无限续命。这些是既有运行保护，不是token／费用预算。如后续真实验收证明需调整，另据证据修订。

## 4. 防重复提交必须独立成立

- 正在提交、同类型任务活动中、存在未决提交时，同类型入口禁用并明确提示；方法入口同样拦截，不能只依赖按钮外观。
- 继续复用原request ID／请求体和后端幂等、同计划同类型活动任务冲突保护；状态查询失败不能换ID重新创建。
- 页面切换回来仍先读取持久任务，同一任务的思考显示只依附该execution。刷新进度、折叠／展开、查看候选均不得新增供应商请求。
- 已发送结果不明仍不自动重试；人工重试沿原重复处理／计费提示，不因曾显示思考就判为确定未处理。
- 三类任务仍各自按需触发，不因本项禁止不同类型正常登记，或把整页编辑／保存锁到外部调用结束。
