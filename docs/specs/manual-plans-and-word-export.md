# 手工日计划到周计划确认与 Word 导出最小实施规格

状态：首个最小实施规格已形成，关键业务规则已逐项确认。Architecture v1 及本次用户明确同意的规则为已确认；本文标注“建议”或“未决”的条目不构成产品规则。当前仅编写文档，不授权代码、数据库、依赖安装、骨架或部署。

依据：[用户与班级](../modules/identity-and-class.md)、[日计划](../modules/daily-plans.md)、[周计划](../modules/weekly-plans.md)、[Word 导出](../modules/word-export.md)。验证见 [Word 模板验证计划](word-template-validation.md)。

## 目标与范围

形成“教师手工保存日计划 → 汇集全班周计划 → 负责人编辑确认 → Word 导出”的最小实施切片。手工路径不要求 AI 成功或已配置密钥；AI、个人提示词、持久任务仍属于首版，只在后续实施步骤接入。本规格不展开 DDL、API 路由、页面组件或完整代码任务清单。

MySQL 8.4 / InnoDB 是业务权威来源；导出文件是所选版本的时间点副本。沿用现有模块边界，不改变架构。

## 已确认的使用者与前置条件

- 教师账号已获管理员分配班级；学期、上课日、年级和游戏配置由管理员统一维护。
- 创建教师及管理员可修改日计划，同班其他教师只读。教师可删除自己的日计划，管理员可删除任意日计划，删除可恢复。
- 周计划创建者是初始负责人；同班其他教师只读；管理员可编辑删除，但不能代替负责人确认。
- 调班不迁移历史计划，教师可查看导出本人原班计划但不可修改，不再查看原班他人计划。
- 负责人调班或停用后暂停新发自动 AI 调用；管理员指定原班教师并由其接受接管后恢复，保留原创建者。
- 导出与下载均校验权限；同班教师可导出他人的日计划及已确认周计划，不获得编辑或确认权限；调班后的历史访问限制不变。

## 已确认的日期与对象身份

### 日期算法

一周从周一到周日。学期开始日所在周为第 1 周，不足七天仍算一周；假期不跳过周号。调休上课日按实际日期所在周归属，不挪到被补课的周。日期对应实际公历星期。

计算表达：令 M 为学期开始日所在周的周一，日期 D 的周次为 `floor((D - M) / 7) + 1`，以日历天差计算。只对已确定归属该学期的日期使用此公式，跨年不重置周号。不由样例中的日期或周号反推规则。

既有计划遇到学期或上课日修改时，管理员先查看影响并确认；不能静默重算，周计划唯一性冲突须先处理，受影响周计划待更新且保留已确认版本。

### 已确认的调休补课判断

使用 Python 库 `chinese_calendar` 判断调休补课日期，教师可在学期内的调休补课日自行创建日计划，无需管理员先逐日添加配置。这是教师主动创建，不是后台自动生成空计划；同班同日唯一性、实际日期周次归属继续适用。

技术核对：官方发行包名为 `chinesecalendar`，导入名为 `chinese_calendar`。`is_workday` 判断工作日；周末且为工作日可识别周末补班，`is_in_lieu` 表示调休休息日，不能把它当补课日。库仅覆盖有限年份，超出覆盖会报错；本轮只读核对，未安装或调用。依据：[官方说明](https://github.com/LKI/chinese-calendar)、[官方实现](https://raw.githubusercontent.com/LKI/chinese-calendar/master/chinese_calendar/utils.py)（2026-09-20 核对）。

已确认：库提供默认日历，管理员明确配置的园所停课、补课例外优先；没有例外时，库识别的学期内补课日直接允许创建。库未覆盖某年份时提示“该年份日历数据未就绪”，允许管理员配置上课日后继续使用，不猜测调休，也不阻止已有计划查看和导出。

有效日历仍归用户与班级模块管理并持久化在 MySQL，库是默认日历输入；既有计划不随库升级静默重算，继续遵守日历调整的影响预览、管理员确认和版本保护。本次细化不改变数据权威来源或 Architecture v1。普通非上课日及学期外日期不允许直接创建；确需备课时管理员先调整上课日或学期范围，继续遵守已有计划影响预览、确认及冲突处理。

### 对象及必要关联

| 对象 | 身份、归属和内容 |
| --- | --- |
| 日计划 | 独立稳定身份；创建教师、原班级、学期、实际日期、周次、星期、内容版本、删除状态。同班同日仅一份有效记录，不因创建教师不同而放宽；同一教师在该班同日也只能一份 |
| 日计划内容版本 | 最终采用字段、原始教案、原始拆分过程基准（存在时）、修改者和版本关系；基准不被最终编辑覆盖 |
| 游戏组与组内游戏 | 稳定组标识与游戏标识；活动时段、游戏类别、多个名称、共用目标和指导；重点指导、支持策略等独立保留，不从斜杠或顿号强制推断拆分 |
| 周计划 | 独立身份；班级、学期、周次；同班同学期同周一份有效记录；原创建者与当前负责人分开 |
| 周计划内容与来源 | 上一确认版本、当前人工编辑内容、最新候选分开；来源关联日计划身份、版本、日期、游戏组及所选游戏；确认记录保留缺项和未更新说明 |
| 日历关联 | 学期及上课日配置决定归属；保留足以检测归属变化的版本或等价标识，具体存储形式留待实现 |

重复创建打开已有有效日计划或周计划，保留其创建者及编辑权限。恢复已删除记录时若与有效记录冲突，先处理冲突，不覆盖或静默合并。并发创建也必须满足同一唯一性规则。

“自主游戏”与“自选游戏”已确认同义，内部统一类别，导出保留模板的“自主游戏”栏目名称。多个游戏共用目标与指导时保存游戏组，不人为分摊成每个游戏专属目标。周计划选择其中一个游戏时携带该组共用内容及来源。

| 集体活动后游戏类型、区域名称、重点指导、目标、指导、支持策略 | 室内区域游戏／户外或专用室的对应位置 | 重点区域候选；可以来自同班任意教师、任意日期的该时段游戏，不能擅自缩为本周 |

周计划日期列保留周一至周五，遇周末上课时增加对应日期列并按日期排序；假期注明，不截掉第六、第七个上课日。上课日缺日计划与假期分别表达，不能因缺计划而隐藏该日期列。

## 保存、汇集、编辑、确认与导出

1. 教师选择日期，读取班级日历与周次，检查已有记录。先按管理员明确配置优先、库默认日历其次判断日期；非上课日必须提示。没有管理员例外时，库识别的学期内调休补课日可自行创建；库年份缺失时提示并等待管理员配置。普通非上课日及学期外日期不能直接创建，需管理员先调整上课日或学期范围。
2. 教师手工填写并保存最终采用内容；不要求先运行 AI。班级、学期、日期确定后允许内容留空保存；日计划导出前提示缺项，教师确认后仍可导出，保留空栏目、不自动补写。该提示确认不授予编辑权限，也不替代周计划负责人确认。
3. 保存及登记相关周计划更新在同一事务中完成，保存不等待 AI。管理员修改、删除及日历影响按相同版本保护处理。日计划模块不执行周计划生成、不被周计划反向改写。
4. 创建周计划时填写主题；已存在则打开。晨间谈话与集体活动名称确定性汇集到待确认内容，标明缺失日期及来源。手工路径由负责人选择引用游戏、编辑其余栏目；AI 暂未接入或失败不能阻止该路径。自动候选不足时先展示已有项目及缺项，不能伪造足额引用。
5. 人工编辑内容与新候选分别保存。候选采用规则沿用 Contract：游戏重选允许替换；其他人工修改栏目由负责人选择是否替换，主题不自动覆盖。管理员编辑仍形成待负责人确认的新内容。
6. 确认时检查权限和来源版本；旧候选不能作为基于最新来源的结果确认。负责人仍可明确确认当前不完整或未更新内容，记录具体缺项和未更新之处。
7. 导出选择明确版本。上一已确认周计划可导出，提示未包含更新；未确认候选不能直接导出。日计划导出最终采用内容；周计划导出不可回写确认或内容。
8. 日计划严格按所选日期范围筛选。周计划按上课日期与范围交集选择整份，按稳定计划身份去重，不裁切周内栏目。无匹配计划时提示，不生成空文件、不扩大日期范围。
9. 日计划按日期升序、周计划按周起始日升序合并。每份计划从新页开始，份内长内容自然分页。下载后的文件不随后续修改更新。

建议的最小实现约束：同一日计划的并发编辑以内容版本检测冲突，提示重读后处理，不静默覆盖另一设备的新内容。该技术保护不新增审批流程；具体交互在实现前细化。

### 已确认的过程标红与材料边界

无原始拆分基准时，按最终内容导出，不标红，并提示无法比较。有基准时，新增和替换后的文字标红，纯删除不显示已删文字，纯段落移动和仅格式变化不标红，不增加删除线。

周计划材料由 AI 获取，再按已有 AI 候选采用与负责人确认规则处理。已确认以所选游戏名称、目标、指导、支持策略及班级年级为依据，优先提取其中明确提到的材料，不足时生成补充建议；保留生成依据，只存周计划，不回写日计划。此规则不引入外部搜索或新增服务。纯手工切片无材料候选时可保留缺项，由负责人按不完整确认规则处理；不把材料改成手工来源要求，也不强制等待 AI 成功。

### 已确认的同名游戏与来源选择

保留不同日期的各来源记录，周计划选取时同类别同名游戏只占一个名额。AI 选择一个具体来源，携带该来源的整组目标和指导；负责人可以改选其他来源，不跨来源混合冲突内容。名称相近但不完全相同的游戏先不自动合并。“自主／自选”的统一类别规则适用于这里的类别判断。

去重作用于周计划选取名额，不删除或合并日计划来源。改选来源后，目标与指导跟随所选来源，材料仍须记录其实际生成依据；旧材料不能冒充基于新来源生成，沿用来源版本检查与未更新确认规则。

## 与后续 AI、个人提示词和持久任务的衔接

依据：[提示词](../modules/prompts.md)、[AI Service](../modules/ai-service.md)。手工数据与后续 AI 采用相同的业务字段、游戏组和来源版本，不另建 AI 专属正式计划。

- 日计划保留完整教案、拆分基准、最终采用内容，为拆分、年龄适宜性调整及比较留出关系；AI 候选必须由教师采用。
- 字段结构归系统维护；个人指导不能删改字段名。未完成必需字段适配只暂停对应 AI，不阻止手工保存。
- 日计划 AI 使用当前操作者配置，周计划自动任务使用当前负责人配置和提示词。待执行使用最新有效配置，执行中保持启动版本，并记录实际使用版本。
- 日计划相关保存后 30 秒合并触发周计划 AI，立即更新仍排队；这是后续接入必须实现的已确认行为，不因手工切片取消。
- 持久任务保留来源版本、执行状态和候选关联；执行与确认均检查来源、权限、负责人、提示词适配状态。AI 返回不能覆盖已确认版本或正在编辑的内容。
- 任务进度、内容完整性、来源新旧、确认状态分别表达；AI 失败保留手工内容，结果不明的已发请求不自动重发。

以下日期及活动名为规格夹具，不是对样例内容或法定调休日的推断。

| 场景 | 预期 |
| --- | --- |
| 学期从 2026-09-01 周二开始 | 09-01 至 09-06 属第 1 周，09-07 起第 2 周；08-31 仅是计算锚点，不自动视作该学期可创建日期 |
| 同一学期跨年，开始日仍为 2026-09-01 | 2027-01-01 属第 18 周，不按公历新年重置 |
| 管理员将 2026-09-20 周日配置为补课日 | 属 09-14 至 09-20 的第 3 周，不移入第 4 周；假期周也连续计数 |
| 库识别某周日为调休工作日，且在学期内 | 教师可自行创建，不等待管理员逐日补录；归实际周日所在周；若存在管理员显式例外则优先按例外判断，不把调休休息日误认为补课日 |

| 新学期覆盖库尚未支持的年份 | 提示该年份日历数据未就绪，不自行推断工作日或调休；管理员配置上课日后可继续使用，已有计划查看和导出仍遵守原权限、不被阻断 |
| 班级有甲乙两位教师及保育员丙，日计划由甲创建 | 日计划教师表头显示甲；周计划显示班级教师名单甲乙及保育员丙，信息来自管理员配置，不因周计划由甲负责而省略乙 |
| 该周周二至周五上课，周五日计划尚未保存 | 表头日期仍显示周二至周五，不因缺日计划而止于周四；周次按实际日期所在的学期周计算 |
| 周一至周五加周六、周日均配置上课 | 周表按实际日期显示七个日期列，不截断周末，周次仍是同一实际周的学期周号 |
| 日期在学期范围外，或有效日历为普通休息日 | 不允许直接创建；提示管理员先调整学期范围或上课日，不能以内容可留空为由跳过日期校验 |
| 只确定班级、学期、日期，内容为空 | 可以保存；导出先提示缺项，教师确认后保留空栏目导出，不填入样例或 AI 内容 |
| 乙导出同班甲的日计划或已确认周计划 | 允许导出，不能编辑甲的日计划或确认周计划；导出缺项提示确认不提升权限 |
| 甲保存中四班 09-01，乙再创建同班同日 | 打开甲的记录，乙只读；甲自己重复创建同样打开已有记录；并发不能生成第二份有效记录 |
| 甲、乙分别保存 09-01、09-02，甲负责第 1 周 | 晨间谈话和集体活动各落到对应日期；甲选择游戏来源、编辑周内容并确认，再导出确认版本 |
| 跳圈圈与滚球共用目标和指导，周计划只选滚球 | 保留组目标和指导及日计划／版本／组／滚球关联，不把组目标改写为滚球专属目标 |
| 两日均有集体游戏“跳圈圈”，目标指导不同 | 保留两个来源，选取时只占一个集体游戏名额；AI 选取其中一个来源的整组目标指导，负责人可改选另一个，不混合两日内容 |
| 候选含“滚球”和“滚球接力” | 名称不完全相同，不自动合并；同名但类别不同也不按同类别同名规则合并 |
| 所选区域支持策略写明“提供纸杯”，AI 认为还需托盘 | 材料优先提取纸杯，托盘作为补充建议，保留所选游戏及班级年级等生成依据；负责人编辑确认，只存周计划 |
| 负责人将游戏来源从甲日改为乙日，已有材料基于甲日 | 目标指导改用乙日整组内容；原材料保留真实依据并识别未更新，不能静默标为依据乙日生成 |
| 日计划晨间活动完整填写 | 固定“体能大循环”后为一项集体游戏和一项自选游戏；可共用目标指导，周计划仍汇集选择两项集体游戏及一项自选游戏 |
| 本周只有一份完整日计划，候选为一项集体及一项自选 | 周计划仍缺一项集体游戏；不得重复引用同一游戏凑足两项，按候选不足规则提示、补足或明确确认不完整内容 |
| 仅有一项集体游戏、没有自选游戏 | 显示不足；负责人可手工补充内容并明确确认不完整版本，不能将人工内容标为日计划引用或 AI 补充 |
| 已确认 V1 后日计划保存 V2 | V1 仍可导出但提示未更新；新汇集内容待确认。基于日计划旧版本的候选不能声称最新 |
| 负责人打开确认页后另一位教师修改来源 | 确认检查发现变化；处理最新来源，或明确确认当前未更新内容并记录差异，不能静默确认成最新完整版本 |
| 管理员改周计划内容 | 新内容待负责人确认，管理员无代确认权；原确认版本保留 |
| 删除后重建同班同日日计划，再恢复旧记录 | 存在唯一性冲突，先处理，不静默覆盖新记录；周计划来源变化需跟踪 |
| 所选范围没有匹配计划 | 提示无匹配，不生成空文件，也不扩大范围寻找相邻日期的计划 |
| 日计划以 09-04、09-01、09-02 的乱序输入合并 | 按 09-01、09-02、09-04 输出，每份从新页开始；长过程在该份内自然分页，不能把第二份接到第一份末页空白处 |
| 跨周范围选中多份周计划 | 按周起始日升序，每份从新页开始，按身份去重并保留整份内容 |
| 范围 2026-09-30 至 10-01，与 09-28 至 10-04 周内配置的上课日相交 | 该周计划整份导出一次；范围外同周栏目保留，日计划仍只取范围内日期 |
