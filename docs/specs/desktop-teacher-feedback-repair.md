## 第一批　保存、关闭、失焦和配置版本

- **#37** 从有一份正常周计划的合成库起步，在同一实际桌面会话建第二份。按原路径点「选择周游戏」「生成所选周栏目」「生成材料」，再试保存、确认、返回和关窗。记录各请求状态、周计划 ID、版本、数据库事务和关闭握手，查清 AI 与保存是同一故障还是分别发生。成功时能保存、确认并回开正确的第二份。可恢复失败时保留输入，展示能执行的恢复动作和失败原因。验证恢复后能正常返回及关窗。若持久化持续不可用且现有恢复能力不足，先确定安全退出方式，保存失败不得悄悄丢输入、绕过保存门槛或迫使教师结束进程。
- **#28** 游戏观察正常输入「重点观察幼儿」和「观察环境」，覆盖 Windows 中文输入法、空格及等待自动保存前后。定位定时保存、异步回填、列表重绘或键盘事件是否替换输入控件。验收连续输入不会抢焦点、截断候选或丢空格，重新打开时保存内容正确。
- **#10** 复现普通配置 `v1 → v2` 后立即进班级游戏配置，校对前端显示版本和请求绑定版本。修复首次预览仍带旧版本、重按才成功的问题。正常操作第一次即可预览，确认只推进一次版本。若外部确实改过数据，则保留冲突检查及明确的重读路径。先完成这项再改确认方式。
- 本批同时建立 #17、#30 的最小复现，记录卡在连接、请求、响应还是解析，保留可对照的假供应商用例。先复现和查因，再判断是否调整超时。不能复现教师现场时，分别记录已证明的机制与尚未证实的现场原因，超时保持原值。

- **#11** 有待确认设置时，在拦截提示上提供「前往处理」，打开正确设置区域并定位对应项目。若多处待处理，逐处可到达。跳转保留编辑内容，教师仍可确认或取消。
- **#12** 工作台月历每周一行，从周一到周日七列，表头为「一、二、三、四、五、六、日」。跨月补位、选中日期及计划标记与列对齐。
- **#14** 把「当前月份」的返回操作改为「回到今天」。学期从已设置的系统学期选择，月份选择器使用中文。学期筛选和跳回今天的显示状态应一致。
- **#15** 工作台点日期直接进入当天日计划。有计划打开对应内容，无计划打开当天可编辑页。保持原有未保存保护，浏览日期本身不应创建空记录。
- **#19** 原始教案输入框移到日计划编辑顶部。教案拆分、过程适龄调整、其他活动生成分别放到对应选项卡或该区操作旁，保留各自的保存状态和 AI 任务归属。
- **#31** 周计划概览把缺项和来源变化压缩成短句，例如「多项未填写」「来源有变化」。摘要不逐项列出日期和字段。

- **#33** 新建周计划可选周次，也可选该周星期一日期。两种选择显示同一周并共用身份，按系统日历校验，重复选择时打开已有对应周计划或提示其已存在。

## 第三批　AI 结果、日计划 Word 和游戏观察

先修两条请求链，再改候选交互和输出合同。修复前后都从正常页面触发，以合成夹具覆盖正常完成、返回明确错误和收到推理后未收到完整结果。记录任务 ID、请求阶段耗时、状态码、有效请求参数、图片张数和字节数、供应商结束标记及最终结果解析状态。日志仅保留诊断元数据，排除密钥、推理正文、照片和幼儿资料。对已经发出但结果未知的任务保留原标识及查询入口，重复发送由明确状态和教师操作决定。[DeepSeek 接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)

- **#17** 分别比较普通教案和长教案在直连及受控代理中的表现，定位 DNS/TLS、连接、首包、读取中断、总时限或输入输出截断。若证据指向超时，只调整相应阶段和任务的边界。验收长教案可完整返回并解析，明确错误与结果未知有区别，原输入可继续编辑。
- **#30** 游戏观察用两张合成照片走「生成四栏」。同模型在另一套系统成功是对照线索。逐项比较有效模型参数、图片预处理、代理、输出预算及流式响应收尾。验证只有推理片段、最终正文被截断、完整正文未通过四栏校验等状态可区分，完整有效结果才显示为候选。采用前不写业务四栏。
- **#7** 班级游戏配置可粘贴整段「区域／专用室／户外场地与限制」。AI 拆成结构化候选，教师可核对、改字段，确认后一次保存，取消不改变现配置。缺少信息留空，沿用当前配置校验。
- **#16** 普通 AI 候选让教师在可编辑内容旁直接「采用并保存」或「取消本次候选编辑」，去掉另开的预览及比较步骤。提供「重新生成」及可填写定向修改要求的入口。新结果仍是候选，保留当前已保存版本。配置批量导入和适龄调整保留各自明确要求的预览。
- **#20** 适龄调整预览可重新生成，也可说明需改哪个环节及怎么改。把修订指令与原保存基准及当前候选绑定。失败或取消保留当前候选和已保存教案。
- **#21** 适龄调整显示采用前、采用后并排差异，按活动过程环节对齐。修改标出对应环节，新增标出新增环节。无需教师逐字找差异。
- **#23** 拆分阶段修正常见错字、标点和误入的英文字母，语义不确定的内容交教师核对，保留原文。适龄调整以拆分后的教案为基准，只改或新增一个「活动过程」环节，其余内容保持原样。界面和导出 Word 只把该环节标红。用含错字且只改一个环节的教案验收两段输出。
- **#24** 编号 `1. `、`2. `、`3. ` 各点分别用实际换行，每段「师：……」说话内容结束后换行。检查 JSON 解码、编辑器显示和实际 Word 段落，禁止把反斜杠转义文本直接显示出来。
- **#27** 在反思区加 AI 生成操作，使用当前日计划的已保存内容和教师提供的材料，产出可编辑候选。采用后保存，取消保留原反思。缺少活动实施材料时不编造发生过的事。
- **#36** 周计划 AI 给当前幼儿园年级、学期及周计划上下文，覆盖「本周重点」「习惯与文化」「家园合作」等栏目。用同一中班样例验收内容与年龄匹配，并检查活动、表述和材料不混入小学、中学场景。
- **#18** 日计划 Word 有缺项也可直接发起导出，按原位留空，流程不出现额外的缺项确认。
- **#22** 按「导出 Word 成功」理解此条。实际写入所选文件后自动关闭「导出 Word（数据库已保存版本）」窗口，浮窗提示「文件已保存」。取消另存为或写入失败时保留对话框及可重试状态。
- **#25** 用同时产生两块户外游戏的日计划复现截图，查明各块的模板和数据来源。导出中只显示「下午：户外游戏」。去除多余渲染时保留原数据库内容。如旧记录只有上方块有内容，在回执里说明如何让教师处理，避免静默丢掉唯一的教师输入。
- **#26** 日计划 Word 区域游戏、户外游戏去掉系统生成的「室内区域（一般建议）」「户外场地（一般建议）」等占位及回退说明。保留教师实际选填的地点和活动内容。
- **#38** 周计划 Word 从导出选择页一次发起，缺项最多一处提示，不再弹第二次确认。单周和连续周均检查，已有确认版本、文件冲突和实际写入结果各自正确。

## 第四批　一对一倾听

沿用 [现有产品规格](desktop-one-to-one-listening.md)的每名幼儿五个领域、每领域三个图文位置。先完成图片和日期，再做 AI 批处理与导出。用已有记录和新记录一起验收。

- **#39** 一次选入 1～15 张，自动分到五个领域的空图位。首轮建议按界面领域顺序和本批选择顺序分配，每领域最多三张。提交前可看到落位并调换，已有照片不会被悄悄替换。超过剩余空位时明确提示并保留原记录。
- **#40** 单张可左转、右转 90° 并保存显示方向。预览、AI 输入及 Word 使用同一方向。保留原图，检查关闭重开后的方向。
- **#41** 观察日期／时段使用可点击的月份日历，限制在该记录学期内。定义与旧日期记录的读取兼容，保留旧日期事实。
- **#42** 选好观察月份后，作品日期可选该月与学期范围交集内的某一天。修改观察月若导致已存作品日期越界，应定位提醒并交教师调整，保留原值直到确认变更。
- **#43** 「整理本组倾听记录」按当前领域图位顺序把同组照片及关联日期、文字交给同一次 AI 任务。建议允许实际只有一或两张的组按同一入口提交，空槽不发送，返回内容对应各图位。禁止把其他领域的照片混进来。照片不能作为推断幼儿原话的凭据。
- **#44** 「采用所选项」将勾选的文本、星级或图位记录一次提交并保存，保留逐项勾选与编辑，未勾选项保持原样。一次提交只推进一次相应记录版本。保存失败时仍能看到候选及勾选。
- **#45** 倾听填写流程去掉观察区域，保留旧记录已有信息。AI 能按当前领域和有效材料生成「观察目标」候选，教师可改、选用或留空。检查 Word 中该字段的表现，移除已有模板栏位前先确认样稿。
- **#46** 从已安装版本的倾听列表核对现有「按领域合册」入口。沿用已有导出服务，支持选领域、选择同班同学期幼儿并排序后生成一份 Word。若功能可用但难找到，使「按幼儿合册」和「按领域合册」都易发现。若安装版缺入口或无法生成，修该路径。

### #6 提示词功能包

#### 教师看到什么

老师照常在日计划、游戏观察、周计划或一对一倾听页面主动发起 AI。兼容的默认文字更新无需重装。AI 设置显示当前使用的包版本、最近检查时间及简短变更说明，提供「检查提示词更新」。没有新版、断网、校验失败、版本不兼容分别显示，已有可用提示词继续工作。已经填写的计划、既有候选和确认版 Word 保持各自的业务版本。

有个人指导的字段沿用老师已保存的文字。新默认指导可通过现有适配路径查看并自行采用，保存个人指导不会触发 AI。只使用默认指导的任务在下一次尚未开始的执行选择最新兼容版本。一次执行从开始到返回、校验和候选展示，均可核对实际使用的版本。已发出且结果未知的任务仍按原标识查询。

#### 包内有哪些内容

| 内容 | 首版设计 |
| --- | --- |
| 发布清单 | 包格式版本、单调递增的发布序号、发布时间、兼容客户端版本范围、简短变更说明、负载字节数与 SHA-256、签名密钥编号。签名绑定清单及其所指负载。 |
| 默认指导文字 | 每项包含应用已登记的任务标识、契约版本、默认修订号及经过审核的字段指导文字。任务与字段范围由客户端已有契约限定。启动时内置版本可单独工作。 |
| 追溯身份 | 发布序号标识整包。`task_type`、`contract_version`、`default_revision` 和内容摘要标识单项。执行沿用本地个人指导修订及实际生效版本的记录。相同单项身份必须对应相同内容。 |

首版只允许更新现有契约中明确开放的默认指导文字。应用负责组装输入、注入经允许的变量、校验候选和决定采用行为。输入字段、输出 JSON 结构、图片处理、供应商与模型设置、超时及重试、密钥、工具权限、网络目标均由程序管理。需要改变输入输出、增加任务或增加字段时，随兼容程序版本交付，仍走原有的个人指导适配规则。合成样例和检查结果留在维护侧，发布包只携带默认文字及必要元数据。

功能包设计基线覆盖日计划 3 类（教案拆分、适龄调整、其他活动），游戏观察 2 类（生成四栏、重写单栏），周计划 6 类（选游戏、四个独立栏目、生成材料），一对一倾听 2 类（右栏草案、领域评价）及班级游戏配置拆分 1 类。进入发布包的任务须逐项核对工作进程消费对应文字，并列出可更新字段。班级游戏配置拆分使用独立契约，设置页通过它发起解析，首批远端包是否开放其默认指导由维护者确定。周计划清单中的输入字段集合等结构元数据，即使当前存成字符串也留在程序契约内。「生成四栏」的新修订可以细化支持策略的写法，四栏名称、五领域结构和采用动作继续由程序约束。反思、倾听多图整理及观察目标等新增任务通过其正常执行审核后，再逐项纳入更新白名单。

首批实现按已有可变文字开放 9 类，覆盖日计划 3 类、游戏观察 2 类、周游戏与周材料 2 类、一对一倾听 2 类。完整快照登记 13 项，其中四个周栏目登记内置契约和固定默认修订，继续使用随程序发布的规则。远端发布这四类的独立指导文字前，须由兼容客户端定义文字字段和升级规则。班级游戏配置拆分及后增任务先沿用内置指导。

首版包上限为 2 MiB。发布方对规范化 UTF-8 JSON 的负载计算字节数和 SHA-256，再以 Ed25519 签署绑定负载的清单。包服务读取实际完整预览版本，兼容范围比较客户端的三段基础版本。启动时先校验缓存或恢复内置默认，再启动 AI 执行线程。后台检查每次启动至多发起一次，默认按 6 小时限频。正式来源、公钥和签发流程在发布时配置，源码默认使用内置文字。

#### 如何检查、启用与回滚

1. 客户端按固定受信任 HTTPS 来源在后台限频检查，也接受教师手动检查。网络操作在保存事务之外运行。离线冷启动直接读取已验证的本地可用版本，首次离线用内置版本。
2. 下载写入临时文件，检查体积、完整性、内置公钥签名、包版本、应用兼容范围、任务及字段白名单、重复键、修订和文本长度。整包通过后才登记并一次切换可用版本。更新中断后仍能启动。生效的任务定义、已用历史修订和活动执行所需内容继续可追溯。
3. 复用本地 `local_prompt_bundles` 的单项身份与个人指导版本。远端清单需要单独验证，校验后的默认文字才进入现有登记链。冷启动须识别已经接受的兼容包，不能把旧内置清单当作一次要求降级的更新。恢复备份后仍须复核可用版本及签名，任务历史保留原身份。
4. 维护者回退时，把上一版可用文字作为更高发布序号及新默认修订重新签发，注明回退原因和原版本。客户端据发布序号拒绝旧包重放。当前下载或校验失败时继续使用最近可用的本地版本。本地缓存也不可用时，客户端使用兼容的内置文字，并明确显示所用版本。教师仍可手工操作及使用兼容的 AI 入口。

#### 维护与验收

维护流程为「改指导文字 → 查看字段差异 → 用合成样例检查 → Codex 核对契约 → 受控签发 → 先预览验证 → 正式发布」。私钥由维护侧单独保管，应用只有信任公钥。正式来源、公钥归属和发布渠道映射在实施时确定，真实签发和上传单独授权。首版用现有维护交接管理，多人协作管理网页后置。

先用合成签名源验证兼容包生效、断网冷启动、篡改或错误签名、重复或越权字段、旧包重放、切换中断、重启、旧备份恢复及带新序号的回退。再用假供应商对照更新前后两次任务，核对在途执行钉住旧版、新执行采用有效新版、个人文字保留、旧候选仍可按原契约查看或采用。程序更新、业务数据库联调和提示词包发布分别记验收。现有基础见 [提示词 Contract](../modules/prompts.md) 与 [D2 提示词工程规格](desktop-ai-engineering.md)。

## 第六批　搭班协作与在线数据库

- **#5** 依 [在线协作 ADR](../adr/0005-optional-online-class-collaboration.md)先做班级选择与配置带入。2026-11-08 教师确认自行选择班级，同班自动配对。在线模式由教师认证后走 HTTPS 业务 API，服务端经私网访问数据库，EXE 不持有数据库账号。首段模型按 PostgreSQL 编写，后续按已购 RDS MySQL 8.4 联调。幼儿档案、照片、个人记录和 AI 密钥继续留本地。在线周计划的共享字段、来源、确认权、冲突和主动导入另定。保留版本和确认快照。在线断网时明确提示，不自动切换到 SQLite 接着写同一份周计划。模式切换及数据迁移分别操作。
- **#8** 在线班级关系可用后，在班级游戏配置加入「从搭班老师带入」。经服务端检查两人同班后，展示对方已保存的来源版本和差异。可一次带入到预览，教师确认后才保存，取消保留本人设置。来源变更时按版本重读或提示，禁止通过同名班级跨班取配置。
- 本轮先落实经 ADR 确认的协作功能与标准 PostgreSQL 服务端边界，数据库厂商由教师比选。云库开通、供应商适配实测、线上联调、真实数据迁移及两账号走查暂缓。保留后续走查口径，覆盖同一合成班带入配置、共同完成周计划、冲突处理和切回本地。班级身份沿用第二批确定的稳定标识。正式上云数据范围另行确认。

### 管理端登录、教师发码和桌面升班

2026-11-08 教师确认以下流程，作为首段在线协作接入之后的产品规格。[在线协作 ADR](../adr/0005-optional-online-class-collaboration.md#管理端和教师桌面流程)

- 管理网页使用管理员账号。部署方初始化首个管理账号，管理员登录后管理园所和教师并签发一次性码，服务端校验权限。若日后委托园所管理，园所管理员只管理本园，提示词预览、正式发布与回滚单独授权。桌面本地模式免登录。
- 首次加入时，管理员为指定教师和园所发一次性加入码。兑换只确认教师身份和园所。老师在桌面端从本园班级列表自主选择，同一班级 ID 的老师自动配对。园所与班级关系均由服务端校验。
- 换机或重装恢复时，管理员向原教师身份签发一次性恢复码。兑换后沿用原教师 ID 和仍有效的原班级关系，直接进入原班，无需重选。已撤销的班级权限须由服务端拒绝恢复。两类码均限一次使用，校验通过与兑换须在同一事务完成。
- 升班由有当前班级权限的老师在桌面端发起，选择目标年级和生效学期并确认。沿用原班级 ID，例如「小四班」升为「中四班」，搭班老师刷新后看到同一结果。原学期记录和已确认周计划按当时的班名、学期和版本显示及导出，生效学期的新记录使用新班名。新一届班级另建稳定 ID。[班级和日历规格](class-assignment-and-calendar.md)
- 用合成园所验收管理员发两类码、首次兑换后选班、同班自动配对、换机直达原班、拒绝重复兑换、教师桌面自主升班和历史确认版导出。覆盖搭班双方同时发起升班，重复提交同一变更只生效一次，另一项基于旧版本的冲突变更须重新确认。

### 后续实施顺序与审核门槛

2026-11-08 教师授权在前一轮修复通过 Codex 审核、相关文件停止写入后，按以下顺序接续。只用合成园所、教师、班级、周计划和提示词做首轮联调。Codex 为 OpenCode 与 Command Go 指定互斥的文件责任及验收场景。每段先由实现者自测，Codex 独立复核正常入口和关键失败场景。审核发现问题交原实现者回修，复核通过才接续。第一段安排 Command Go 独立交付一个可走通的发码切片，按真实页面、服务端状态和回修结果判断其能力。

1. 管理员登录和发码。先在隔离的 MySQL 8.4 测试库验证协作迁移与事务，再走通登录、为合成教师签发加入码及恢复码、服务端单次兑换。检查未授权者无法发码、过期和重复兑换被拒绝，并发兑换只能成功一次。
2. 教师选班、自动配对、换机恢复和桌面升班。用两个隔离桌面档案，在同园所选同一班配对，再用新档案验证恢复直达原班。教师在桌面升班，核对两边的班级身份、显示名、历史学期和冲突回执。
3. 周计划同步。先确认共享字段和确认权限。双端验证同周读取、交叉保存、并发冲突保留输入、断线恢复及确认版本导出。
4. 提示词发布。走通管理端草稿、预览、正式发布和回滚。使用合成签名源验证客户端自动拉取、签名和版本校验，以及断网沿用上一次可用包。

线上合成联调使用教师指定的独立 API 域名和已购阿里云 RDS MySQL 8.4。新建独立测试库和专用账号，迁移权限与应用运行权限分别核对，应用仅经华东 2（上海）VPC 内网连接。验证代理到 ECS 源站的 HTTPS 回源，再开放测试 API。数据库和管理凭据走受保护配置，代码、记录和合成夹具不携带凭据。现有网站和业务库分别隔离。

## 教师复测短清单
