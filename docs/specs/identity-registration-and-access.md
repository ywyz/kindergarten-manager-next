依据：[Architecture v1](../../ARCHITECTURE.md)、[用户与班级 Contract](../modules/identity-and-class.md)、[最小计划规格](manual-plans-and-word-export.md)、[事务与版本 ADR](../adr/0002-background-tasks-and-versions.md)、[日志 Contract](../modules/audit-log.md)。

## 决定分类

### 本次用户确认

- 注册、登录均使用用户名和密码；教师姓名在系统设置中填写，不是注册必填字段，也不是登录标识。不收集手机号、邮箱或接入验证码服务。
- 第一个成功注册的账号成为管理员。后续注册账号为教师，仍遵守待分配规则；注册请求不能自行指定角色或班级。
- 教师忘记密码由管理员重置；管理员忘记密码通过服务器上的系统恢复操作重置。不提供邮件、短信自助找回。

### 文档已有答案

- 单园所；一位教师当前只归属一个班级；管理员分配后才能备课。同班共享配置。
- 日计划本人及管理员可编辑，同班其他教师只读并可导出；调班后只保留本人原班计划查看、导出权，不迁移历史计划，也不继续查看原班他人计划。
- 学期与有效日历归用户与班级模块，持久化于 MySQL。管理员明确例外优先于默认日历；普通非上课日、学期外日期不能直接创建计划。
- 同班同日仅一份有效日计划；允许内容留空；保存和受影响周计划更新登记同事务，继续保留来源及版本保护。
- 班级教师名单和保育员姓名由管理员维护。本人的设置姓名不自动覆盖管理员维护的班级名单；姓名与账号稳定 ID 分开。

### 本次可自行确定的工程方案

采用稳定账号 ID、数据库唯一用户名、MySQL 持久会话、Cookie 认证、短事务、版本条件更新和统一错误码。注册不自动登录，成功后转登录页；密码重置由操作者输入新密码，旧会话全部失效，目标用户用新密码重新登录，可在系统设置自行改密。不增加临时密码强制改密、账号审批、邀请注册或新增角色流程。

这些是本任务的实施约定；可在不改变上述产品行为及安全边界的前提下调整实现细节，并同步本文。密码哈希实现选成熟的带盐慢哈希；具体库及参数在实现时结合现有依赖确定，不新增外部服务。

## 最小实施顺序与阻塞范围

| 步骤 | 交付边界 | 前置与独立检查 |
| --- | --- | --- |
| I1：本规格选出的下一项任务 | 注册、登录退出、姓名和本人密码设置、待分配页面、管理员教师账号列表与密码重置、服务器管理员恢复命令 | 不依赖班级或学期即可检查账号角色、会话及越权；三个账号产品决定已收口 |
| I2：班级与有效日历 | 管理员维护班级、教师分配、学期及持久有效日历，教师只读获取所需配置 | 依赖 I1；启动前细化班级／学期字段、学期重叠处理、日历版本和影响预览；不在本文批量设计接口或表 |
| I3：手工日计划保存 | 按有效日历创建、读取、编辑，内容可空、同班同日唯一、版本冲突、权限与更新登记 | 依赖 I2；实现前细化内容 schema、并发编辑及保存与更新登记的同事务契约，不能把登记降级为内存通知或留 TODO |

I1 完成不表示教师已经可以备课，也不代表完整用户与班级模块完成。班级分配、停用／重新启用、调班、历史计划访问、交接及其他账号管理操作在后续相关切片交付，不能提前暴露只有部分效果的操作。后续周计划、Word 导出、个人 AI、个人提示词与持久任务均仍属于首版；持久更新登记须在需要它的保存切片同步落实，不能因 AI 工作进程后接入而取消事务要求。

## I1 目标与不包含内容

交付可在独立开发 MySQL 8.4 / InnoDB 上检查的账号闭环和前端最小页面。没有班级时，教师能登录、填写姓名、改密、退出，并明确看到“待管理员分配班级，暂不能备课”。管理员能查看教师账号并重置密码。

不包含班级／学期／日历 CRUD、班级分配页面、任何计划或导出接口、AI 配置与调用、提示词编辑、工作进程、账号删除、角色转授、管理员备课入口或全套日志查询界面。不新增审批、不把姓名完整性变成账号登录或分配前置条件。日计划创建教师姓名和未来姓名变更对历史表头的影响，留到计划及导出规格细化，不在此默认静默追改历史。

I1 可以新增必要模型、迁移文件、后端与前端代码及直接相关测试，但仅在后续获得实现授权后。数据库创建、迁移实际执行及依赖安装范围须由该次实施任务明确授权；本文不授予执行权。

## 用户操作、状态和权限

1. 访客提交用户名、密码及页面上的密码确认。后台只接收用户名与密码，不接收姓名、角色、班级或账号状态。成功返回实际角色并提示登录；注册失败不留下部分账号。
2. 第一个成功提交注册事务的账号为管理员；不按页面打开、请求到达或客户端时间判定。后续账号为启用的教师。教师“待分配”是启用但没有班级归属的业务状态，不是停用或等待审批。
3. 启用账号登录取得会话；教师进入待分配页面，管理员进入教师账号列表。待分配教师只可访问本人设置、本人密码和退出功能，不能读取其他账号或任何班级计划。管理员无需班级即可使用本次管理入口。
4. 本人可在系统设置填写或修改姓名，也可在验证当前密码后修改本人密码。姓名可未填写；不得用用户名自动冒充教师姓名。前端显示未填写状态。
5. 管理员按用户名／姓名在教师列表中定位账号，选择重置密码、输入并确认新密码，再提交。界面明确目标账号和“该账号现有登录将失效”；管理员自行向教师告知新密码，系统不发送消息。不读取或回显原密码。
6. 管理员密码恢复仅通过服务器本地命令；网页教师重置入口不接受管理员目标。恢复不新增账号、不改角色、不改变班级归属、不解除停用。
7. 退出撤销当前会话；改密和重置撤销该账号全部旧会话，操作者重置别人密码不影响操作者登录。本人改密后回登录页。不永久锁定账号以代替失败限流。

所有权限在后端重新判断；浏览器隐藏按钮不能替代授权。I1 的教师班级恒为空，`can_prepare=false`。未来接入真实班级关系后再计算该值；I1 不创建假班级、占位班级 ID 或可被客户端改写的 `can_prepare` 字段。

## 必要数据与约束

以下为本切片的逻辑字段与约束；物理表名可按项目命名确定。ID 用后端生成的不透明稳定字符串，API 时间用 UTC ISO 8601；数据库时间统一 UTC。

| 对象 | 必要字段与约束 |
| --- | --- |
| 账号 | `id` 主键；`username` 唯一非空；`password_hash` 非空；`display_name` 可空；`role` 仅 `admin/teacher`；`is_active` 默认 true；`version` 从 1 单调递增；`auth_version` 从 1 单调递增；`created_at/updated_at` |
| 首次注册控制行 | 固定主键、`claimed` 布尔、`first_admin_id` 可空。迁移建立唯一控制行，初始未领取；成功初始化后永不自动重置，不随账号数量变化重新开放 |
| 登录会话 | 独立 ID、`token_hash` 唯一、账号外键、创建时 `auth_version`、`created_at/expires_at/revoked_at`。数据库不存原始 Cookie 凭据 |
| 本切片操作记录 | ID、时间、操作者账号 ID（注册为创建者；服务器恢复可空）、操作者类型 `account/server_operator`、动作、目标账号 ID、提交后的账号版本。仅存操作元信息，不存密码、哈希、Cookie、请求体或完整命令行 |

工程输入约定：用户名去首尾空格后转小写，3–32 位 ASCII 字母、数字、`_`、`-`、`.`，至少一位字母或数字；注册与登录使用完全相同规则，界面提前展示，数据库用规范化值唯一约束，避免依赖默认排序规则。暂不提供用户名改名入口。姓名去首尾空白，1–80 个字符，允许中文；空串归为 null。姓名不唯一。密码 12–128 个字符，不裁剪、不转大小写，不强制字符种类；页面允许粘贴，重复输入仅作本地一致性检查。

账号 `version` 用于设置和管理员密码重置的并发检查；`auth_version` 仅在密码／认证资格变化时递增。姓名修改不撤销会话。I1 不建班级关联字段或后续计划表；后续以账号 ID 建真实关联，不能用姓名或用户名关联历史计划。

### 首个管理员的事务

注册输入检查和密码哈希计算在短事务外完成。事务内锁定固定首次注册控制行：未领取则插入管理员并记录领取；已领取则插入教师；账号、控制行及成功操作记录一起提交。唯一用户名冲突或其他错误全部回滚。两个并发注册只能有一个管理员；先取得锁的请求失败回滚后，另一个成功请求仍可成为管理员。不能使用“先 count 用户，再无锁 insert”或进程内锁。

控制行缺失视作迁移未就绪并拒绝注册，不能在请求中自动建表或重建未领取标志。无已存在控制行的非空业务库不能据账号数重新推断初始化。首次管理员规则只用于新系统首次注册；账号停用、密码遗失或恢复备份后不重新触发。

部署交接时，在站点对教师开放注册前，由指定管理员完成首次注册并核对角色；这只是执行既定首个注册规则的运维顺序，不另加邀请码规则。本次不执行部署。

### 会话及更新一致性

会话凭据使用安全随机值；Cookie 为 HttpOnly、SameSite=Lax，HTTPS 环境设 Secure，本地回环 HTTP 开发可单独关闭 Secure。默认固定有效期 12 小时，无“记住我”或自动续期，过期重新登录。凭据不放 localStorage，API 不在 JSON 返回会话 token；认证响应禁止缓存。

前后端按同源 `/api` 访问，开发由 Vite 代理本地 API，不增加跨域认证架构。所有修改请求校验允许的精确 Origin 并仅接受 JSON（退出也校验 Origin）；不能仅靠 SameSite 防跨站请求。服务器本地恢复不走公开 HTTP 接口。登录、注册及恢复入口提供有界失败限流：I1 单进程下采用有容量上限的短期计数，返回 429 和 `Retry-After`，不按失败次数永久停用账号；具体阈值作为可配置工程参数，在实现说明中记录。服务器恢复只受本机操作权限控制。

每个认证请求检查会话到期／撤销、账号启用和 `auth_version`。密码更新、认证版本递增、撤销旧会话、账号版本递增与操作记录同事务提交。登录在写入会话前重查其验证过的密码版本，避免与重置竞争产生基于旧密码的新有效会话。认证写操作提交前重查操作者权限与认证版本；需要锁多个账号时按稳定 ID 顺序锁定，避免重置与本人操作互相死锁。数据库错误全部回滚，不能报告虚假的成功。

## API 输入输出

统一前缀 `/api`。成功响应只含显式公开字段，禁止直接序列化 ORM 账号。`Account` 为 `{id,username,display_name,role,is_active,version}`；`Me` 为 `{account:Account,class_id:null,assignment_status,can_prepare:false}`，本切片教师 `assignment_status=pending_assignment`、管理员 `not_applicable`。班级真实关系在 I2 接入。

| 方法与路由 | 权限及输入 | 成功输出 |
| --- | --- | --- |
| `POST /auth/register` | 访客；`{username,password}`；未知字段（特别是 role/class_id）拒绝 | 201 `{account:Account,next_action:"login"}`；不自动登录 |
| `POST /auth/login` | 访客；`{username,password}` | 200 `Me`，设置新会话 Cookie；不能沿用客户端提供的旧会话标识 |
| `GET /auth/me` | 已登录启用账号，无请求体 | 200 `Me`，供刷新页面恢复真实身份及状态 |
| `POST /auth/logout` | 当前 Cookie；无业务输入 | 204，撤销当前会话并清 Cookie；已失效 Cookie 也可幂等退出 |
| `PATCH /settings/profile` | 本人；`{display_name,expected_version}` | 200 更新后的 `Account` |
| `POST /settings/password` | 本人；`{current_password,new_password,expected_version}` | 204，全部旧会话失效，清当前 Cookie，返回登录页 |
| `GET /admin/teachers` | 管理员；`offset=0,limit=20`，limit 1–100；可选 `q` 为规范化用户名或姓名的文字检索，按字面匹配 | 200 `{items:[Account],total,offset,limit}`；只列教师，按创建时间与 ID 稳定排序，无密码字段 |
| `POST /admin/teachers/{id}/password-reset` | 管理员；`{new_password,expected_version}`；目标必须是教师 | 200 `{account:Account,sessions_revoked:true}`；无密码回显 |

错误响应统一为 `{error:{code,message,fields?}}`。字段错误只给字段名及原因，不包含输入密码。401 `AUTH_REQUIRED`（含过期会话）；登录账号不存在、停用或密码不正确统一 401 `INVALID_CREDENTIALS`。403 `FORBIDDEN` 用于教师访问管理接口、跨站修改或管理员网页重置管理员。404 `ACCOUNT_NOT_FOUND` 只对已通过管理员授权的不存在目标返回。409 `USERNAME_TAKEN` 或 `VERSION_CONFLICT`；422 `VALIDATION_ERROR`；429 `RATE_LIMITED`；数据库不可用／迁移未就绪返回脱敏 503 `SERVICE_UNAVAILABLE`，不得泄露 SQL 或连接地址。

首版不创建备课占位 API 以证明权限；以实际管理员接口的拒绝案例和直接调用权限判定的测试覆盖待分配边界。未来备课服务还须校验当前班级、对象创建者、对象原班级及请求动作，不能仅凭 `can_prepare` 放行。

## 服务器管理员密码恢复

约定本地入口 `python -m app.cli reset-admin-password --username <用户名>`，实现时提供从 `backend/` 运行的说明。仅定位已存在的管理员；用户名不存在或角色为教师立即失败，不创建新管理员、不修改首次注册标记。数据库配置沿用已有运行配置，不新增远程公开恢复路由。

以不回显的交互输入读取并确认新密码，不把密码作为命令行参数、环境示例或日志输出。操作者明确确认目标账号后执行，成功只输出用户名、成功状态及会话已失效；取消或输入不一致无写入。它与网页改密使用相同原子更新规则，并记录 `server_operator` 来源，不能伪造为管理员本人发起。目标被停用时仍保持停用，不借密码恢复完成启用。服务器或数据库不可用时明确失败，修复后重新执行。

该命令属于未来可授权实现的产物；本次不连接服务器、读取运行凭证或执行命令。

## 失败、冲突与恢复

- 重名：数据库唯一约束兜底，前端保留用户名供修改；不能吞掉冲突或变成登录既有账号。并发重复注册只创建一条。
- 注册响应丢失：提示可能已完成，可尝试用原用户名登录；重试遇重名不再创建账号，不再次授予管理员。不能回传既有密码。
- 登录失败／过期：清理失效的本地身份展示并回登录页；不把浏览器缓存身份当授权。
- 姓名修改或密码重置版本冲突：409，无部分写入，保留非敏感编辑，重新加载目标后由操作者再次提交，不盲目自动覆盖。
- 密码变更响应丢失：允许先尝试新密码；教师无法确定时联系管理员再次重置，管理员通过本地恢复处理。不自动重放密码写入。页面完成或离开后清理密码输入。
- 数据库故障：返回失败；账号、首次注册标志、凭据版本、会话撤销及成功日志不能各自部分落库。已有 `/health` 继续仅表示 API 进程存活，不能用它证明账号数据库可用。

## 与后续模块的衔接及未决项

账号稳定 ID 是日计划创建者、周计划负责人、个人 AI 配置与提示词归属的关联基础。浏览器会话失效不会取消离线任务授权；密码重置本身不等同于账号停用、调班或接管，也不自动触发 AI 或变更计划版本。工作进程仍须按 Contract 检查启用状态、班级关系、维护责任及实际来源／配置版本。

I2 接入班级时，待分配变为已分配必须由管理员操作和数据库真实关系决定；不得前端自行选择班级。调班／停用涉及周计划暂停与接管后，必须把这些关联状态作为同一业务变更正确处理，不只修改账号字段。I1 不提前实现这些入口来绕开任务依赖。

| 尚待细化 | 阻塞范围 |
| --- | --- |
| 班级字段、成员分配及变更 API、学期是否允许重叠与归属选择、日历版本及调整预览 | 阻塞 I2 相关实现；不阻塞 I1 |
