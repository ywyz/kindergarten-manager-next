## 1. 决定分类

### 已确认，实施时不重新选择

- 单园所；管理员统一维护班级、学期、上课日与共享配置；每位教师当前只归属一个班级，待分配不能备课。姓名未填不阻止分配。
- 园所名称、班级教师表头名单、保育员姓名由管理员维护。账号姓名与表头名单分开，修改姓名或分配教师不自动改写名单；保育员不是新角色。
- 历史计划保留原班级和创建者。调班后教师只保留本人原班计划查看／导出权，不可修改、不再看原班他人计划；新班权限按真实归属判断。
- 负责人调班／停用须暂停自动 AI，管理员指定原班教师且对方接受后才能恢复；旧请求结果仍受权限及版本保护。
- 周一至周日为一周；开始日所在周算第 1 周，假期不断号、跨年不重置，补课按实际日期归周。普通非上课日及学期外不能直接创建日计划。
- `chinese_calendar` 是默认输入，管理员明确例外优先；库缺年份不猜测，管理员配置后可用。有效日历持久化于 MySQL，查看既有计划不依赖库当前覆盖。
- 有计划后的日历调整须先预览、确认、处理有效周计划冲突，受影响周计划待更新且保留确认版本；不能静默追溯重算。

| 教师只读配置与日期解释 | 分配后读本班配置、全园学期和日期状态；清楚显示计划编辑尚未交付 | I3 才提供计划创建／保存接口及按钮 |

首次分配不会迁移计划、创建计划或更改表头名单。I2 只是完整首版中的基础切片，不代表所有班级管理能力完成。

**跨切片保护：** 园所配置中持久保存 `plans_started_at`，初始 null，作为“已进入有计划阶段”的不可逆标记，不是计划数量缓存。I3 第一次成功创建任何计划时必须在同一事务内锁定该配置并设置时间；删除全部计划也不能清空。I2 的既有配置变更在相同锁下检查此标记；非空则拒绝，直到真实影响处理能力交付。计划上线前此联动是 I3 的必做条件。不能在缺表时捕获异常并声称零影响，也不能写空计划表／任务表。此门槛是阶段性工程限制，后续有真实影响处理后允许按 Contract 调整，并非永久冻结产品。

## 3. 数据字段与数据库约束

沿用 I1 的 32 位不透明 ID、UTF-8、UTC 时间、递增 `version >= 1`、InnoDB 和外键限制删除。业务日期用 MySQL `DATE` 与 API `YYYY-MM-DD`，按园所中国本地公历解释，不用 UTC 时间戳转换日期。创建／更新时间用 UTC。写 API 拒绝未知字段。候选规范化后与当前完全相同时返回 422 `NO_CHANGES` 并提示无变更，不创建可应用的空预览或成功操作记录。

| 数据对象 | 最小字段与约束 |
| --- | --- |
| 园所配置 `school_settings` | 固定单行 ID、`school_name` 可空（填写时 1–120 字）、`version`、`schedule_version`、`plans_started_at` 可空、时间。迁移创建该控制行；不预填样例园名。`schedule_version` 是全园学期／日历写入序列，保障范围冲突和预览失效 |
| 班级 `classes` | `id,name,grade,header_teacher_names,caregiver_name,version,created_at,updated_at`。name 去首尾空白 1–80 字；grade 必填，值域固定为 small/middle/large（小班／中班／大班）。表头教师名单为有序姓名数组（最多 20 项，每项 1–80 字，可空数组），不存账号 ID、不自动同步；同名真实人员不按姓名去重。保育员姓名可空、填写 1–80 字。按已确认 P3：规范化名称以明确二进制排序规则建唯一键，大小写按字面区分，不依赖数据库默认模糊比较 |
| 当前教师归属 `teacher_assignments` | `teacher_id` 主键并外键 accounts；`class_id` 非空外键 classes、索引；`assigned_by` 外键 accounts、`assigned_at`。一教师最多一行，无行才是待分配；不存冗余姓名、不按姓名关联。目标必须启用且 role=teacher，由锁内业务校验保证跨表角色约束 |
| 学期 `terms` | `id,name,start_date,end_date,version,current_calendar_revision_id,created_at,updated_at`。名称 1–80 字，非身份、无需唯一；`start_date <= end_date` CHECK。按已确认 P1：全园任意两学期闭区间不可相交；范围查询索引 start_date/end_date；不用单列 UNIQUE 冒充范围排斥约束 |
| 日历修订 `calendar_revisions` | `id,term_id,revision_no,term_version,start_date,end_date,library_version,created_by,created_at`；`(term_id,revision_no)` 唯一。含本次日期范围及库版本来源，库版本字符串只是来源元数据，不是动态依赖 |
| 日历快照日 `calendar_days` | `(revision_id,date)` 主键；每天一行（含休息和未知日），`base_state=teaching/non_teaching/unknown`、`base_library_version`、`override_state` 可空（teaching/non_teaching）、`override_reason` 可空（配置时必填 1–200 字）、`effective_state`。外键修订；状态 CHECK，并校验 effective 为例外优先的结果；日期必须在修订范围且连续完整，由构建器和提交检查保证 |
| 变更预览 `configuration_changes` | `id,operator_id,kind,target_id,normalized_proposal,base_versions,impact_summary,status,expires_at,created_at,applied_at,result_reference`。保存实际候选、依赖版本和摘要，status 仅 pending/applied；不是生效配置。30 分钟有效，应用必须同一管理员；applied 保留结果用于超时重试识别。候选仅含本规格公开配置字段，不存凭据 |
| 操作记录扩展 | 保留 I1 账号记录语义和旧行。为班级／学期／日历／园所操作增加 `target_type,target_id,target_version_after`；I1 的 target_account_id/account_version_after 对非账号操作允许 null，对账号记录仍必填。迁移将旧行映射为 account 目标；不把班级 ID 填进账号外键，不重写历史时间、动作或版本 |

日志扩展迁移必须同步适配 I1 的实际记录写入函数，使新增账号操作同时填写通用目标字段；读取与旧字段保持兼容。首次分配以教师账号为目标记录提交后的账号版本，归属的班级 ID 由真实关系保存；不记录完整姓名列表或候选请求体。

归属创建与目标账号 `version + 1` 同事务；账号是归属并发版本的拥有者，不另建无实际用途的 assignment version。首次分配不改 `auth_version`、不撤销会话，下一次请求立即读到归属。`Account` 公开字段保持兼容。

修订及日期行提交后不可原地编辑，旧修订不自动删除。当前指针必须指向本学期修订（复合外键或等效数据库约束）；修订候选完成后再设置指针。初建学期允许事务内部指针暂空，但提交前必须完整，公开读取空指针视为未就绪错误。未来计划保存可引用稳定修订 ID；不在 I2 添加计划外键或计划 schema。

工程边界：一次候选最多覆盖 2,000 天，例外批量最多 366 个日期；超限返回 422，范围拆批只适用于例外操作，学期本身不得截断保存。列表 offset/limit 沿用 I1（默认 20，最大 100），日期查询最多 366 天，前端按月读取。任何缺失日期行均属数据不完整，不能默认为休息日或即时调用库补齐。

## 4. 日期归属与持久日历

日期解释先判断学期范围，再读取当前修订。按已确认 P1，一个日期只能属于一个学期；无归属返回 `outside_term`，不计算有效周次。不能由教师任选学期绕过归属。

令 M 为学期开始日所在周周一：`week_number = floor((D - M).days / 7) + 1`；返回实际 `weekday`（周一 1 至周日 7）、`week_start=M+7*(week_number-1)`。周锚点可在学期外，但只有闭区间内日期有该学期创建资格。

每个日期优先级：

1. 学期外：无创建资格，即使请求携带补课例外；例外写入必须处于候选学期范围内。
2. 学期内有管理员例外：按明确上课／停课生效，不受库覆盖年份限制。
3. 无例外且库有明确结果：采用持久化的默认结果；周末工作日允许备课，调休休息日不允许。
4. 无例外且库不覆盖：存 `unknown`，显示“该年份日历数据未就绪”；不能以周一至周五猜测。

管理员可在未知年份按日或所选日期批量明确“上课／停课”，配置日期立即就绪，其他日期保持未知；不要求整个年份配齐才开放已明确日期。删除例外回落到本修订保存的默认状态，可能变回 unknown，必须在预览显示。一般库运行错误（非覆盖缺失）属于导入失败，不能吞掉后伪装为未知年份。

初建学期由当前已安装锁定版本的 `chinese_calendar` 生成覆盖全范围的默认快照，并预览未知日期数量；无需把全部年份都配齐才创建学期。默认生成不逐次联网，不自动升级依赖；具体包版本在未来实现／验证报告记录，本轮不选最新版本或安装。

库升级仅改变候选输入，不改变当前指针或任何已保存快照。管理员主动“重新导入默认日历”时，读取当前安装版本，逐日展示默认及有效状态的差异、未知转就绪、例外遮盖的默认变化；保留所有范围内例外。即使新旧库版本号相同，也按实际结果与依赖摘要核对。确认后一次切换；刷新、API 重启及教师读取不能触发升级导入。有计划阶段该操作按依赖边界暂停开放。

学期缩短：预览列出被移出日期及其例外，确认后仅新修订排除这些日期；旧快照不删除。扩大时对新增日期取本次库输入，范围内既有日期保留原默认及例外，除非明确选择重新导入；修改起始日还须预览所有周号变化。修改名称同样递增 term version，但不必新建日期修订；版本检查不得将旧名称修订元信息当当前名称。

## 5. API 与权限

沿用 `/api`、I1 Cookie 会话、精确 Origin 校验、JSON、显式公开字段和 `{error:{code,message,fields?}}`。所有写入在提交前重新验证操作者会话／auth_version／启用与管理员身份。

`Me` 扩展为 `{account:Account,class_id:string|null,assignment_status,can_prepare}`；教师有真实归属为 assigned，无归属 pending_assignment；管理员仍 not_applicable、class_id=null、can_prepare=false。教师启用且有有效真实班级时 can_prepare=true，表示身份资格，不表示日期允许或计划功能已上线；日期另回 `date_eligible`。I2 页面必须显示“已分配，可查看班级和日历；计划编辑尚未开放”，不出现可点的空备课入口。

`Class` 为数据表公开字段及 version，另可返回管理员专用 `assigned_teachers:[{id,username,display_name,version}]`，与 header_teacher_names 分栏。`Term` 为 id/name/start_date/end_date/version/calendar_revision_id。教师读本班表头配置，不返回管理员教师账号列表。

| 方法、路由 | 输入 | 成功输出／用途 |
| --- | --- | --- |
| `GET /admin/classes`、`GET /admin/classes/{id}` | 分页或 ID | `{items,total,offset,limit}` 或 Class；管理员 |
| `GET /admin/school-settings` | 无 | 园所公开配置、version、schedule_version；管理员 |
| `GET /admin/teachers`（扩展） | 原分页检索，加可选 assignment_status | 原 Account 每项增加 class_id、assignment_status；管理员待分配列表不另造账号来源 |
| `POST /admin/teachers/{id}/assignment` | `{class_id,expected_version,expected_class_version}` | 200 `{account:Account,class_id,assignment_status:"assigned"}`；只允许首次分配 |
| `GET /admin/terms`、`GET /admin/terms/{id}` | 分页或 ID | Term 列表／详情；管理员 |
| `POST /admin/configuration-changes/preview` | 下表带判别字段的候选 | 201 Preview，**只保存预览候选，不生效** |
| `GET /admin/configuration-changes/{id}` | 同一操作者 | Preview 及应用结果，供刷新／超时恢复 |
| `POST /admin/configuration-changes/{id}/apply` | `{confirm:true}` | 200 `{status:"applied",result_reference,versions}`；仅应用已看过且仍有效的原候选 |
| `GET /admin/calendar?from=&to=` | 日期范围 | 按日期的解释及当前版本，管理员 |
| `GET /class-context` | 无 class_id 输入 | 已分配教师的 `{class:Class,school_name,school_version}`；不返回其他班账号资料 |
| `GET /terms`、`GET /calendar?from=&to=` | 分页或日期范围 | 已分配教师只读 Term 列表／日期解释；管理员使用上列管理路径 |

Preview 输入以 `kind` 严格分支，禁止任意通用对象写入：

| kind | proposal 与前置版本 |
| --- | --- |
| school_update | `{school_name}`、expected_version |
| class_create / class_update | 创建传完整班级字段；更新传 target_id、仅变更字段、expected_version；年级及名称按已确认 P2/P3 校验 |
| term_create / term_update | 创建传 name/start_date/end_date；更新传 target_id、仅变更字段、expected_version；均携带 expected_schedule_version |
| calendar_override | target_id 为学期、`dates:[{date,state:"teaching"|"non_teaching"|null,reason?}]`；null 撤销例外；expected_term_version、expected_calendar_revision_id、expected_schedule_version；同日重复拒绝 |
| calendar_reimport | target_id 为学期；三个版本同上；无需客户端提供库结果或版本，服务端记录真实输入 |

Preview 回 `{id,kind,target_id,base_versions,changes,impact,blockers,expires_at,status}`。changes 包含旧值／新值、日期逐日差异和周号差异；大结果可在详情按日期分页，但摘要必须含总数。impact 包含真实分配教师数量、日期增减／上课／休息／未知变化数量、例外移出清单及计划依赖状态。

无计划阶段，计划影响显示 `plan_impact_status="not_applicable_before_first_plan"`，说明来自持久阶段标记；不伪造调用计划模块并返回 0 个计划。标记非空的受限操作返回 blocker `DEPENDENCY_NOT_READY`，不得应用；I2 不产生计划／任务明细。未来开放后才可展示实际受影响日／周计划 ID、班级、归属前后、任务状态和有效周计划唯一性冲突，并在冲突解决前拒绝应用。

日期响应每项 `{date,term_id,term_version,calendar_revision_id,week_number,week_start,weekday,base_state,override_state,effective_state,source,date_eligible,reason_code}`；学期外相关字段 null、effective_state=outside_term。日历未知是可读取业务状态（200），不是整次读取 503；损坏／缺失快照返回脱敏 503。教师不能凭 date_eligible 直接获得尚不存在的计划 API。

错误：保留 I1 错误结构；404 对授权后不存在对象返回 `CLASS_NOT_FOUND/TERM_NOT_FOUND/CHANGE_NOT_FOUND`；409 `VERSION_CONFLICT`、`ALREADY_ASSIGNED`、`CLASS_NAME_TAKEN`（P3）、`TERM_OVERLAP`（P1）、`PREVIEW_STALE`、`PREVIEW_EXPIRED`、`DEPENDENCY_NOT_READY`；422 非法字段／日期／年级／重复日期；503 数据库／配置未就绪或默认日历构建失败，消息脱敏。先鉴权再查目标，避免向教师泄漏其他对象。冲突后通过已有读取接口加载最新值，不向错误 envelope 塞入不兼容任意对象。

## 6. 事务、预览与并发

锁顺序统一：涉及的 accounts 按稳定 ID 升序 → 操作者 session（沿用 I1 提交前校验）→ school_settings → classes 按 ID → terms 按 ID → configuration_changes。只获取需要的锁；I2 不更改 I1 账号操作语义。禁止进程内互斥替代 MySQL 约束。

- 首次分配：锁管理员与教师账号，重验操作者会话、目标 role/is_active/version；锁目标班级并比较 class version；再读真实归属。插入归属、目标账号 version + 1、成功操作记录一起提交。归属主键兜底并发。同一管理员两个会话同时分配到不同班最多一个成功；第二请求版本冲突，不覆盖。已存在归属即便同班也明确 ALREADY_ASSIGNED，不记录第二次成功；客户端可重读核实响应丢失。
- 预览生成：先读版本和阶段标记，在事务外构建日历候选，再用短事务锁定必要对象、重验版本、保存完整候选与影响摘要。不锁数据库等待管理员点击，不发 AI，不写当前配置。保存候选前若版本改变返回冲突，不把混合时点数据制成预览。
- 预览基线：对象版本、schedule_version、阶段标记，以及班级维护涉及的真实成员摘要。确认时重算成员摘要，首次分配改变实际影响范围也会使预览失效。学期写及日历写都递增 schedule_version；园所资料／班级更新递增各自 version。
- 应用：在锁内重验当前认证、预览操作者／期限／状态、所有基线、依赖门槛与产品约束；候选内容不能由 apply 请求替换。term_create/update 的重叠检查必须在单行 school_settings 锁下使用当前锁定读，不能用 REPEATABLE-READ 的旧快照判断；同样锁覆盖其他学期创建，避免两个“不重叠”检查同时通过。任一冲突均回滚并要求重新预览，不能自动采用新差异。
- 日期应用：插入完整新修订与日期行、切换学期指针、递增 term version 与 schedule_version、操作记录、预览 applied 状态一次提交。同一读取请求以单个数据库一致性快照取得指针和全部日期，禁止半批新半批旧。前端跨页读取若发现版本不同，重新加载范围。
- 应用重复提交：同一管理员提交同一 applied 预览返回首次结果（标明其提交版本，当前最新另读），不再次递增版本或写日志；未 applied 且过期才返回 PREVIEW_EXPIRED。网络不明时先 GET 该预览；不要自动重放新的候选。取消只离开页面，候选过期也不会生效。
- 数据库异常：配置、指针、日期、版本、归属、操作记录、applied 状态全回滚。死锁／锁等待超时返回可重试的脱敏冲突（VERSION_CONFLICT，说明重新读取），客户端不盲目重放；失败不能显示“已保存”。

有计划阶段后续开放时：预览和应用须比较真实计划／来源／任务版本，若预览后新增、恢复或修改了相关计划则失效；同事务完成日历归属影响、周计划待更新及持久更新登记，冲突不自动合并、删除或覆盖。已确认版本保持不可变。调班／停用事务须同时处理维护责任和暂停状态；外部请求不可保证撤回，旧结果不能直接生效。I2 不以空回调实现这些契约。

## 7. 前端操作路径

1. 管理员登录 → 管理区：教师账号、班级、学期与日历、园所资料；保留 I1 姓名和密码入口。无班级时待分配列表提示先创建班级。
2. 班级列表 → 新建／详情编辑：班级名称、年级、表头教师名单、保育员姓名；详情另列实际账号归属。填写姓名不是选择成员；保存先展示字段差异和实际成员数量，点击确认后生效。空表头资料明确“未填写”，不填样例值或用户名。
3. 教师列表筛选待分配 → 选择教师和班级 → 显示用户名、姓名未填状态、目标班级，提示“表头名单不会自动更改” → 确认分配。成功刷新列表；教师下一次刷新／窗口重新激活读取 Me，进入本班只读配置和日历。已分配行只显示真实归属，不出现无效调班按钮。
4. 学期列表 → 创建名称、起止日期 → 显示日历覆盖和未知日期、重叠错误 → 确认。日历月视图区分默认上课／默认休息／管理员例外／未知；学期外不提供例外编辑。
5. 管理员选日期 → 设上课／停课并填写原因，或撤销例外 → 预览前后状态、来源、周次、未知及移出范围 → 确认。重新导入单独入口，显示实际库版本和差异；不因打开页面自动应用。
6. 409 保留本页非敏感编辑和旧预览，明确已失效，加载最新后由管理员重新生成预览确认；不自动覆盖。受后续能力限制时解释该操作需要计划影响处理，隐藏确认动作，后端仍拒绝绕过。
