## 3. 共同候选与采用契约

业务候选不可变，execution_id唯一。日候选存原始教案或其受控版本ref、拆分基准候选、调整后过程和字段payload；周候选存完整来源manifest、游戏／区域具体身份、材料依据、栏目和主题建议。都附实际config／contract／personal版本、owner_epoch（周）和input hash。

日计划采用只能由创建者或管理员，`expected_content_version`防冲突；同班其他教师只读。采用拆分时保存原始教案与未经适龄调整的split_baseline，最终过程可另采用调整候选。调整／手工编辑不改基准。不能客户端PATCH基准或用最终过程冒充原始拆分基准。采用原文改变时旧拆分候选不挂最新，导出按所采用版本基准比较。

周游戏候选允许明确采用后覆盖人工游戏；其他栏目／材料按负责人选定字段替换，主题只建议不自动覆盖。管理员可编辑草稿但不替负责人采用周候选或确认。来源选择的完整目标指导由业务模块从确切来源填入；AI补足新增`source_kind=ai`，服务端稳定item_id、日引用全null，严格区别manual／daily_plan，不让模型编造真实id。

采用只追加业务内容版本，不创建确认或改历史；UI本地编辑基线不受任务通知和确认刷新隐式推进。新任务回调、采用、确认各自再校验来源／权限／版本，已确认快照保持自包含。候选过期与显式确认已有陈旧内容是两个不同路径，不用ack把旧候选说成最新。

## 4. 切片与授权闸口

下列为建议实施顺序，**不是本轮编码授权**。业务代码仍由OpenCode唯一写入，协调者负责规格、只读审阅和证据整合。

1. **基础配置与指导**：本人配置／加密、全部任务registry、默认及个人指导、适配、日志元信息；先迁移／纯服务，再API／UI。密钥库与HTTP客户端最小依赖在开工清单列出，不扩一级栈。
2. **持久执行核心**：task表、登记／合并、token／lease／send_marker、候选落库协议；先用显式模拟transport验证真实MySQL和真实进程中断，不借此宣称真实AI能力。
3. **业务AI闭环**：日拆分／适龄／其他活动候选采用；周游戏／栏目／主题候选采用；I3／I4投影与来源保护接入。按已确认P4提供节假日上下文，不能以AI编辑方便改变手工流程。
4. **材料闭环**：输入basis、候选依赖、材料采用／编辑／陈旧facts／确认；按已确认P3处理改选后显式重生成，并按M1–M7完成真实调用与下载／Word补验。
5. **维护与恢复收口**：接管指定／接受、调班停用联动、删除恢复联动、运行版本／配置轮换故障测试。若自动任务启动前需要某项授权保护，应提前实现保护而不是等此片才检查。

每片实施前OpenCode列实际修改文件、迁移、依赖和验证，匹配授权范围；缺产品决定先指出，不自选。实现不得把原I4材料恒null当永久边界，也不得先开无候选手填材料绕过能力。

第一片已按 1A 数据／迁移／服务、1B API／权限、1C 前端实现。实际状态见 [部署结果](../bootstrap/ai-slice1abc-deployment-result-2026-10-05.md)与 [Windows 报告](../bootstrap/ai-slice1c-desktop-validation-2026-10-05.md)。当前先补修剩余验收夹具工具并完成隔离真库验证，后续切片仍须具体授权。
