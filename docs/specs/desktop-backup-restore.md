## 3. 完整快照的边界

1. 备份已保存的数据库业务和被模型登记的全部原图／必要衍生图，覆盖当前稿、不可变历史、AI 输入冻结图及合法来源引用。不能只数当前记录或当前照片；不能重编码原图、静默漏图或以当前图替代历史图。
2. 每个受管资源由数据库记录解析相对路径，核对类型、大小、内容散列、真实文件身份与所属根。不信任数据库内的任意绝对路径，不跟随链接／重解析点去读外部文件。
3. 不纳入程序、前端、运行时、Word 模板、更新暂存、运行锁、浏览器缓存、照片 staging、导出临时 DOCX、用户自行另存文件或开发环境。模板属于程序版本，备份记录应用版本，不复制外部模板原件。
4. 不递归纳入旧备份、恢复保护目录和 `migration-backups`。后者是旧 schema 的迁移故障材料；当前完整业务及历史已由本次快照覆盖，不承诺携带全部旧数据库副本。现存迁移备份及未知孤立文件不因备份／恢复被自动清理。
5. 内存中的未提交候选编辑及正在输入文字先由既有保存／离开协调处理。用户明确取消的预览编辑遵守原语义；备份不新增完整崩溃草稿恢复能力，也不能声称包含从未保存的内存输入。

## 4. 一致性、写屏障与生命周期方案

按已确认 P05 核定下列工程边界，具体实现由 OpenCode 提出并接受独立审核：

- 先完成 IME／正文保存以及设置、候选编辑的既有处理；失败停留。正在导入／生成／保存或原生另存为时不能穿过未决操作进入快照。等待／取消备份不等于取消供应商任务，不因等待超时重新生成 AI。
- 快照管理取得本地维护操作的唯一身份和后端写屏障，阻止新业务写入、照片文件生命周期变化、AI 新提交／最终提交及会改变持久状态的清理；等待已有操作确定完成后再捕获。页面禁用与后端屏障须同时覆盖，旧请求及后台执行器不能绕过。
- 使用 SQLite 在线 backup 生成独立数据库，包含已提交 WAL，再依据**这份数据库**枚举资源并逐项复制、验证。SQLite backup 只保证数据库，不自动保证外部照片；见 [SQLite 官方说明](https://www.sqlite.org/backup.html)。
- 冻结边界、文件复制和关闭协调均有进度／取消及有界失败处理；取消和异常释放自己持有的屏障，不释放其他关闭／恢复操作的代次。快照完成前不把输出文件交付为成功。
- 完成内层清单及数据库／文件校验后，再生成最终交付文件。使用同一目标卷的临时文件、flush 和最终提交；失败不能损坏已有同名文件。不能将 Word 的 Base64／30MiB 通道直接用于完整备份。

原语级别的冻结或 SQLite 单独写锁不足以证明这些边界。B1 交付须展示所有相关入口的覆盖与有意义的并发反例；B1 屏障在核查 §8 的实际范围已通过；宿主排空及恢复屏障仍由 B2 取得证据。

## 5. 格式、加密和安全校验方案

### 5.1 格式与版本

使用单个应用可识别文件，含有界格式头及版本化载荷，支持用户已确认的明文和密码加密两种模式。B1 开工核定扩展名、magic、字节布局及严格模式判别；不能通过扩展名或解密失败猜测另一种模式。数据库快照和受管资源形成一个包，清单至少含：snapshot ID、UTC 创建时间、应用版本、备份格式版本、数据库 revision、数据库及资源相对路径／字节数／SHA-256、对象数量和必要业务摘要。

备份格式、数据库 migration revision、AI 历史 contract 和内容版本分别校验。未知／过新格式或 schema 拒绝；已支持旧 schema 只能在隔离副本走明确 Alembic 升级及逻辑摘要验证，不向未知库 stamp、静默 downgrade 或删除合法旧 AI 内容。升级失败不动当前业务根。

### 5.2 密码与现有依赖

当前锁定的 `cryptography==50.0.1` 已具有密码 KDF 和流式认证加密原语；不需要新增依赖。Codex 仅用合成口令验证安装能力：Scrypt `N=2^17,r=8,p=1` 一次约 0.352 秒，流式 AES-GCM 合成往返成功；这是当前开发机的能力探针，不是备份实现、安全验收或全机型性能承诺。

选择加密时，使用随机盐、随机 nonce、从密码派生 256 位密钥，并使用认证加密保护完整载荷；参数及格式头绑定认证，读取前限制 KDF 资源消耗。具体参数、容器布局和大文件上限须在 B1 开工核定。不能用普通 ZIP 密码冒充强加密，不保存可恢复密码或携带 Windows 主密钥，不依赖仅同机可解密的材料加密用户备份。明文模式也须完整校验，但散列不构成来源认证；不得显示为已加密。参考 [KDF 官方文档](https://cryptography.io/en/50.0.0/hazmat/primitives/key-derivation-functions/#scrypt)及 [GCM 官方文档](https://cryptography.io/en/50.0.0/hazmat/primitives/symmetric-encryption/#cryptography.hazmat.primitives.ciphers.modes.GCM)。

大包按流式／有界内存处理；若使用 GCM，认证标签通过前不能把已解出的内容交给业务、预览或包解析器。临时明文仅放受管理的隔离区并有明确失败／取消清理规则；不写口令、派生密钥、完整教案或照片到日志。错误密码、篡改和截断均不得触及当前数据；不能将散列说成来源认证。

### 5.3 外部包安全读取

- 完整校验之前只写隔离区；拒绝绝对路径、驱动器／UNC／设备路径、`..`、反斜线绕过、ADS、保留设备名、尾点／尾空格、大小写／Unicode 冲突、重复成员及文件／目录冲突。
- 拒绝 symlink、重解析点、硬链接及展开后别名；逐级核对真实路径和文件句柄，包中路径不能成为命令、外部文件读取或恢复目标指令。
- 预检声明的条目数／解压体积，并在实际读取中计数、计字节，拒绝伪造大小和压缩炸弹；清单严格解析，拒绝重复键、未知必要字段、负数／bool 伪整数、漏项、多项、坏散列和不完整 SQLite。
- 技术限制须覆盖现有 25MiB／40MP 原图、600 图路径及超过旧 30MiB 桥接能力的大包，并明确实际限制；不能静默删图或给完整业务新增隐藏照片配额。具体总量和清单限制随 B1 的内存／磁盘测量核定。
- 数据库只读检查完整性、FK、revision 和业务逻辑：归属／唯一性、当前内容及历史指针、来源与恢复回执、候选和执行绑定、图片集合／顺序／hash。不能只比较行数或 API 200。

## 6. 恢复与当前数据保护方案

以下落实已确认 P02“替换当前档案”，由 OpenCode 在现有本机数据权威及宿主职责内实施，不扩展多档案切换。

1. 教师选择本地备份文件；在隔离区认证／展开、完整校验并按需迁移副本，展示创建时间、版本、档案／内容数量、照片及凭据可用性等预览。预览成功不是恢复完成，不先覆盖现用库。
2. 确认后再次保护当前未保存工作，处理在途任务和原生 IO，取得后端独占维护屏障及数据根运行锁。无法确认旧句柄／进程已退役则拒绝切换，不强杀不明进程。
3. 创建并校验恢复前的完整本地保护副本，明确其位置和保留方式；不能暗中删除唯一可恢复副本。该保护目录用于本机回滚，包含与现用数据同类的业务内容，须受当前用户目录权限保护；不混同为已按密码加密的可携带备份文件。
4. 关闭相关数据库连接，数据库家族和受管图片作为一组恢复。不能新 DB 配旧 WAL／SHM，不能出现数据库成功而图片未就位的成功状态。现有运行锁位于数据根内，成组切换不能假定可直接重命名整个带锁目录。
5. 用受管、持久的阶段日志和同卷 staging 记录准备、旧组保全、新组切换及核对结果；路径由应用生成，不能照抄包中绝对路径。进程中断后，在迁移、提示词同步和 AI 启动前核对阶段，只选择完整旧组或完整新组。日志不明则保留两边、拒绝写入并给出恢复指引，不猜测成功。
6. 切换前可取消；进入提交切换阶段后不能把取消当作“现在强退”。空间不足、权限、文件占用、迁移／校验失败或中断均不得交付半恢复状态。失败保留当前可用数据或可明确恢复的保护副本，并如实显示阶段。
7. 重新打开后复核档案、内容、历史／来源及图片，刷新页面基线；重启仍可编辑保存、查历史和导出 Word。整库恢复本身不制造新的计划／观察业务内容版本；维护回执与已有历史业务恢复回执分别处理。

恢复不会执行备份中的 AI 请求。合法成功、失败和 unknown 记录保留；旧在途执行须按现有发送证据暂停或归为 unknown，并撤销旧执行许可。临时预览／导出 token 不因恢复而重新成为本轮授权；旧 `launch_id`／session 不能复用，导出临时文件不从旧绝对路径复活。需要重新预览／另存时走正常新操作，保留原结果记录，不伪造旧文件已恢复。

按已确认 P04，同 Windows 用户且独立材料仍有效时可继续解密；缺失、损坏或跨用户／机器时，显示需重新填写，手工编辑／历史／导出不受阻。只用合成 DPAPI 材料验证，不读真实密钥；不能将本机成功写成跨机通过。

## 9. B1 开工合同核定

原 OpenCode 首轮私有工程合同已审阅，以下为 Codex 核定的开工边界；原合同的冻结顺序、`os.replace` 和 Scrypt `maxmem` 表述不得直接照做。不是实现或验收通过。

### 9.1 模块及接口

由 OpenCode 实施 local 层 `backup_format.py`、`backup_snapshot.py`、`backup_barrier.py` 及必要的独立业务校验模块；改动实际相关的 runtime、tx、图片／导出文件写入口、AI 执行器及请求保护。B1 不接教师 UI、不实现 B2 恢复、不修改 ARCHITECTURE、依赖或构建发行。

`SnapshotService.create(output, password, cancel, progress)` 返回已校验最终文件及 snapshot ID／清单／大小／hash；`password=None` 显式表示明文，空字符串不得降级。`verify(path, password, cancel, progress)` 只写隔离区，返回清单、独立数据库和资源根供 B2 使用。取消、进度、同根唯一操作身份和 lease 释放须有实际接口；B2 的原生 IO／页面保护留明确接点，不能测试替身通过就声称宿主已接入。

### 9.2 第一版容器

- 扩展名 `.kgmbackup`，magic `KGMBKP1` 加 NUL，共 8 字节；格式版本 1。固定 128 字节小端头：version(2)、mode(1)、flags(1)、header_len(2)、KDF ID／log2N／r／p／salt_len／nonce_len／tag_len 各 1 字节、3 字节保留、payload_len(8)、salt(32)、nonce(12)、header_digest(32)、20 字节保留。非零保留位／未知模式拒绝。
- mode=1 为明文、mode=2 为密码加密。明文 KDF 参数、盐、nonce、tag 长度全为 0，header_digest 为将自身置零后整头的 SHA-256；只是损坏检测。加密 header_digest=0，完整头作 AAD，尾部 16 字节认证标签；严格核对文件总长，无尾随内容或模式回退。
- 内层 ZIP 只接受 STORED，顺序为 `manifest.json`、`db/kindergarten.db`、按路径排序的资源；严格核对实际成员与清单和数据库登记项。首个格式没有虚构的旧格式迁移；未知格式拒绝。已知旧 DB 只能隔离升级，不把 AI 历史 contract 当库 revision。
- 密码模式用现有 cryptography 的 Scrypt `N=2^17,r=8,p=1`、随机 32 字节盐、随机 12 字节 nonce、256 位 AES-GCM，读取前仅接受固定参数。该 Scrypt API **没有 maxmem 参数**，不得声称设置了它；固定参数约束计算／内存成本，实际内存峰值仍须测量。流式处理，认证通过前不解析明文。
- 初始技术上限：总文件及展开体积各 64GiB、数据库 8GiB、单资源 64MiB、成员 250000。清单上限核定为 **64MiB**，不照抄原候选 256MiB；避免大量 Python 对象和多份序列化副本无界驻留。超限完整失败，不截断业务；容量与内存实证后才给相应通过结论，不把 600 图或 1GiB 工作集变为总存储配额。

### 9.3 必须修正的一致性次序

先取得维护意图，阻止新的外部变更／AI 提交／文件操作，同时让已接受的操作及已在途 AI 正常完成并提交；再等待当前请求、导入／保存、执行／结果持久化全部静止，最后原子冻结调度并取得数据库与文件的快照独占屏障，再核对没有遗漏。在此之前禁止新 DB 写会阻塞 AI 最终提交；提前冻结所有 claim／SEND 又会让已有排队任务无法完成，两者均不符合 P05。

所有 writer 的进入和活跃计数须在同一个原子协议内，失败／rollback／close、嵌套及跨线程释放均配对；旧导入文件阶段早于 SQL 事务，须用整个操作 scope 覆盖。快照 owner 自身的只读备份／校验与其他数据根不被误拦。后台写／清理不能绕过屏障；不能仅在 `begin_immediate` 前做一次无计数的检查。

等待可取消、有明确超时／失败反馈；不能撤销或重发 AI 来凑“已静止”。冻结的获取与释放保留原关闭／取消等独立 owner，快照结束不能调用泛化 unfreeze 清除后来或原已存在的关闭意图。

### 9.4 输出和安全验证

同卷、独占创建临时文件，完整校验并 flush 后才发布；最终提交必须是**原子且不覆盖已有目标**的操作。不能先 `exists()` 再用 `os.replace`，否则并发出现的同名文件会被覆盖。检查已有目标、最后提交前创建目标的竞态、父目录替换及链接／别名，均须保留已有字节并明确失败。

密码模式下，未加密 ZIP、数据库和解密后的临时内容只能放在受应用管理、当前用户权限保护的隔离工作区；隔离工作根位于现用数据根及独立凭据根之外，外部包校验／展开不能先写现用业务目录。不能因为用户把加密备份存到外接盘就把临时明文先放在该盘的公开目录。最终同卷输出临时文件只承载将要交付的选定模式；错误、取消和中断的临时材料须可识别且不作为成功备份。

源图、输出父目录和隔离区均按实际句柄／身份核对，不先 resolve 后忽略重解析；不使用通用递归删除用户或不可信路径。独立隔离区清理也须限定自己创建的对象，失败保留可识别现场，不删保护副本。

真实 SQLite／文件系统验证至少覆盖 WAL、当前及旧已知 schema、未知表／view／trigger／virtual table／列、FK 与业务指针／来源／回执、全部登记原图和衍生图的字节／hash、历史和 AI 图引用、合法旧 AI contract；以及错误密码、截断／篡改、危险包路径／成员冲突、实际 >30MiB 与 600 图量级、取消、空间／权限／占用、并发在途和最终提交碰撞。首失败及限制如实记录，不跑真实 AI 或操作原数据。

新增 `.kgmbackup` 文件及本片实际命名的私有工作／恢复目录须有相应 Git 忽略规则，并验证大小写、嵌套路径和公开资源例外。不能只因本轮测试选了仓库外目录就省略，提交前明确排除备份包、私有照片、日志及保护材料。

## 10. B2 接续设计边界（B1 独立通过后实施）

下列是 P02、P04、P05 和既有保存保护的工程落实，当前先作设计，不能据此提前编写 B2：

1. **教师入口。** 在现有桌面设置／维护区域提供创建备份、选择本地备份并校验预览，以及进度和取消。使用原生选文件／保存对话框；页面取得本轮受限操作标识，不向任意 API 传路径、命令、PID 或 URL。取消选择不报失败或成功。加密／明文选择清楚可见，不在未输入密码时自动降级。明文和密码文件使用同一套完整性与业务校验。
2. **预览绑定。** 预览绑定实际文件字节／snapshot ID、隔离结果及当前操作代次，不能“预览甲、恢复乙”。源文件或隔离内容变更后重新验证，旧预览、丢失回包和重复点击先核对同一操作结果；不并行启动第二次恢复。档案、时间、数量等包内文字只按数据转义展示。
3. **保护副本可使用。** 自动保留的恢复前保护副本必须完整校验并能再次通过应用的正常预览／恢复流程使用，不能只保留需要开发人员手工拼装的库和照片。可使用本地受限目录保存完整快照与可读取清单，或现有格式文件；具体方式由 OpenCode 核定，但不自动删除、不递归收入新备份，界面能告知保留位置。此本机保护材料与教师选择密码加密的可携带备份分开说明。
4. **切换前排空。** 先处理正文、候选及设置草稿、图片导入、原生另存为、AI 和旧 HTTP 变更，取得维护独占后停止旧执行器及后台结果写入，确证数据库会话和文件句柄均已退役。恢复不能借用户正常关闭的 stop-and-exit 擅自将所有任务改为已取消；保护前原结果完整保存。
5. **维护日志和成组恢复。** 日志只记录应用生成的 operation ID、固定相对组件和阶段／hash，不能执行包内路径。保全旧 DB 家族及资产，安装新 DB 与资产作为一组，避免旧 WAL／SHM 附着新库。明确每次落盘、改名、提交及复核的顺序和崩溃边界；空间不足／占用／权限／迁移失败时保留旧完整组或可明确恢复的保护副本，不显示部分成功。
6. **启动接续。** 在持有适当独占的前提下，先解析维护日志、核对实际完整组，再允许普通 prepare、schema 迁移、提示词同步和 AI 启动。崩溃发生在组件改名和日志更新之间，也须依据预期身份／hash判断；不明则保留两组并拒绝写入。不能把这种未知状态自动记作恢复成功或反复恢复。
7. **旧身份退役。** 加载恢复后的工作台时建立新的 launch／API session／页面与关闭代次，旧 HTTP、候选 token、导出／恢复预览、关闭 ack 和后台回调不能命中新库。即使恢复到同 profile ID、同记录 ID 或更旧版本，也不能让旧页最后保存或迟到 AI 结果写入；不能仅靠 UI 清空缓存。
8. **结果和关闭。** 完整组核对成功并能重新加载业务后才显示完成。提交切换前可取消并保全当前稿，进入不可安全取消阶段后明确显示正在完成，阻止正常关闭越过切换；异常终止按阶段日志接续。完成后重新读取恢复的资料及编辑基线，不回用旧 DTO。保留维护回执，整库恢复不制造业务内容新版本。
9. **凭据和 AI。** 原独立凭据目录不被覆盖或清空，database_uuid／key_id／nonce／密文保持；只有合成同机材料可用时沿用，缺失／坏材料允许手工业务且提示重填。新执行器先做安全启动分类，旧在途按发送证据暂停／unknown，保留原失败／unknown 与原因；任何测试都不产生真实供应商请求。
10. **独立验证。** 真实源窗口与新进程重启、重复恢复、错误口令／坏包、保护副本再恢复、各切换边界故障注入、旧页和旧回调迟到、取消／关闭／原生保存交叉、同机 DPAPI 与缺材料、恢复后编辑／历史／来源／图片／Word 必须分别取得证据。注入覆盖和真实断电、当前开发机和其他机器／用户、源码和冻结包分开报告。

2026-10-31 工程合同补充（仍待 B1 通过后实施）：

- **连续维护能力。** 保护副本捕获与切换共享同一个已排空、独占的维护 lease；不能在保护成功与切换之间释放写屏障。B1 通过后由共享核心所有者提供内部受控捕获入口，核对实际数据根、owner／token、独占与存续状态，不释放调用者的 lease。恢复实现不得复制一套快照引擎，也不让页面提交 lease 或文件路径。
- **恢复保留运行锁。** 沿用原 Runtime 和运行锁，只退役旧 engine／会话再重开；不能先 dispose 再用第二 Runtime 绕过锁。API 旧 token 为闭包值，须重建 app／session_scope；新 executor 使用新 launch 身份。服务停止须确认线程已退出，不能只调用带超时的 join 就切换文件。
- **临时授权与业务历史。** 轮换配置预览 HMAC，清空现有三类内存 token store；旧观察恢复预览须失效，旧导出按 launch／scope 失效。可以改变这些临时授权状态及已有安全启动分类，不删除业务历史／候选／回执、不制造新业务版本；独立比较应逐字段列出这些预期变化。`recover_on_start()` 会写库分类，不发网络，不能称为只读检查；独占仍在时不得让普通 writer 绕过屏障。
- **Windows 落盘证据。** journal 与逐项改名共同形成可接续协议，不构成多文件原子事务。以实际文件身份和完整组 hash 处理“改名已发生、日志尚未更新”的窗口；落盘失败保留两组。核对实际 `FlushFileBuffers` 写权限与同卷移动调用，受控失败／真实进程终止分别测试，不由单一 flag 宣称真实断电或硬件缓存安全。参考 [FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers)、[MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw) 及 [Moving Directories](https://learn.microsoft.com/en-us/windows/win32/fileio/moving-directories)。
- **物理身份时点与日志退役。** 旧组的物理 hash／WAL／SHM 身份在旧服务、执行器、会话和 engine 均关闭、检查点已稳定后固定，不能把在线保护包的 DB 物理 hash 当作关闭后旧组 hash。安装核对完成后，在任何新 engine 启动写、HTTP／UI 开放之前，须将切换中的 active journal 安全退役为操作回执或等价关闭状态；其后不得按安装时 DB hash 把正常提示词同步、AI 启动分类或教师新写入误判为损坏并自动回滚旧档案。必须验证恢复后新写、再启动两次仍保留新工作。文件组提交与 UI 重载分别记录终态，不能把重开失败说成资料未恢复。
- **已退役连接不可复活。** SQLAlchemy `engine.dispose()` 不禁止旧 engine／Session 对象重新取连接；恢复接缝须显式使旧代次不可重新连接或写入，并在旧连接全部退出后检查 DB 家族占用。不得仅靠宿主线程已停止推断旧对象失效；合成验证持有旧 Session，恢复后再次尝试读写应受控拒绝，新代次正常工作。
- **互斥与分工。** 备份／恢复与关闭、原生保存及更新安装共用明确的维护互斥；本轮保持源码只检查更新，不新增下载／安装行为，不丢弃既存更新材料。B1 通过后先冻结共享接口，再划分恢复核心／Runtime 与宿主／API／前端文件责任；共同文件不并行写。辅助完整夹具只读复用，源码、合成故障、窗口与未验范围分别报告。

### 10.1 B2-S1 共享捕获接口核定（限定源码独立通过）

采用现有结果／进度类型，新增内部 `SnapshotService.capture_maintenance_protection(*, lease, output, cancel, progress=None) -> SnapshotResult` 及 `SnapshotBarrier.validate_exclusive_lease(lease)`。保护包固定 Format 1 明文；输出为数据根、凭据根和 B1 工作根外的绝对路径，由调用者创建私有父目录，捕获入口以实际句柄核对当前用户受限 DACL。该接口不向页面／HTTP 暴露 lease 或文件路径。

调用者顺序必须是：先保护页面工作 → 建立维护 intent 阻止新外部提交 → 允许已接受 DB／文件／AI 工作及结果持久化正常排空 → 确认 live／queued AI 已终结 → 以本轮唯一 owner 冻结调度并确认执行器 idle → 取得并持续持有 exclusive → 捕获保护包并切换。不能先 freeze 再等待旧排队 AI；不能先排空后才建立 intent 留出新提交空隙。freeze owner 使用如 `restore:<operation_id>` 的本轮唯一值，防止迟到释放清掉下一轮 owner。

捕获入口再次只读核对同一 barrier 实例、有效 owner/token、exclusive／未 release、DB／文件计数为零、执行器 idle 及数据库中无 live／queued AI。失败受控拒绝，不在 exclusive 下等待需要写库的 AI，不重新取 lease、不释放调用者 lease、不调用 freeze／unfreeze。复用同一捕获引擎、正常 verify 和 no-replace 发布，保持提交前取消／提交后完成的终态。

独立验证至少包括：同一 lease 捕获后仍拒绝其他 writer／文件操作／新 intent；错误根、失效／未独占及不合类型的 lease 拒绝；执行器 idle 但 DB 仍有 queued AI 时拒绝；缺图／坏图／同名输出／取消失败不释放调用者或其他 owner；普通 create／verify、旧包及密码包保持。接口通过并固定后才交恢复核心使用。


### 10.2 宿主接续与异常退出的固定边界

- 旧 host 在 core 重开新 engine 前退役；重开使用新的 app／token／scope／launch／Window／host，窗口回调绑定自己的 bundle。新窗口存在、读取业务并显示实际页面后，再收口旧窗；通知与连接／错误／首次／正常页面条件链分开。
- 面板维护锁与排空既有操作的 pageBusy 分开，关闭探针另行覆盖在途维护，避免维护操作等待自己。开始／确认以 requestId 和操作代次幂等登记，丢回包先查询同一请求；页面仅传原生选择的 opaque ID。
- 新服务在 ready 之前已有生命周期所有者；失败创建或未确认停止也必须由最终清理追踪。仅在实际相关服务／执行器退出确认后释放原 Runtime 锁；错误页的退出仍使用最新 bundle。
- 需要重启的已终结维护错误可安全结束窗口；特殊退出由已退役 host 或已确认 transport 停止等实际状态支持。仅 recovery_required 旗标不绕过普通 AI 在途、未保存工作或正在切换／重开的保护。
- 预览、错误口令重试、准备和取消按核心操作身份收口自有暂存；被替代请求保持可查询并退役其活动能力。成功发布结果优先于迟到取消；未知安装状态提示核查，不进入成功重开。保护副本的嵌套校验进度仍可取消，不以通用 verify key 推断已开始切换。
- 进度用教师可读文案；恢复后的新页面保留保护副本位置和保留方式的可复制文本。显示位置不承担路径／命令授权，密码不入状态、通知或日志。

本节落实既有 P02／P05／P06 与 §6 的显示、隔离和安全接续要求；实际源码窗口、原生实际点选、教师体验及发行各自取证。
