## 输入与输出

输入为当前本地数据中的计划、明确的内容版本、筛选范围、固定模板及日计划活动过程比较基准；输出为 Word 文件。导出不修改计划内容、来源关系或确认状态。

本机应用会话与请求来源校验须覆盖导出入口和文件传递；同班教师查看、导出他人计划与园所管理员权限不再作为 v2 要求。本地身份及历史数据访问方式按身份规格确定。

表头中的园所名称、班级教师名单及保育员姓名来自本地班级配置；具体维护界面另定。日计划显示创建教师，周计划显示班级教师名单和保育员。周次沿用实际日期所在的学期周次算法，不能从表头日期跨度或所显示列数重新计周；表头起止日期显示该周第一个至最后一个上课日，依据有效日历，不因某日缺少日计划而缩短范围。

## 范围规则

- 日计划支持单日、按周、按月及自选日期范围；严格筛选范围内日计划。内容缺项时先提示，教师确认后仍可导出，保留空栏目，不自动补写；这不改变周计划内容确认规则。
- 周计划支持单份及按日期范围合并；以其上课日期是否与范围相交选取整份计划。
- 选择单日会选出包含该上课日的整份周计划；跨周、跨月不裁切周内栏目，每份只出现一次。
- 未确认候选不导出；上一份已确认版本可以导出但提示存在更新。
- 当前内容不完整也可由制作教师确认后导出，记录缺项或未更新内容，不强制 AI 成功。

无匹配计划时提示，不生成空文件，不扩大日期范围。日计划按日期升序合并，周计划按周起始日升序合并；每份计划从新页开始，份内长内容自然分页。单次导出按实际入选份数限制为日计划最多 31 份、周计划最多 8 份。

上述31份／8份只适用于日计划／周计划；游戏观察不新增任意业务份数额度，技术容量仍须后续验证，不静默套用旧限制。

2026-10-14 D1B范围已收敛：本片只适配日计划。按明确日期范围选择已保存有效记录，旧学期、当前学期外或当前停课日的已有计划仍可导出，不受当前新建资格限制。缺项确认绑定范围、完整计划／内容版本集合及完整缺项事实，变化后重新确认；读事务内物化DTO后结束，再生成Word。受限宿主另存为区分生成失败、取消、保存失败和实际成功，不附加导出自动保存。接口和竞态规则见[D1规格 §12](../specs/desktop-manual-daily-plan.md#12-d1b-word-范围确认与原生保存)。2026-10-15第二轮修复后R11／R13关闭，R6仍有旧查询解除新保存互斥的问题，真实原生操作／Word全页待补验，未获产品验收，见[审阅 §11](../bootstrap/desktop-d1-review.md#11-d1b-第二轮修复复审2026-10-15)。

既有导出引擎在内存生成完整 DOCX 并返回文件内容，可作为本地 API 复用基础。桌面容器中的文件选择、保存或下载机制须验证后在规格中明确；不把“服务不保留导出副本”解释为教师不能保存文件，也不因封装桌面窗口而默认已有浏览器下载行为可用。

## 游戏观察导出扩展（2026-10-26，E13设计核定）

导出关联表前片已通过[E01／E02／E04独立核查](../bootstrap/desktop-game-observation-foundation-review.md)。2026-10-28接续已实施三模板、明确选集／排序、固定snapshot及受限宿主交付；本片独立证据与当前回修状态见[导出核查](../bootstrap/desktop-game-observation-export-review.md)，不由表结构或实现者自测替代。

输入为观察模块固定导出快照；Word只渲染，不决定采用、不回写观察资料或材料。单份及勾选多份可混合公共／室内／户外，跨页选择维护明确ID集合；默认日期升序、缺日期末尾，同日起始时间升序、缺时间当日末尾，同值创建先后，仍可手调。先成功保存当前编辑，缺项确认绑定实际选集／顺序／各draft revision及aggregate hash／完整缺项事实；变化重新预览，物化后只按固定snapshot生成，不回读当前稿混版本。

仅有表头资料、四栏均无实际正文且无有效照片才为空记录；有正文无图或只有有效照片均可导出。缺项允许明确确认后留空，坏图／空记录先处理并阻止整次，不静默漏图或跳过记录。三模板为A4纵向、原六列网格及8行业务表；标题在表外“{园所}游戏观察记录（公共/室内/户外）”，宋体16磅加粗居中。第1／2行各6独立格，第3行姓名值2–4合并span3，第4–8行值2–6合并span5；固定标签沿模板，含“幼儿年龄”；基本资料含环境11磅，四栏正文值12磅。第6行正文后每组1或2张inline图，单图居中，按顺序等比不裁切，默认不印说明；每份新页、份内自然分页，不留额外空白末页。

snapshot_id不是读取凭证；所有查询校验应用会话及归属，export_id受限token绑定profile、launch/session scope、固定选集／hash、期限及状态。宿主save_observation_export(export_id,filename)仅从固定本机端点流式原子另存为；同token同文件名指纹仅查询原结果或在途，异指纹拒绝，不重复开对话框。实际结果区分saved/cancelled/failed/indeterminate，回执丢失不能自动再保存；宿主实际IO才是保存结果来源，后端收到报告后记录，不因生成／下载完成而报saved。

成功／取消／失败／过期释放本尝试临时DOCX，保护仍在读取的流；有效期内用户可明确按固定snapshot新建token重试，过期重新预览，只清临时对象，不删业务原图／历史／input引用。旧save_docx及30MiB限制不变，不放宽原Base64入口。受限查询、快照字段、宿主回执及完整Word／命名规则统一见[观察Contract§7](game-observations.md#7-导出与-word)与[工程E11–E12](../specs/desktop-game-observation-engineering.md#12-e11三模板及固定导出)。

本片三模板及产品实际输出已在当前Windows 11／Word16.0 Build16.0.20527以合成资料逐页核查，原生另存为取消／明确重试／实际保存另有证据；最终工程结论以[导出核查](../bootstrap/desktop-game-observation-export-review.md)为准。DOCX结构、COM或PDF不能替代真实Word页面，教师产品验收、WPS、其他环境、冻结新包与发行未整体通过；D2／D3历史结果及[E13设计记录](../bootstrap/desktop-game-observation-contract-review.md)保持各自身份。

实际参数、受管产物摘要锚点、到期释放及终态待回报／明确补报协议统一见[工程§13.1](../specs/desktop-game-observation-engineering.md#131-本片实际协议与技术参数2026-10-28)。只读结果查询不执行补报；补报仅使用宿主已有实际IO事实，不再下载／弹窗／写文件，不把后端回执丢失误当文件未保存。

## 标红与兼容

日计划活动过程以原始教案拆出的过程为基准，比较教师最终采用内容，导出时将改动标红。活动主题必须正确填充，不保留旧系统字段遗漏。

上述标红只适用于日计划；游戏观察不加入标红、AI审核提示、候选标签或脚注。

已确认：无原始拆分基准时按最终内容导出，不标红并提示无法比较；有基准时新增和替换后的文字标红，纯删除不显示已删文字，纯段落移动和仅格式变化不标红，不增加删除线。

首版不提供任意模板上传编辑，不引入 Typst 转换。已导出文件是时间点副本，后续计划变更只能通过重新导出体现；本地数据库和业务版本仍是权威内容，导出文件不是业务主数据。若文件传递使用临时资源或 object URL，应按其生命周期释放；临时资源方式在桌面规格中确定，不新增长期导出文件仓库。

## Windows 实际验收

Windows 11 是已确认的桌面首发系统，Windows 10 后续验证。具体运行条件按 ADR 0004 与桌面首片规格验证，不从旧测试环境反推完整支持清单。

DOCX 须通过实际产品导出并保存，再在 Windows 桌面 Word 或 WPS 文字中实际打开并逐页检查页面视图或打印预览，记录实际系统、软件版本／构建及字体。仅有 OOXML、PDF 或 LibreOffice 结果不能替代实际 Word／WPS 验收；不要求实体打印。

保留内容、分页、表格、动态列、标红、范围、版本与合并等案例，桌面文件交付还须核对中文文件名、非空字节、文件完整性和失败不产生误导文件。范围切换时旧响应不得覆盖新选择或触发旧文件保存，既有竞态保护需在桌面形态复验。

历史 [I5 验收环境](../specs/i5-validation-environment.md)与[正式收口](../bootstrap/i5-final-closeout-2026-10-03.md)只证明各自记录的版本与环境，不自动证明桌面容器兼容。旧环境中的远程实例、本机 WSL 或 MySQL 要求不再是桌面验收拓扑；既有完整 W6 非空材料待验仍保留待验身份，后续相关材料切片须完成，不因架构调整标记通过。
