# AI Service Contract

状态：Architecture v2 有效 Contract，2026-10-08；依据[ADR 0004](../adr/0004-local-desktop-architecture-proposal.md)。本地运行方向已接受，实现和验收仍需分别记录。

## 职责与权威数据

本模块拥有教师个人 AI API 地址、模型、加密密钥及配置版本，统一处理网络调用、结果结构校验、失败分类和调用元信息。不拥有计划的业务确认权。

AI 请求由教师电脑上的 Python 程序发出，界面不直接持有密钥调用供应商。对 OpenAI 兼容服务的接入是已确认方向；具体协议、接口路径和兼容范围按接入规格确定，不默认所有供应商均支持同一接口。本地运行不能保证供应商不超时。

## 调用契约

调用方提供任务类型、本地操作身份与配置归属、来源内容及版本、输出字段契约、实际提示词版本。返回经校验的候选结果或分类错误，以及实际配置版本、耗时等元信息。业务模块决定是否采用。本地身份的具体形式在身份规格中确认。

- 每日活动计划使用当前使用者明确配置的 AI 服务和个人提示词，不静默借用他人密钥。
- 周计划使用制作教师的配置和个人提示词；其触发方式、其他栏目输入与交付顺序在周计划规格中确认，不沿用云端负责人离线自动调用规则。
- 字段契约未适配时暂停对应任务，手工编辑和保存仍可使用。
- 配置修改不自动重新生成已确认计划。待执行任务使用最新有效配置与已适配提示词；已开始任务保持启动时的版本，记录实际使用版本。

## 游戏观察调用扩展（2026-10-26，E13设计核定）

E02已实施四张AI表的来源链与旧daily必需写入适配，见[E01／E02／E04独立核查](../bootstrap/desktop-game-observation-foundation-review.md)。观察类型只登记数据；本节视觉发送、执行、候选与采用仍未实施，应用真实AI未调用。

观察复用本模块同一配置、执行、校验、失败分类及任务状态；不另设观察调度／执行状态机。source_kind只为daily_plan/game_observation，观察任务固定game_observation_generate/rewrite。四AI表的非空来源复合链、旧daily约束保留及观察材料关联统一见[观察Contract§3.2](game-observations.md#32-共用-ai-四表非空同源复合链)；旧日计划API显式限定daily_plan并保留原响应，全局关闭／在途统计覆盖两类。

观察从成功保存draft冻结业务input、schema、全部已关联照片／工作图／顺序／说明和派生参数；source_revision仅元信息，FK指稳定record，不把草稿revision指向历史version。待执行任务在claim／开始时选择最新有效配置及已适配提示词，execution记录实际config/default/personal/contract、模型和该input已冻结派生参数；不重建旧工作图，不因后来配置变化追溯污染兼容候选。schema不兼容时暂停该任务，不暗改input。

实际基础字段与四栏／单栏上下文矩阵、候选和采用协议统一见[观察Contract§6](game-observations.md#6-ai-投影候选与采用)。所有已关联照片参与明确AI操作；不静默取子集。网络worker只读已验证图文，材料层在事务外解码／派生。视觉帧独立版本化，保留既有公网HTTPS／DNS／peer／TLS、dispatch、密钥保护及未知结果不自动重放；不全局放宽旧1MiB文本保护，视觉字节、IPC、工作集及超时仍待容量验证。

AI拥有执行、结构校验、候选持久化及状态，观察拥有候选业务意义与采用决定。正常编辑、手工保存、历史恢复及Word不依赖AI就绪；候选不直接覆盖正文，补写提示不入Word／后续提示词。上述观察执行／采用仍仅设计，未调用应用真实AI；E02仅完成数据来源基础。D2／D3既有结果不因本扩展改写，设计核定见[E13记录](../bootstrap/desktop-game-observation-contract-review.md)。

## AI 与教师边界

当前优先交付教案拆分、活动过程年龄适宜性调整与日计划其他活动生成。周计划游戏选取和补足、主题建议及其他栏目能力保留业务边界，按后续规格及授权实施；不能从能力清单推定本轮全部实现。

AI 不能代替教师确认，不能将候选直接设为正式内容。候选不足时可生成游戏名称、目标和指导，但须标记为 AI 补充，不能伪造日计划引用。AI 失败保留已有内容，不能阻断手工备课。

## 失败、执行与恢复

鉴权、额度、配置错误暂停；明确可重试的临时失败有限重试。无法确定供应商是否已经处理的超时或进程中断不自动重发，提示可能重复计费并允许手动重试。

JSON 无法解析、必需字段缺失等输出错误须区分于网络错误；是否重新调用、次数上限和费用提示在实施规格中确定，不默认无限纠错调用。

本地执行采用受控调用并发，网络调用不占用长数据库事务，不阻塞界面正常编辑。任务状态保存在本地；执行组件与界面进程的具体组织在实施规格中确定，不再要求中央服务器与 MySQL 工作进程。

本地任务只在程序运行期间执行。关闭窗口、退出、休眠、更新前的处理需在规格中明确；持久化状态不保证能够恢复供应商端正在执行的请求，也不提供外部供应商“恰好一次”处理保证。换电脑或恢复备份不能自动重放旧任务。

## 安全边界

密钥加密保存，解密材料与普通业务数据库分开。仅在获授权任务中使用，不完整回显，不写入日志、错误或前端持久存储。配置版本标识不等于保存明文密钥。具体 Windows 凭据保管方式另定；本机绑定加密的密文不能直接视为另一台电脑可用的凭据，跨设备凭据处理遵循 ADR 0004。

仅允许公网 HTTPS API 地址，校验实际连接目标和重定向，阻止本机、内网、云元数据等地址。网络校验须覆盖 DNS 解析与跳转，不能仅校验输入字符串外观。本地桌面运行不代表已授权本地或内网 AI 端点。

本机业务 API 只监听回环地址并校验本次应用会话与请求来源；这是界面与本地程序的通信边界，与公网 AI 地址限制分别执行。

日志默认只记录任务、操作身份、配置／提示词版本、状态、耗时及脱敏错误；业务需要的候选内容由日计划或周计划模块保存，不作为遥测上传。
