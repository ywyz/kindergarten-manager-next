# 用户与班级 Contract

状态：已确认业务边界。本文不是 API 路由或数据库字段清单。

## 权威数据与职责

本模块拥有账号、角色、班级归属、维护交接授权，以及管理员维护的学期起止时间、上课日、班级年级、区域和户外游戏配置。首版单园所；每位教师归属一个班级。同班配置共用，不按教师分别保存学期或班级游戏配置。

园所名称、班级教师名单及保育员姓名由管理员维护，作为 Word 表头信息来源；日计划显示创建教师，周计划显示班级教师名单和保育员。保育员姓名是表头资料，不因此新增保育员账号角色。

教师注册后待分配；管理员分配班级后才能使用备课功能。管理员可管理账号、停用账号、分配班级、查看全园计划、修改删除教师计划及查看日志。管理员不能通过产品读取教师完整 API 密钥。

## 已确认的账号入口与恢复

2026-09-21 用户确认：注册与登录使用用户名和密码；教师姓名在系统设置中填写，不作为注册必填或登录标识。第一个成功注册的账号成为管理员，后续注册为待分配教师；不能由注册请求指定角色或班级。

首版教师忘记密码由管理员重置；管理员密码通过服务器上的系统恢复操作重置，不采用邮件或短信自助找回。首个注册并发、密码重置与会话失效的工程方案，以及下一项账号任务的边界见[账号注册、登录与待分配访问规格](../specs/identity-registration-and-access.md)。

本人设置姓名与管理员维护的班级教师名单分开，不因教师修改姓名自动覆盖班级表头资料；姓名变更对历史计划表头的处理留到计划／导出字段规格明确。

## 提供的业务能力

- 判断账号是否能够备课，以及当前所属班级。
- 判断计划是否可查看、编辑、删除、确认或接管；工作进程同样遵守授权。
- 提供学期及班级配置，解释日期对应的周次、星期和上课日状态。
- 提供调班、停用、负责人交接与日历变更的业务事件或状态，供相关模块处理。

以上为逻辑交互，不指定新增事件中间件。跨模块更新通过已确认的事务和数据库持久任务完成。

## 调班、停用与历史

历史计划不随调班迁移，保留原班级和原创建者。调班教师可查看、导出本人原班计划，但不可修改，也不再查看原班其他教师计划；获得新班权限。

周计划负责人调班或停用后，暂停其负责周计划的自动 AI 调用。管理员指定原班教师接管，接管者明确接受后获得维护及确认权限，调用切换到其 AI 配置和提示词。原创建者保持不变。交接前管理员仍可处理内容，已有确认版本可按权限导出；管理员编辑不自动获得代确认权。

对已经发出的 AI 请求不能承诺撤回；接管或权限变化后，旧结果不得绕过当前负责人及版本检查直接生效。

## 日历调整

有计划后不静默追溯重算归属。管理员修改学期或上课日时先看到影响范围，确认后生效；若会产生有效周计划冲突，先解决冲突。受影响周计划进入待更新状态，已确认版本保留。

## 已确认的周次与日计划数量

周一至周日为一周，学期开始日所在周为第 1 周，不足七天也计一周；假期不跳过周号，跨年不重置。调休上课日按实际日期所在周归属，不挪到被补课的周。具体计算及例子见[最小实施规格](../specs/manual-plans-and-word-export.md)。

同班同日仅一份有效日计划，因此同一教师在该班同日也只能一份。重复创建打开已有记录并遵守原编辑权限；删除记录恢复时遇到有效记录冲突须先处理，不覆盖。

## 调休判断与同班导出

已确认使用 Python 库 `chinese_calendar` 判断调休补课日期，教师可在学期内的调休补课日自行创建日计划，不要求管理员先逐日添加补课配置。此处为教师主动创建，不是后台自动生成日计划。库提供默认日历，管理员明确配置的园所停课、补课例外优先；没有例外时，库识别的学期内补课日直接允许创建。库未覆盖某年份时提示“该年份日历数据未就绪”，管理员配置上课日后可继续使用，不猜测调休，也不阻止已有计划查看和导出。有效日历仍由用户与班级模块管理并持久化在 MySQL，既有计划不随库升级静默重算。

同班教师可以导出他人的日计划和已确认周计划，不因此取得编辑或确认权限；调班后的历史访问限制不变。

普通非上课日及学期范围外日期不允许直接创建日计划；确需备课时，管理员先调整上课日或学期范围，再按有效日历创建。调整仍遵守已有计划影响预览、确认及冲突处理规则，不借创建操作静默修改日历。
