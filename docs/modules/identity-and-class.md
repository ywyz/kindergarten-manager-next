# 本地身份与班级配置 Contract

状态：Architecture v2 有效 Contract，2026-10-08；依据[ADR 0004](../adr/0004-local-desktop-architecture-proposal.md)。本文是业务边界，不是 API 路由或数据库字段清单；实现和验收仍需分别记录。

## 权威数据与职责

本模块管理本地使用者身份、学期起止时间、上课日、班级年级、区域及户外游戏配置，以及园所名称、班级教师名单和保育员姓名等表头资料。运行时有效配置保存在本地 SQLite；WebDAV 用于快照接续与备份，不作为日常业务查询数据库。

2026-10-08 产品确认：桌面首版采用一个本地教师档案，首次填写姓名、班级和学期，完成初始化后直接进入工作台，之后启动也直接进入工作台。无需旧注册、登录或等待管理员分班流程，不再要求园所管理员集中管理、同班共享查看或管理员接管计划。

2026-10-11 产品补充确认：首次一起填写姓名、班级名称及年级、学期名称及起止日期；园所名称可以留空后补。稳定内部身份、原子初始化、重试幂等及D1A数据／API边界见[D1规格](../specs/desktop-manual-daily-plan.md)。D1A在3.14.7基线上工程通过；2026-10-15首次页面及维护入口已有实现，配置相关问题关闭，但D1B仍待R1／R6及补验，未获产品验收，见[审阅 §11](../bootstrap/desktop-d1-review.md#11-d1b-第二轮修复复审2026-10-15)。

2026-10-14 用户确认 D1B 支持当前班级名称／年级维护和沿用 ID 的同班升班，新增班级及多班切换后置；支持学期新增、名称及起止日期修改、切换浏览。旧学期以及日历调整后移出范围或改为停课的已有计划仍可编辑、导出，保留原归属、周次、创建日历修订和四项表头快照。日期创建资格与已有记录访问分开；切学期只是浏览选择，不迁移已有计划。具体配置预览、版本复核、日历修订及 API 见 D1 规格 §9–10。

单档案入口不取消本机 API 的应用会话与请求来源（Origin）校验；内部稳定身份标识及班级、学期配置的具体维护方式按[桌面基础适配计划](../specs/desktop-foundation-plan.md)细化，不据此新增多档案或本地密码流程。

日计划显示创建教师，周计划显示班级教师名单和保育员。保育员姓名是表头资料，不因此新增保育员账号角色。使用者的姓名与班级教师名单分别保存，不因修改个人姓名自动覆盖班级表头资料；姓名变更对历史计划表头的处理在计划／导出字段规格中明确。

## 提供的业务能力

- 为计划提供明确的本地制作身份与所用班级、学期配置，保留历史来源。
- 提供学期及班级配置，解释日期对应的周次、星期和上课日状态。
- 提供日历变更的影响范围与有效配置版本，供计划模块处理。
- 配合本机 API 的应用会话及来源校验，避免不受信任网页直接访问本地数据。

以上为逻辑交互，不指定新增事件中间件。跨模块业务更新保持事务一致；本地任务具体组织按后续规格确定。

## 配置变化与历史

已有计划保留原班级、原创建者与相关版本，不随配置改变静默迁移或改写历史。班级或使用者变化后的访问、编辑和数据迁移方式在本地身份规格中明确，不继续套用中央管理员调班、停用及接管流程。

对已经发出的 AI 请求不能承诺撤回；来源、配置或适用身份变化后，旧结果须经过当前版本及适用性检查，不能直接生效。

## 日历调整

有计划后不静默追溯重算归属。使用者修改学期或上课日时先看到影响范围，确认后生效；若会产生有效周计划冲突，先解决冲突。受影响周计划保留来源变化标识，已确认版本保留；是否及何时自动生成新候选另按周计划规格确定。

## 已确认的周次与日计划数量

周一至周日为一周，学期开始日所在周为第 1 周，不足七天也计一周；假期不跳过周号，跨年不重置。调休上课日按实际日期所在周归属，不挪到被补课的周。既有计算例子见[最小实施规格](../specs/manual-plans-and-word-export.md)，使用前排除其中被 v2 替代的身份与部署条款。

在本地数据中，同一班级同日仅一份有效日计划。重复创建打开已有记录；删除记录恢复时遇到有效记录冲突须先处理，不覆盖。不据此引入同班教师之间的共享、锁定或中央唯一性服务。

## 调休判断与创建范围

已确认使用 Python 库 `chinese_calendar` 判断调休补课日期。教师可在学期内的调休补课日主动创建日计划，无需预先逐日添加补课配置；此处不是后台自动生成日计划。

库提供默认日历，使用者明确配置的园所停课、补课例外优先；没有例外时，库识别的学期内补课日直接允许创建。库未覆盖某年份时提示“该年份日历数据未就绪”，配置上课日后可继续使用，不猜测调休，也不阻止已有计划查看和导出。有效日历由本模块管理并持久化在本地 SQLite，既有计划不随库升级静默重算。

普通非上课日及学期范围外日期不允许直接创建日计划；确需备课时，使用者先调整上课日或学期范围，再按有效日历创建。调整仍遵守已有计划影响预览、确认及冲突处理规则，不借创建操作静默修改日历。

## 实施前须细化

2026-10-17用户确认D2班级游戏配置采用最小方案：可用区域／专用室、户外场地或游戏范围及简短限制／指导；未填写时允许生成一般建议并明确说明，不增加按星期排班。默认任务年级取计划创建快照，可明确选择本次目标年级，不改当前班级或旧表头。工程字段、版本及沿现有预览／应用路径的扩展见[D2规格§9.1](../specs/desktop-ai-daily-plan.md#91-配置和任务输入)，目前只有规格，没有新增配置实体／接口或迁移。

- D1B 当前班级、多学期维护、已有计划访问及有效日历预览已按 D1 规格 §9–10 收敛，不再列为产品未决；新增班级／多班切换仍后置。
- 配置变更、换机及恢复历史数据时的身份与计划映射。

这些事项不允许从旧系统推定，也不扩大为当前未确认的班级人数管理功能。
