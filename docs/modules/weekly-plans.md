# 周计划 Contract

状态：Architecture v2 有效 Contract，2026-10-08；依据[ADR 0004](../adr/0004-local-desktop-architecture-proposal.md)。本地制作及来源调整已确认；周计划后续交付时间、其他 AI 栏目完整输入和自动触发细节仍待规格确认，实现和验收分别记录。

## 归属与唯一性

周计划由本地制作教师维护和确认，不再要求同班共享查看、管理员编辑删除或负责人调班接管。制作身份及班级配置的具体映射随本地身份规格确定。

本地数据中，同班、同学期、同周只保留一份有效周计划。重复创建打开已有计划；可恢复删除与重新创建不得产生两份有效记录。恢复存在冲突时先处理冲突，不能静默合并或覆盖。

创建身份和必要历史版本保留。原中央系统的创建者与负责人交接、停用及他人密钥切换不再作为当前义务。

## 内容来源与生成

| 内容 | 来源与生成规则 |
| --- | --- |
| 主题名称 | 教师提供，AI 可建议但不自动覆盖 |
| 制作教师的晨间谈话、集体活动名称 | 按本人日计划日期对应 |
| 另一位教师的晨间谈话主题、集体活动名称 | 由制作者按日期手工填写，不要求取得另一位教师日计划 |
| 户外游戏 | 仅参考本人日计划晨间活动与班级配置，AI 选两项集体游戏、一项自选游戏；日计划的一项集体加一项自选不改变周计划数量，候选不足按缺项及补足规则处理 |
| 重点区域中的游戏 | 仅参考本人集体活动后的区域、户外或专用室游戏及班级配置，不读取其他教师日计划 |
| 已引用游戏的目标与指导 | 读取所引用本人日计划的对应内容，保留来源和版本 |
| 材料 | 保留按所选游戏名称、目标、指导、支持策略及班级年级提取材料、不足时建议补充的业务规则；v2 完整输入映射与触发方式在周计划规格中确认，制作教师编辑确认 |
| 不足游戏 | 列出已有内容并提示不足；允许 AI 补足名称、目标、指导，标记 AI 补充 |
| 本周重点、环境创设、生活习惯培养、家园共育等其余栏目 | 完整输入依据与生成触发方式待确认，不沿用汇总全班日计划的假设；生成结果仍须制作教师编辑确认 |

引用日计划的内容保留来源和版本；班级配置作为依据时保留实际使用版本。AI 补充不得伪造日计划来源，仅存在于周计划。来源补齐后如重新选取并替换补充项目，新结果仍须确认；是否自动启动重选另行确定。

日计划多个游戏共用目标与指导时，引用组内某个游戏须保留该组共用内容和来源，不编造专属指导。“自主游戏”与“自选游戏”为同一类别。

同名游戏保留各日计划来源记录；周计划选取时，同类别同名游戏只占一个名额，由 AI 选择一个具体来源并携带其整组目标与指导，教师可改选其他来源。不跨来源拼接冲突内容；名称相近但不完全相同的游戏先不自动合并。

材料保留生成依据，只存周计划，不回写日计划；提取与补充均进入候选采用及教师确认流程，不把支持策略全文直接当材料。既有映射和例子见[最小实施规格](../specs/manual-plans-and-word-export.md)，须先按本 Contract 检查来源与身份差异。

## 保存、生成与确认

本人日计划保存、删除或班级配置变化后，已关联周计划须保留来源变化信息，不能继续把旧来源表示为最新。确定性字段何时带入、手工录入字段如何保护、是否自动执行 AI 及等待时长在 v2 规格中明确；原云端“保存后 30 秒自动生成”不直接沿用。

分别保存：

- 上一份已确认版本：可导出，不能被自动更新原地改写。
- 当前人工编辑内容：不因新 AI 返回而直接丢失。
- 最新候选结果：附来源版本、配置／提示词版本及来源是否过期的信息。

沿用候选采用边界：教师明确采用重选游戏候选时允许替换人工游戏内容；其他人工修改的 AI 栏目保留，由教师选择替换。主题名称始终由教师决定。AI 返回本身不等于采用，不得直接覆盖教师手工填写的另一位教师信息。

生成期间来源变化，结果不能作为最新内容确认，应处理最新来源。确认时再次检查来源版本及本地数据适用性，避免编辑期间的变化被遗漏。已有确认版本不自动覆盖后续修改。

本地任务仅在程序运行期间执行，不承诺教师退出应用后继续生成；退出、休眠、更新和换机后的恢复规则遵循 ADR 0004，不自动重发结果未知的 AI 请求。

## 状态与导出契约

任务进度、完整性、来源新旧与确认状态分开表达。例如一份周计划可以同时拥有“已确认上一版”和“AI 更新失败”，两者不矛盾。

| 情况 | 已确认的行为 |
| --- | --- |
| 更新等待或生成中 | 可导出上一份已确认版本，导出前提示未包含最新变化 |
| AI 失败 | 保留已有内容，可重试或手工修改；不强制等待成功 |
| 缺项或当前内容未完全更新 | 制作教师可明确确认当前已有内容后导出，记录缺失和未更新之处 |
| 未确认 AI 候选 | 不直接用于导出 |
| 候选基于旧来源 | 不可冒充最新候选确认；允许显式确认不完整内容的规则不取消来源标识 |

确认不完整计划不等于后台任务成功，也不等于内容完整；界面不能用同一状态掩盖区别。任务完成后如何呈现新一轮候选在 UI 规格中明确。

## 非职责

不反向修改日计划，不读取其他教师的 AI 密钥，不通过自动生成决定产品权限，不将导出文档导回为数据权威。不为手工录入另一位教师的栏目新增同班同步要求。

## 实施状态与规格接续

既有[材料实施规格](../specs/weekly-materials-implementation.md)、[协同索引](../specs/ai-capabilities-implementation.md)及旧验收记录保留原身份。与本 Contract 冲突的全班汇总、负责人接管、中央执行及触发规则须先改写，未决栏目来源须先确认，不能直接执行旧规格。

周计划的后续交付时间单独确定，不阻塞当前“每日活动计划完成后做游戏观察记录”的顺序。本次不宣称周计划桌面迁移、材料实现或待验案例通过；后续入口见[Architecture v2 实施入口](../bootstrap/architecture-v2-readiness.md)。
