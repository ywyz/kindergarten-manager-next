### 2. 备份设计必须覆盖的工程问题

- **实际数据清单**：本地教师档案、班级／学期／日历和 AI 非密钥配置、日计划、观察记录、已保存草稿／候选、版本历史、当前指针、基准与来源、确认快照、恢复回执、AI 执行状态，以及被这些记录引用的业务资源。以现有模型为准，不新增未批准业务功能。
- **存储边界**：按实际数据根解析数据库与受管理资源，不能硬编码源码体验路径。现有升级前 `migration-backups` 主要是数据库保护，不能据此宣称照片和全部业务已备份。解释迁移备份是否纳入及理由；不递归打包备份本身。程序文件、更新暂存、运行锁、导出临时文件、照片 staging、缓存和开发环境分别处理，不能整体打包运行目录冒充完整备份。
- **一致性**：为 SQLite 与业务文件确定同一个可恢复边界；可以评估 SQLite 在线备份能力，但不能直接复制运行中的 `.db` 并忽略 WAL。并发保存、照片增加／移除／清理、在途 AI、取消和退出都要有明确方案，不能只证明数据库单独自洽。需要暂停操作时说明范围和时长，不能为了实现方便擅改教师流程。
- **格式与校验**：定义快照 ID、创建时间、应用版本、备份格式版本、数据库 migration revision、资源相对路径及大小／散列等清单；检查数据库完整性／外键、记录关联、历史指针和图片引用。散列用于损坏检测，不替代来源认证或加密。完整成功后才交付最终备份，失败／中断不能遗留一个被当作成功的半包。
- **安全读取**：对外部备份包检查路径穿越、绝对路径、链接／重解析点、重复／冲突路径、条目数／解压体积和不完整文件，校验前不能写入现用业务目录或把包内路径当外部指令执行。安全限制与教师需要的照片容量一并验证，不能用过小限制悄悄缩减既有能力。
- **凭据精确说明**：完整数据库快照可能仍带加密 API 密钥行，不能笼统声称“不备份凭据”。分别说明密文、nonce、数据库身份和独立 DPAPI 主密钥如何处理及验证；若需修改副本中的凭据数据，应明确语义与一致性影响。本轮不读取真实密钥，不做凭据同步或跨机解密承诺。
- **版本兼容**：分清备份格式、数据库 revision、AI 契约历史版本和业务内容版本。未知／过新格式先拒绝，已支持旧格式通过明确迁移路径处理；不能给未知库 stamp、静默降级或把合法历史 AI 内容当损坏删除。

### 3. 恢复设计必须保住当前数据

- 按确认后的产品流程，先在隔离区完整展开、校验并生成预览；明确当前工作未保存、正在生成／保存、取消和关闭时的处理，不能边校验边覆盖现用库。
- 设计数据库、图片及相关指针的成组恢复／切换、必要的独占检查和可恢复的中断处理。磁盘不足、权限失败、文件占用、进程崩溃和迁移失败时，原数据须仍可使用或能明确恢复，不能出现库已替换、照片尚未完成的成功状态。当前数据保护副本的保留和清理规则写明，不暗中删掉唯一可恢复副本。
- 恢复后核对身份、档案、内容、历史、来源和图片，重启后仍可编辑、保存、查历史、导出。备份内已有历史不等于恢复瞬间自动产生新业务版本；是否新增业务记录须遵守已确认契约。
- 保留失败／未知 AI 执行及原因，不从备份自动重放已发送或结果不明的请求。明确历史在途状态恢复后的安全处置，保持人工重试入口和可能重复处理／计费提示；不为证明恢复成功而真实发起 AI 请求。
- 换目录／换机后的原路径不能驱动任意文件读取；DPAPI 不可用时，业务数据仍按规格恢复，AI 显示需重新配置，不静默丢弃业务、不泄露密钥、不自动重发任务。
