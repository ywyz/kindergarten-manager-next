## 产品决定

## 当前执行顺序

### 1. 收口 B1 Git，再固定 B2 共享能力

B1 只限快照／校验后端通过，主分支整合基线仍为 `e836726`。先由原会话将自己的结果记录与独立报告对齐，停写；Codex 核对全部已变／新增文件、隐私、相对链接与批准 blob。再由原会话只暂存批准清单、普通提交并推送当前桌面分支；不 force、不改公开历史、不 tag／Release、不把私有日志／DB／照片／备份／保护材料提交。Codex 复核实际提交、远端及批准清单一致。

随后由原会话在共享快照核心最小增加“**调用者同一维护 lease 下捕获完整保护副本**”的内部能力，先核定签名及职责再编码。核对数据根、owner/token、独占和存续状态；不能重新取 lease、释放调用者 lease 或清掉其他关闭／恢复 owner。保持 B1 普通创建、验证、取消终态与旧包能力；不得复制一套快照引擎。针对该接缝独立验证后，才交辅助恢复核心使用。

### 2. 恢复核心与 Runtime 接续

辅助会话在明确所有权后按[规格 §10](../specs/desktop-backup-restore.md#10-b2-接续设计边界b1-独立通过后实施)实施：

- 预览绑定实际包／隔离结果、快照和操作代次；重复请求幂等，旧预览不能恢复其他内容。
- 同一个维护独占内捕获并重新校验完整保护包；保护失败不得切换。保护包必须能由正常应用入口选择、预览、恢复，不只留开发人员手工拼装材料；放数据／凭据根外的私有位置，不递归入包。
- 保留原 Runtime 的运行锁，只关闭／重开 engine；DB 家族与 `observations/assets` 成组切换，旧 WAL／SHM 不附着新库。journal 记录受管相对组件、身份、hash 和阶段；重命名已发生但日志未写成时仍须按实际完整组确定接续。
- 启动接续在取锁后、迁移／提示词同步／AI／HTTP／UI 之前。未知或混组保留两边并拒绝写入，不猜测成功。真实进程终止与受控落盘故障分列，不冒称真实断电。
- 临时授权、旧 session／launch、config HMAC、预览、导出及迟到回调退役；相同档案／记录 ID 也不能串写。只改变明确的临时授权及安全启动状态，不删业务历史／照片／候选／回执、不制造新内容版本。`recover_on_start` 会写库分类但不发网络。
- 切换前取消能保全旧数据；切换中等待完成或明确回滚，不强退、不报假取消。窗口关闭遵守同一安全边界，不能借普通 stop-and-exit 取消本应等待的 AI。

该会话停写后 Codex 独立核查实际协议、阶段故障、旧请求和重启；共享核心缺陷交回原会话，不并发写同文件。

### 3. 宿主／API／前端与 B3 源码窗口

核心接口明确后，由原会话接原生选文件／保存、设置页、P06 确认后的首次入口、进度／取消／预览确认和保护位置提示。页面只传受限操作 ID，不传任意文件路径、命令、PID 或 URL；大包不走旧 Word Base64／30MiB 桥接通道。

复用既有正文、IME、候选、设置与材料草稿保护。确认 ServiceRun 线程、AI 执行器、旧会话和原生 IO 退役后才改现用组；重建 app/API token、session_scope、launch、页面与关闭代次，不能只刷新 page ticket 或清 UI 缓存。源代码仍只检查更新，不新增下载／安装；维护操作与更新／关闭／保存互斥，不丢弃既存更新材料。

Codex 运行与实际改动相称的回归及独立源码窗口闭环：创建明文／密码备份、坏包／错误密码、校验预览确认、保护副本再恢复、各阶段中断与新进程启动、恢复后编辑保存／历史来源／图片／Word、旧页及旧回调拒绝。复用已验证完整合成夹具，按字段与资源字节对比；不能只数记录或看 200。UI 合成／原生实际点选／教师体验／冻结入口各自记证据，不互相替代。
