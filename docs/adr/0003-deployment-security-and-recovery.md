# ADR 0003 单机部署、安全与恢复

状态：已接受。环境观察及尚未验证的指标不构成部署成功事实。

## 部署决策

部署目标为 `ssh aliyun` 对应服务器。与现有应用共存，使用独立应用目录、数据目录和内部端口，复用现有 Caddy 的 HTTPS 与反向代理。Caddy 提供前端构建产物，API 监听本机内部端口。

使用 systemd 管理一个 FastAPI 服务进程、一个独立 Python 工作进程和定时备份。已有 Docker 环境不是要求本项目容器化的依据。现有 MySQL 实例复用与否按 ADR 0001 核查。

## 容量目标

约 30 人同时在线编辑、保存，并允许同时提交 AI 任务。AI 可以排队并显示状态，不要求 30 个请求同时执行。需验证与既有应用共存时的响应、内存、数据库锁等待和 Word 导出占用，不能从服务器规格推定达标。

## 密钥与调用边界

- 教师分别配置 AI API 地址、模型和密钥；不使用全园统一密钥替代已确认流程。
- 密钥加密存储，应用解密密钥与数据库分开保管。页面不回显完整密钥，管理员无查看入口。
- 后台仅在获授权任务中解密使用；认证头和密钥不得进入日志或错误回显。
- 产品权限隔离不能保证对服务器最高权限控制者保密。
- 自定义 API 地址仅允许公网 HTTPS。校验实际目标及重定向，阻止本机、内网和云元数据地址访问；具体 DNS 与连接校验实现在安全规格中明确。
- 记录任务实际使用的配置与提示词版本，但不把明文密钥当作版本记录。

## 日志决策

记录操作者、对象、变更版本、调用状态、耗时和脱敏错误。管理员可查询。日志默认不重复保存完整教案、提示词、模型回复或认证头；必要的内容版本和候选由业务模块保存。

日志保存期限、详细错误访问范围和凭证轮换清理策略仍是实施细节，不在本 ADR 中假定。

## 备份与恢复决策

每日自动生成一致性备份，加密后上传独立 S3 存储，保留最近 30 天；WebDAV 暂作备用，不要求首版实现双目的地同步。备份覆盖数据库、固定模板及恢复所需配置和密钥材料；备份解密所需的恢复密钥另行保管，不能只留在应用服务器。

MySQL / InnoDB 可采用事务一致性逻辑导出作为首版方案，执行时避开 schema 变更；角色、账号权限、配置和模板的恢复需求须明确，不能认为业务库导出已经包含一切。

目标为最多丢失最近 24 小时数据，具备在一个工作日内恢复服务的流程。须验证上传完整性、解密、数据库还原、应用配置及个人密钥可用性。自动备份失败须可见；仅每日定时触发或已安装云备份客户端不证明目标达成。

## 非授权边界

此决策不授权修改 Caddy、安装服务、创建数据库、读取旧业务内容、开通云服务、提交凭证或部署应用。具体部署操作须属于后续明确任务。
