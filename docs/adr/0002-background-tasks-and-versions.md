# ADR 0002 持久任务与周计划版本处理

状态：已接受，依据本次会话逐项确认的更新、重试、交接和部署规则。

## 背景

日计划改变会影响全班周计划；创建教师可能离线，AI 请求可能缓慢、失败或结果不明。教师仍需保存编辑、保留人工修改和导出已有内容。仅把任务放在请求进程内存中不能满足已经确认的重启恢复规则。

## 决策

单 FastAPI 服务进程处理交互，独立 Python 工作进程执行 MySQL 中的持久任务。两者属于同一项目；不新增 Redis、Celery 或消息中间件。systemd 管理进程。

日计划保存和登记受影响周计划更新任务在同一事务提交。周计划立即显示待更新，确定性字段进入待确认内容；AI 等到最后一次相关保存后 30 秒再执行。立即更新可以跳过等待，但不跳过队列和权限检查。

待执行任务合并到最新来源。任务执行记录来源版本、负责人、AI 配置和提示词版本。执行前检查有效账号、班级关系、维护责任及提示词适配状态。AI 调用在数据库事务之外执行。

运行中的任务使用启动时配置；尚未运行的任务使用最新有效配置。配置或提示词更改本身不触发已确认计划重新生成。具体密钥版本临时留存和轮换清理方法属于待定实施细节，不将密钥复制到日志。

## 版本契约

- 分别保留上一份已确认版本、当前人工编辑内容和最新候选。
- 新候选不直接覆盖当前编辑；采用游戏候选时允许覆盖人工游戏内容，其余人工修改由负责人选择是否替换。
- 主题名称由教师维护，AI 建议不能自动覆盖。
- 结果写入与确认检查来源版本。过期结果不能冒充最新结果确认，也不能覆盖较新内容。
- 明确确认当前不完整内容后允许导出，记录缺失和未更新之处；这不是把过期候选标为最新。
- 已确认版本不是原地被改写的可变视图；管理员修改也产生待确认内容，负责人负责确认。

任务执行状态、内容完整性、来源是否最新、是否已确认是不同维度。AI 失败不等于已确认版本不可导出；内容缺项不等于必须等待 AI。不得用单一“成功/失败”字段抹平这些业务差异。

## 中断与失败

- 鉴权、额度和配置错误暂停并提示处理。
- 明确可重试的临时失败有限重试；次数、间隔在实施规格中确定。
- 已发送但结果不明的超时、中断或进程重启不自动重发，提示负责人手动重试及可能重复计费。
- 重启恢复未开始任务，运行中任务按是否可能已发出请求处理；不能简单将所有运行中任务恢复为待执行。
- 来源再次变化时处理最新版本，旧结果不作为最新候选采用。
- 负责人调班、停用后暂停调用；完成接管接受后使用接管者配置恢复。

## 后果与待验证

任务持久化并不自动提供“恰好一次”外部调用保证。须验证任务领取、进程中断、重复触发、版本竞争和权限改变场景。数据库可实现短事务领取，但领取超时、执行标识及防重复写入的具体设计尚待实施规格确认。

一个工作进程可有受控的调用并发；具体上限根据服务器和供应商条件验证。此 ADR 不引入微服务边界。
