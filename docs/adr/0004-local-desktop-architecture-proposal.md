# ADR 0004 教师本地应用架构

状态：已接受，2026-10-08。用户在审阅推荐后明确回复“同意该推荐内容”。本 ADR 确认 Windows 本地应用、Vue／TypeScript＋Python、SQLite、WebDAV 与数据库业务历史方向，并确定每日活动计划之后做游戏观察记录。pywebview＋WebView2 为优先验证的桌面窗口方案，PyInstaller 为打包候选；具体发行方案仍须实测。

本 ADR 替代 ADR 0001 的 MySQL 部署选择、ADR 0002 的云端执行与 MySQL 任务传递方式，以及 ADR 0003 的中央服务器部署、多人容量和 S3 首选备份方案。未冲突的业务版本、人工确认、失败保护与日志脱敏原则继续有效。架构确认不表示代码已迁移，也不授权业务实现、安装依赖、远程操作或部署。

## 背景与目标

产品面向教师个人在电脑上备课和整理教育工作内容，后续按模块扩展。用户报告旧云端系统 AI 调用慢、存在超时，而使用相近供应商、模型和教案的电脑直连体验较好。该观察支持验证本地执行，但尚不能证明历史故障根因或承诺本地调用不再超时。

本轮先确认架构与语言，以每日活动计划为首个完整交付模块，完成后再做游戏观察记录。拍照点名属于后期扩展，不作为当前选型必须先完成的原型。

## 用户已明确的产品取舍

- 首发只支持 Windows，其他操作系统后续考虑；不需要手机编辑。不同电脑接续使用，不要求同时编辑。2026-10-08 补充确认：先保证 Windows 11，Windows 10 后续验证。
- 2026-10-08 补充确认：一个本地教师档案，首次填写姓名、班级和学期，之后直接进入工作台；无需旧注册、账号密码登录或等待管理员分班。用户说明目前云端没有数据，首版不安排旧业务数据导入，使用全新本地数据；不据此清理远程资源。
- 周计划中的游戏只参考制作教师自己的日计划与班级配置。另一位教师的集体活动名称、晨间谈话主题由制作者输入；同班查看不再需要。
- 不需要园所管理员集中管理业务。WebDAV 用于跨设备读取与自动保存、备份；遥测与软件更新用于了解软件情况和修复问题，具体范围另定。
- 后续功能包括游戏观察记录、一对一倾听、班级人数管理、因病缺勤统计、退费表格制作等。当前只确定每日活动计划之后做游戏观察记录，其余功能不在本轮启动。
- 首版沿用数据库业务版本模型，Git 保留为后续候选；保留 Vue 界面，不以 Qt 重写现有 UI。

周计划其他 AI 栏目的完整输入依据、周计划的后续交付时间，以及观察记录的具体字段与流程，分别在对应规格中确认；不从旧仓库继承为新需求。

## 语言与技术决策

| 层 | 已接受的方向 | 选择理由与验证边界 |
| --- | --- | --- |
| 界面 | Vue 3、TypeScript、Vite、Element Plus | 沿用现有页面与组件，用于计划、记录、配置和统计界面 |
| 本地业务 | Python，保留 FastAPI 服务边界 | 复用 AI、业务规则、数据访问和 Word 导出代码，保持界面与业务分离 |
| 界面通信 | 本机 HTTP API，尽量保留现有 `/api` 契约 | Vue 与本地服务同源加载；适配个人使用语义，不能承诺现有鉴权、权限和所有接口原样保留 |
| 数据访问 | SQLAlchemy 2.x、Alembic | 继续用显式模型与迁移管理数据结构，重新验证目标数据库兼容性 |
| 本地数据库 | SQLite，替代桌面版的 MySQL 服务 | 适应本机、低写入并发、无需教师维护数据库服务的条件；现有 MySQL 模型与迁移须审查适配，不宣称只改连接串即可迁移 |
| 桌面窗口 | 优先验证 pywebview＋WebView2 | 在 Windows 上使用现有 Vue 构建产物和本地 Python 服务；其他系统不在首发支持范围 |
| 应用打包 | PyInstaller 候选 | 与桌面容器一起验证安装、启动、文件导出、退出及升级；不是已完成的发行方案 |
| 跨设备与备份 | WebDAV，应用管理版本快照与恢复 | 本地保存与网络同步分开，远端不承担日常业务计算 |
| 历史版本 | 延续数据库业务版本模型 | 补历史查阅与恢复；首版不引入 Git 作为业务历史存储，保留后续评估可能 |

Qt/PySide/PyQt 保留为评估过的替代路线。当前模块未呈现足以抵消界面重写成本的桌面集成需求；未来增加本地识别能力时，可先放在独立 Python 业务模块中评估，不预先安装视觉模型或设备 SDK。

## 运行与数据边界

```text
桌面窗口中的 Vue 界面
        │ 本机 API
本地 Python 业务程序 ── 教师配置的 AI 服务
        │
本地数据库与文件
        │ 版本快照与接续检查
WebDAV
```

运行中的业务数据保存在本机。WebDAV 保存用于接续和恢复的副本；应用只有在验证远端版本、本地修改和兼容性后才能切换本地数据。具体同步协议在实施规格中设计。

AI 请求从教师电脑发出，密钥由本地 Python 使用。界面显示执行状态并允许继续正常编辑，网络调用不得占用长数据库事务。采用候选、保留人工修改、保存原始拆分基准和 Word 比对规则继续作为复用审查依据。

不再依赖集中管理与同班共享；本地单档案初始化后直达工作台的入口已确认，内部身份标识、配置字段与初始化实现按规格细化。服务只监听本机回环地址，并校验本次应用会话与请求来源；不能通过不受信任网页任意调用。

本地任务只在程序运行期间执行。关闭窗口、退出程序、休眠、更新前的任务处理须明确；记录任务状态不能保证恢复供应商端正在执行的请求。已发送而结果不明的任务不自动重发；换电脑或恢复备份也不能自动重放旧任务。

## 同步与维护原则

1. 本地保存成功后再后台同步，分别显示本地保存与同步状态。不同电脑轮流使用仍可能留下离线旧副本；检测远端变化，保留冲突内容，不直接以最后上传覆盖。
2. 先生成一致性快照再上传，避免直接双向同步正在使用的数据库目录。同步最新数据与保留历史备份分别设计，并验证换机恢复。
3. API 密钥、WebDAV 凭据与普通业务内容分别处理。若使用本机绑定加密，另一台电脑重新配置凭据；如需同步密钥，另行设计可恢复的加密方案，不能复制密文就声称跨机可用。
4. 遥测由使用者选择开启，仅包含版本、耗时、错误码等软件运行信息，不包含教案正文、儿童资料、照片、密钥或收费明细。收集项和保留范围须具体定义。
5. 更新机制须校验发行来源和软件包，迁移前保留可恢复数据，并检查两台电脑的数据格式兼容性。旧程序不得覆盖它不能识别的新格式数据。更新或遥测服务不可用不影响本地手工功能。

以上为已接受的工程边界；同步协议、遥测平台和自动更新组件仍需具体规格，未选定或安装。

## 交付顺序与复用审查

### 第一阶段 每日活动计划

由 OpenCode 先列出实际改造文件、迁移、依赖与验证方案，再按具体授权实施。完整能力范围为：本地配置、日期与日历、教案拆分、适龄调整、其他活动生成、人工编辑与保存、原文比较、Word 导出，以及异常情况下保留已有内容；具体验收案例与切片分工另行细化。

桌面安装、数据持久化和跨设备接续作为应用基础配套分片验证；WebDAV、更新与遥测各自的交付时间需在实施计划中明确，不把所有后续能力塞进首个编码切片。

现有 I1–I5、AI 1A–1C 的实现与验收是对应旧架构和版本的证据，不自动等同本地版已通过。现有 AI transport 与持久执行尚未实现的状态继续保留。Word/WPS 的实际下载与版式验收仍需覆盖新交付形态；旧链路的待验项目不因方向调整被标记为通过。

### 第二阶段 游戏观察记录

每日活动计划达到约定完成标准后，再确认游戏观察记录的字段、图片与 AI 使用方式、编辑保存和导出要求，并实施该模块。复用经验证的本地运行、配置、任务、保存与导出基础能力。

### 后续阶段

一对一倾听、人数管理、因病缺勤、退费表格、周计划后续能力和拍照点名分别形成规格与授权。拍照点名不阻塞当前每日活动计划，不启动相关模型选型或原型实现。

- 单档案入口已确认；内部身份与班级配置、窗口退出及任务恢复、WebDAV 同步与恢复凭证、遥测与更新的具体协议仍需实施规格。
- 每日活动计划的详细验收案例，以及安装、同步、更新等基础配套的分片交付顺序仍需实施计划。
