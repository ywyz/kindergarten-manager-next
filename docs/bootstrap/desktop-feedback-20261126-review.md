# 2026-11-26 教师测试反馈复验

修复基于 `dev/0.1` 的 `79d9fa2`，分支为 `fix/desktop-feedback-20261126`。OpenCode 使用 GLM-5.3 处理备份、更新和待办，Command Code 使用 GLM-5.3 Flash 处理日计划、管理站和图标。OpenCode 达到用量上限后，用户指定原 Command Code 会话继续修复 WebDAV 和 Nextcloud。Codex 在 Windows 11、CPython 3.14.10 x64、独立数据库和合成档案上复验。

## 日计划

- Edge 中从工作台月历打开空白日期，首个操作显示「填入原教案」。填回后文字切换为「拆分教案并修改」。第一轮点击「生成其他活动内容」仅打开栏目选择器。退回后，单击会提交一次包含全部四栏的任务，未指定单个栏目。
- 首次将候选原样填入空白晨谈并保存，初版仍误报生成输入变化。修正后，对初始为空和初始已有正文两种情况分别验证了读取候选、预览与实际采用。另行编辑晨谈后，旧候选按预期转为只读。验证使用合成 AI 候选。
- 完整活动缺少实施材料时，点击反思入口打开材料编辑器。填写后再次点击，Edge 记录到恰好一次反思任务请求。留空当天活动时入口保持禁用。
- 在首次打开的拆分候选中，活动目标、准备、重点和难点原来各显示 2 行，实测高度 52 像素。回修后的前端连接既有合成候选，在同一 Edge 显示条件下各显示 6 行、高 136 像素。

使用本轮前后端再次通过空白计划、四栏生成、实施材料、反思及首次拆分结果的 Edge 验收。日计划、定向修改和候选采用的后端回归通过 257 项测试及 129 个子测试。

## 备份与恢复

在隔离的 HTTPS WebDAV 服务上，使用相同的加密备份、正确密码和带照片的样本。较短的目标档案路径能完成恢复。延长合法目标路径后，原版和第一版修复均在确认预览前报校验失败。调用记录显示 Windows 在解包时创建受保护的资源目录返回 206，应用将这次文件系统错误显示成备份包无效。教师原机的报告仅附带更新检查成功事件，无法据此确认原机是否遇到了同一原因。

第一轮桌面反馈预览过滤了恢复事件。退回修正后，Edge 显示了「WebDAV 恢复 · 失败 · `RESTORE_PASSWORD_INVALID`」。从该窗口提交合成反馈，收到独立协作服务的回执，并在 MySQL 中查到同一固定事件。附带诊断只含操作、时间、结果与错误码。

使用 11 月 24 日版本生成的同一加密备份继续复验。长路径下，修正受保护目录创建后，先后定位到图片打开、图片身份复核及准备目录中的文件身份复核仍使用受长度限制的路径。修复后，该旧包在同一长目标目录完成预检、准备、安装与重开。新库版本为 0023，保留恢复前保护副本。逐行核对教师、日计划、周计划和观察记录，并核对受管照片指纹，均与旧档案一致。

隔离 HTTPS 服务另行覆盖了上传、列出远端版本、下载、口令重试、恢复确认及重开。已有档案和空档案分别接收带照片的加密备份，长路径复验通过。选择不设独立密码后，备份直接进入预检，两个目标均恢复成功。通过同一 WebDAV 入口读回 11 月 24 日的加密包，比对 39 张原有业务表，并核对受管文件，均与旧档案相符。

独立的 Edge 界面验收向真实 Vue 面板送入原故障回执，修复前同一句「当前档案未更改」实际显示两次，修复后显示一次。需要重启核对时，界面表明结果尚未确定。

对实际恢复安装结果分别注入磁盘不可用和维护忙。桌面保留 `RESTORE_STORAGE_UNAVAILABLE` 或 `RESTORE_BUSY`，给出对应处理办法，并标明当前档案未更改。另在 285 个 UTF-16 码元、含中文、空格和特殊字符的 Windows 路径核对 SQLite 只读打开方式。校验能读回已有记录、拒绝写入；缺失文件不会在校验时被创建。按照该方式再验，加密、免密码、长目录、旧包四个 WebDAV 场景均通过。

## Nextcloud 待办

在独立的 Nextcloud 32.0.15.1 中创建合成账户和任务清单，通过带证书校验的 HTTPS 连接。首版将任务能力属性放在错误的 XML 命名空间，真实任务清单因此显示为不支持待办。回修后，桌面 CalDAV 客户端能识别该清单，读回另一客户端写入的任务，创建新任务，并用原 ETag 更新标题、截止日期和完成状态。

进一步通过桌面本地 API 进行双向新增、编辑和完成。另一端已有的备注、优先级和精确到时分的截止时间均保留。两端都修改同一任务时显示冲突，两份内容各自保留。单端删除未传播，停用后操作工作台待办及点击立即同步均未产生 CalDAV 请求。Edge 从设置页连接、选择真实清单，工作台显示远端待办；停止并清除本机密码后，设置页重新显示登录表单。

在真实 Nextcloud 接受新增请求后，验收程序丢弃该请求的回执。初版重试时本机出现了两条待办。回修后，同一场景反复同步，远端和本机各保留一条，本机待办编号保持一致。将开启联动的档案恢复到已连接另一账户的电脑时，重新打开的档案保留个人待办，同步处于关闭状态。设置不会列出另一账户的清单，立即同步和新增本地待办均未向 Nextcloud 发出请求。

在同一 Nextcloud 上为两个账户分别创建标识相同、标题不同的任务。从甲账户切换到乙账户再切回甲，两条本地待办保留各自编号和标题，远端两个清单各保留自己的任务。连接时输错新密码，也保留原先可用的连接。另以两个模拟服务端提供完全相同的用户名、清单路径和任务标识，同样验证了往返切换，两端均未收到跨账户写入。

并发复验刻意延迟了旧账户的清单响应。在新账户已确认、新待办已经写入工作台之后，旧响应返回，首版实现仍向旧清单写入了新待办。回修后，旧操作停止，新待办只出现在刚选定的账户。同时执行工作台自动同步和手动「立即同步」，同一条新远端任务只导入一次。

若一次新增的回执丢失，两端又分别修改了标题，无法判定哪一方更新。连续两次同步均报告冲突，保留各自标题和本机编号。若内容仍相同，重试只恢复关联，本地版本号保持原值。

## 阿里云管理站

在单独的 MySQL 8.4.11 中从第 8 次迁移开始，先写入合成园所、班级、教师、成员、令牌与反馈，再应用第 9 次迁移。逐表比较 21 张表原有各列，记录完全一致。三张实体表的新停用时间列均可为空，已有对象保持可用。

Edge 通过管理页登录并执行三类空对象删除、归档取消和归档确认。确认后从列表隐藏，数据库保留历史成员关系。最初归档班级仍显示为教师的当前班级，退回后该入口返回未选班，教师可改选有效班级。管理页也能显示合成反馈所附的中文恢复事件及错误码。

继续用两个合成成员、已登记升班状态和有效学期检查停用班级，发现搭班、升班和共享周计划仍可读取，停用园所仍可按 ID 列出班级。回修后，同一组入口均已关闭，教师仍可改选其他有效班级。通过正式新建班级操作生成的空班级也可彻底删除。协作套件通过 171 项测试及 63 个子测试。服务端修复提交为 `8adbc1cb35fabde0047a764e2050daeb5026d575`。

北京时间 11 月 26 日 21:53 已部署至现有管理站。初次备份因命令行客户端的默认数据库选项与导出工具不兼容而退出，发生在数据库变更前。调整导出工具读取的参数后，完整备份的 SHA-256 与 gzip 校验通过，服务器上的备份权限为 `0600`。随后执行三条增量语句并重启服务。公网健康接口返回 200，管理页与提交内容的 SHA-256 一致，匿名读取后台反馈返回 401。现网验收使用只读请求。[管理站](https://manager-next.ywyz.tech/admin)
