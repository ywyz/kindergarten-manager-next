## 2. V1（P1）：同字段双份真实编辑在"保留修改"时丢一份

反例序列（复审给出，本轮按实际动作完整驱动）：待适配 → openAdapt → f1 输入适配草稿 A → 真实 cancelAdapt 关闭保留 → 普通 f1 输入不同草稿 B → saveNormal 真实 409 → companion GET 停放已适配 current/based=latest 完整 map → keepEditsNewBaseline。修复前该轮 keep 分支先取普通文字 B、随后清空 adaptDraft/target 且 removed 不含同名 A，A 被静默删除，提示却称适配文字已移入普通面。

代码（`PromptGuidanceCard.vue`）：

1. `keepEditsNewBaseline`：同字段同时存在两份真实编辑（编辑器文字 ≠ 旧基线、且 `splitAdaptDraft` 的 keep 仍含该字段文字、且两份内容不同）时，不再按普通优先后删另一份：
   - 普通编辑面的文字原样留在编辑器（该面自己的真实工作，走既有"保存修改／放弃修改"入口）；
   - 另一份适配文字进入既有只读参考区（`adaptRemovedDraft`，迁出待适配块的"未提交的适配草稿文字"行），始终可见、可查阅；
   - 处置入口全部为既有动作："放弃适配草稿"显式删除；任务仍待适配时，普通面清理后重新 openAdapt 会让该文字经既有 `splitAdaptDraft` 机制重新回到适配编辑面（可提交或放弃）；内容在两处相同时视为同一份文字，只保留编辑器一份，不制造重复行。
   - 不自动合并、不先删再提示；提示按是否存在未合并文字区分且如实描述去向。
2. 参考区模板两处真实化：标题由"以下字段已不在最新契约中…"改为同时如实说明两类行（"已保存原文"来自已不在最新契约中的字段；其余为未提交的适配草稿文字），避免对同名保留行作出不实陈述；"放弃适配草稿"入口的显隐条件从"状态非待适配"改为"存在未提交适配草稿行"——保证仍待适配且面板关闭、以及远端已适配两种状态下，保留文字都有直接可达的既有显式处置入口。

未触碰的既有正确语义（回归确认保持）：adoptLatest 明示放弃路径仍完整清理 target/open/draft/removed；纯预填不转为"工作"；同字段相同文字只保留一份；仅单面 dirty 走既有分支（普通改文字面 verbatim 保留、仅适配文字迁普通面）；U3 收缩契约移除文字路径；U1/U2 全部行为。

## 7. 决定点（供复审确认，未自行新增选择流程）

本轮在既有可见草稿／只读参考／显式保存与放弃语义内解决，未新增产品选择流程；以下为遗留的具体决定点，等待产品确认后才有后续实现：

1. **同名双文字的"换向"能力**：被保留在参考区的适配文字只读。仍待适配时可经"重新打开适配"让它回到可编辑面（既有机制）；远端已适配后该文字只能查阅或显式放弃——若产品希望提供"把参考区文字一键换入普通编辑面（替换当前修改）"这类动作，须先给出产品决定，本轮未实现。
2. **参考区行标签复用**：同名未合并文字与被移除字段草稿共用"未提交的适配草稿文字"行标签与同一只读区（本为收缩契约设立的既有区域）。标题已按两类行如实改写；是否需要为同名保留行单独的呈现/文案，属产品呈现决定，本轮沿用单区。
