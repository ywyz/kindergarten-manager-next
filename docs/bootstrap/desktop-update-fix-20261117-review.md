## 第一轮审核记录

已确认首失败发生在程序替换之前：发布 ZIP 在实际验证目录解出前 316 项，第 317 项许可证完整路径为 270 个 UTF-16 单元；验证目录前缀为 126 单元（不含包顶层 `KindergartenManager`）。独立合成复现与首失败一致，原现场指纹未变。

初版前端在检查接口抛异常时补读本地状态，但生产桥接也可能返回普通错误对象，导致首启没有历史摘要。已退 B 补充独立本地读取及普通错误／延迟检查用例。

许可路径初审要求区分文件与目录上限，并严格区分 126 单元验证前缀与安装根长度。Windows 的传统目录创建约束还要求保留短文件名空间，见[微软路径长度说明](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation)。真实旧路径回归不能用遗漏许可目录前缀的测试代替。

初始 100 单元安装根只是本轮工程验证假设，并非已承诺的产品范围。完整文件清单显示，排除未使用的 `lxml.isoschematron` 后，既有迁移文件仍达 260 单元、一个保留的许可父目录达 249 单元。Codex 以本机 CPython 3.14.10、`LongPathsEnabled=0` 独立创建合成目录，247 单元成功、248 单元及以上返回 `WinError 206`。因此最终完整树门槛采用安装根 98 单元、文件 `<260`、目录 `<248`，不为达到假设预算而重命名迁移或删减必要运行资源；100 单元失败边界保留。实际默认根 70 单元、计划合成受管根 93 单元均在门槛内，超过 98 单元的自定义根不宣称通过。C 继续据此修正门槛及测试。

前端第三轮独立复核：使用锁定的 Vue 3.5.45／TypeScript 依赖，将原测试仅调整三个依赖解析路径及源码目录，原断言和真实 SFC 源码不改，36 项通过。普通失败对象、延迟检查、显式清除、同计划去重、卸载及新操作覆盖旧请求均有覆盖；这仍是自动组件验证，不是原生界面或教师实际验收。
