开发以 Windows 11 原生环境为主，OpenCode 在 Windows 本机运行，VS Code／终端作为开发入口，桌面 Codex 负责协调。WSL 可作独立辅助，不共用虚拟环境、依赖目录或运行中的数据库。OpenCode 唯一写入实现、测试、迁移和构建脚本，Codex 负责技术核查、规划设计、文档、审阅、相关验证与 Git／发布管理。

周计划游戏参考制作教师自己的日计划与班级配置，另一位教师的集体活动名称、晨间谈话主题由制作者输入；不要求同班查看或园所管理员集中管理。周计划其他栏目的输入依据与交付时间仍需对应规格确认。拍照点名属于后期扩展，本轮不进行模型选型或原型；一对一倾听、人数管理、因病缺勤、退费表格等不自动进入当前实现范围。

## 实施准备顺序

1. **文档适配与限定复用审查已交付。** 已依据 ADR 0004 标明 v1 规格适用范围；D0 技术验证规格见 [桌面首片与后续顺序](../specs/desktop-foundation-plan.md)。继续使用 `codex/desktop-v2-foundation`，不将限定审查当作完整代码审计。
2. **D0 第三轮工程复审通过。** [独立审阅 §7](desktop-d0-review.md)确认 R1–R10 关闭、92 项测试通过；最新最终包仓外三进程、普通关闭／重启、原生保存／取消／占用失败后重试及 Word 两页查看已有证据。记录一项非阻塞 watchdog 极端挂起限制；保留干净机器、Win10、WPS、其他 DPI 和用户本人体验未验，不扩大为发行完成。旧包系统策略拦截保留历史身份。
3. **D1A及原R1–R17当前开发机工程通过；R18代码、新包与页面验收通过，已关闭。** [第八轮审阅§17](desktop-d1-review.md#17-d1b-第八轮修复复审与工程收口2026-10-17)历史保持；[R18复审§20.6](desktop-d1-review.md#206-用户逐页验收与r18关闭2026-10-17)记录用户长园所2页、合并7页逐页反馈与关闭依据；[体验结果§20](desktop-d1-result.md#20-d1-教师流程与实际-ime-体验2026-10-17)的用户读回／v4／微软拼音仍有效。[最新收口§20.8](desktop-d1-result.md#208-t6-b核对与本轮教师体验收口2026-10-17)记录T6-A／T6-B／T7通过、配置v4与新旧单日文件核对；微软拼音按用户明确反馈正常，不再复验或穷举输入法。本轮教师体验收口，[当前任务](../tasks/current.md)转为D2需求收敛；[D2草案](../specs/desktop-ai-daily-plan.md)已记录Q1–Q6确认、Q7可配置OpenAI兼容及OpenCode工作包，[E1–E5工程规格及实施清单](../specs/desktop-ai-engineering.md)已完成；W1对应子项已通过；W2已通过当前Windows 11工程核查，完整D2仍待验。不启动AI调用、D3历史／WebDAV／发行或远程操作。
4. **按任务范围执行并审阅。** OpenCode 实施后，Codex 对实际差异、自动检查与产品证据分别审阅；架构接受不自动启动真实 AI 调用或远程作业。任务完成后更新同一提示词，不另增多轮交接文件。
5. **每日活动计划达到完成标准后再做游戏观察记录。** 观察记录先确认字段、图片与 AI 使用方式、编辑保存和导出要求，再实施；不从旧仓库自动继承需求。

每日活动计划的已确定完整范围包括：本地配置、日期与日历、教案拆分、适龄调整、其他活动生成、人工编辑保存、原文比较、Word 导出，以及异常情况下保留已有内容。具体验收案例和首片边界仍需细化。
