## 准备步骤与现场门槛

1. 授权后只作本任务所需远程检查：上述对象是否存在、端口、MySQL 版本／权限模式、实际 current／源哈希、DNS／证书与 Caddy 对应段。记录实际值，不把历史部署记录当当前事实；不重新做全面环境审计。
2. 建新账号、目录、精确库及本库账号。MySQL 下划线权限必须按服务器 partial_revokes 模式正确处理并实际 SHOW GRANTS 核验，不能照搬本机转义形式。复制完整源及已安装环境、核对依赖版本与锁；不升级或安装。独立进程、同源 Secure／HttpOnly cookie，无跨子域 Domain。
3. 核对原库仍只有合成数据，取得一致性快照，只导入精确临时库；先核对 SQL 无跨库 USE／DDL。若发现真实数据，停止复制，返回最小合成种子方案，不擅自脱敏复制。SQL、密码哈希、密文均在私密目录。只在临时库清会话与恢复令牌，不写原库。
4. 使用独立 K_good 和私密配置启动临时 API。核对内部／公网 health、实际登录、权限、七个 v1 契约及默认、静态产物哈希和 cookie 隔离；临时账号身份及密码由既有私密渠道交接。教师 head 初始状态现场核对，不删除已有个人历史伪造初始。
5. 形成 B_contract（v1 基线）备份，停临时 API，实际还原到同一临时库并清临时会话、重启、核验恢复。证据归档含源、工具、私密配置与备份哈希、恢复实际结果。此清单允许该可丢弃库的备份／恢复，不允许恢复或清理原库。
6. 交 Windows 实际 URL、账号私密位置、现场基线和源／工具身份；此时保持正常主密钥与 v1。验收报告明确“远程准备完成”和“场景未补验”分别登记。
