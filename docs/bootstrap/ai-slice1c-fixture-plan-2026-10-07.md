## 2. 独立远程环境

建议在既有服务器复用 MySQL 8.4、Caddy、systemd 和已安装 Python 环境。仅用于验收，单独的 API 进程不是系统架构新增组件；不启动 worker。

| 项目 | 拟定值／约束 |
| --- | --- |
| HTTPS | `https://kg-next-ai-fixture.ywyz.tech`；执行前实测 DNS／证书，不把历史泛域名记录当作当前可用证据 |
| 目录／服务 | `/opt/kindergarten-manager-next-ai-fixture`／`kg-next-ai-fixture-api.service`，独立运行账号及环境文件 |
| API | 拟 `127.0.0.1:18091`，先确认未占用；如变更须同步清单，不能抢占端口 |
| MySQL | 既有 `127.0.0.1:13386`，**只写 `kg_next_ai1c_fixture`**，独立本库应用 DML 账号与准备账号，不复用原库写权限 |
| 原实例 | `kg_next_i5_acceptance`、`kg-next-i5-api.service`、18090、原 current／app.env 均保留；禁止向其发布 v2/v3 或切换密钥 |
| 运行源 | 复用经复审的 1A–1C 实际运行文件与完整 dist；核对部署源清单和逐文件哈希，工具另列哈希，不仅以文档 HEAD 代替 |
| Origin／cookie | 独立 HTTPS 同源、Secure／HttpOnly；检查 cookie 没有跨子域 Domain，测试登录不能撤销原实例会话 |

准备数据优先使用当前验收库的**一致性合成数据快照**，仅在专项授权后复制到精确临时库。先确认仍仅含合成数据；若出现真实数据，停止复制并重做最小合成种子方案。SQL 原件、密码哈希、配置密文均属私密，不进入 Git。复制工具须先核对快照无跨库 USE／DDL，不能让 dump 内原库名称覆盖目标保护。

复制完成后，仅在临时库清除会话及账号恢复令牌（先核实实际表；不写原库），防止继承登录；保留合成账号身份、业务数据及不可变版本。登录仍需原交接密码；只在私密渠道传递。本轮不需要修改原实例密码。

契约案例优先用仅登录读取过的待分配合成教师 tfr_i5，同账号两页即可，不需要班级权限。先核验其 personal head 尚未初始化；若现场状态不符，不能删除个人历史冒充初始，应改用经授权通过既有注册流程建立的临时合成教师并更新私密交接。C7 手工日周定向回归用临时库中的 tow_i5；账号选择和版本均以现场为准。

临时实例使用新生成的独立正常主密钥 K_good，不复制原实例主密钥。被选配置账号在临时 UI 清除旧密钥后保存新合成密钥，使当前版本确实由 K_good 加密；历史密文不被重写，不测试历史执行解析。开始 C7 前建立“有合成密钥”的基线备份 B_crypto（包含配套私密配置）。契约场景开始前另建立当前契约全为 v1 的基线 B_contract。必须实际把备份还原到临时库并核验一次，备份有哈希不等于已经会恢复。

## 3. 固定契约发布配方

仅针对 `daily_lesson_split`；v1 应实读并匹配以下六字段，否则拒绝。保持 input_vars 和 output_schema 原样；这是指导字段适配夹具，不声称改变候选输出或真实 AI 能力。

| 契约 | guidance_fields（固定顺序） | 目的 |
| --- | --- | --- |
| v1 | theme、objectives、preparation、key_points、difficult_points、process | 原基线 |
| v2 | theme、objectives、key_points、difficult_points、process、acceptance_support | 同名保留、移除 preparation、增加 acceptance_support |
| v3 | theme、objectives、key_points、difficult_points、acceptance_support | 再移除已编辑的 process，用于收缩契约 |

每版默认 map 必须与字段集完全一致；文字使用公开无价值合成标记，例如 `AI1C-FIXTURE-v2-theme`。发布先取 v1 锚点 FOR UPDATE，再锁内读取最新 contract／全任务最新 default revision，校验调用者提供的 expected contract／default，原子追加一份 contract 与完整匹配 default，默认 revision 取该任务全历史 MAX+1。系统发布 created_by=NULL，使用既有合法 ID 和 UTC 时间；不伪造管理员文字编辑事件。

只接受 v1→v2 或 v2→v3。重复、旧 expected、字段偏差、半份发布均拒绝且零增量；不覆写历史，不删除旧个人版本，不主动推进个人 head／适配缓存。记录私密发布 manifest（阶段、时间、目标身份、版本、字段名、产物哈希），不得记录指导正文、账号凭证或 DSN。通用 schema 编辑器、产品 API、registry mutation 都不在范围。

工具本身不提供 reset／drop／truncate／rollback。各子例需要恢复时：Windows 先退出并关闭自建页面，托管者停临时 API，归档该例证据，恢复 **临时库** B_contract，清临时会话，再重启及核验。新页面重新登录，不把之前页面的旧个人 revision 带进新场景。此恢复仅用于可丢弃夹具，不是产品回退机制；原实例的 append-only 历史不受影响。

## 4. Windows 契约补验阶段

以同一账号的两个独立页面 A/B 制造个人版本冲突；用独立管理员会话操作默认。现场读取版本，不硬编码历史 revision。可区分的文字只用合成标记，secret 不出截图。

1. **C5 基础适配**：v1 初始化并存所有字段→托管者发布 v2→刷新显示待适配、旧文字仍在；旧 based 字段可普通保存、accept/reject 禁止；适配同名保留、新增预填、preparation 原文只读。纯预填关闭不制造 dirty；修改后关闭保留草稿并计入离开确认；完成提交完整 v2 map，成功后 current。
2. **V1/U3-1 远端已适配**：重建 v1 基线并发 v2。A 适配 theme=A，关闭保留；普通 theme=B。B 完成适配。A 普通保存真实409，GET读 current；明确保留后 B 在普通框、A 在参考区。返回取消保留两份；保存 B 后 A 仍可见且离开仍确认；明确放弃适配草稿后干净。另轮“载入最新”清全部残留。
3. **V1/U3-2 去重与不同字段**：每个变体用新基线重建。相同字段相同 A/B 仅留一份；不同字段两份 dirty 不丢，保存实际变更字段。仅普通 dirty、仅适配 dirty、纯预填关闭分别按既有语义核验。
4. **V1/U3-3 远端仍待适配**：重建 v1并发v2；A双草稿，B仅普通保存。A409后保留两份，普通保存后重开适配，参考文字回可编辑面；完整适配后干净。
5. **V1/U3-4 收缩契约**：新基线下教师保留 v1 个人版本，托管者先发 v2；A 在待适配编辑面输入 theme=A，关闭保留，再在普通面输入 theme=B 和 process=C。托管者发布 v3，B完成v3适配推进个人版本，再由A旧普通保存触发409。保留分流后普通文字、同名适配文字和被移除 process 都可见，普通保存请求不得包含已移除字段，参考保留至明确处置。细节严格对照原桌面 V1/U3-4，不强行写 disabled 控件；工具或可达流程不足记录受阻并回协调者，不自造 UI。

飞行窗口重复写、普通输入／放弃按钮禁用，适配／参考区返回确认及账号隔离按原交接核验。各场景发布后先得到托管者实际成功 manifest，再继续页面动作；发布和浏览器不是一次批量脚本。

## 5. C7 缺／错主密钥阶段

使用相同临时实例，每个状态都恢复 B_crypto 后开始，避免清除密钥影响后续子例。切换服务配置只由托管者执行；配置在进程启动时载入，因此必须实际重启临时 API，不靠修改文件或浏览器模拟宣称生效。

| 状态 | 真实状态及必验 |
| --- | --- |
| 正常 | K_good 下 UI 保存合成 secret，配置 GET200／has_secret=true／ready；为后续故障提供可验证基线 |
| 缺主密钥 | 进程 AI_MASTER_KEY 显式空（禁用 dotenv，排除其他 env 来源），有密文配置 GET200、ready=false、DECRYPT_UNAVAILABLE。带新合成 secret 的 PATCH503，缺 secret 的元信息 PATCH因保留旧密文需解密也503；输入保留，版本／head／审计无增量，固定错误不含原异常。清除仍成功，页面可以读取其他设置 |
| 错主密钥 | K_wrong 为另一份合法32字节材料，保留相同 key ID，确认失败来自解密而非 ID 格式；GET200／DECRYPT_UNAVAILABLE。省略 secret 保留原密文的 PATCH503及零增量。**显式提供新 secret 可由 K_wrong 重新加密，不能把此动作预期写成必然503**；如验证该路径，独立恢复基线后执行并如实记录，再另轮验证清除成功 |
| 恢复 | 停临时 API并恢复 B_crypto 和 K_good，重启后 GET200／ready=true、版本匹配；真实 UI 确认设置可用 |

缺与错两轮各定向确认登录、姓名／个人指导读取及既有手工日周和 Word 链路仍可用；仅写必要合成数据并按原恢复方法追加版本，真实下载保存文件和非空／CRC／SHA-256。不是 Office/WPS 逐页或完整 W6。不测试供应商、不调用 transport。

## 6. 复审、执行交接和收尾

先交 OpenCode [编码提示词](ai-slice1c-fixture-opencode-prompt-2026-10-07.md)。提交报告后协调者核对目标保护、事务／锁、拒绝零增量、无密钥输出及文件范围；通过后填实际源、端口、服务、私密账号／密钥位置、备份与恢复验证结果，形成可批准的远程执行清单。未经具体授权不建立远程临时资源。

Windows 本轮在原[桌面提示词](ai-slice1abc-desktop-codex-prompt-2026-10-05.md)基础上只接续上述剩余案例，补验前交接实际 URL／基线／阶段／manifest。证据包括浏览器与工具版本、真实 HTTP、个人／默认／契约演进、两份文字 DOM 区域、按钮禁用、离开确认及去敏截图。服务器故障证据与前端拦截模拟分开。

发生失败保留该临时场景、证据和私密配置，不覆盖未导出的 manifest。最后退出测试登录、关闭自建页面，恢复临时库与正常密钥并验证；远程资源退役另按明确范围执行，不做全局清理。原实例只进行获授权的只读身份对照。所有夹具补验完成后才讨论1A–1C正式收口，之后再考虑持久执行核心。
