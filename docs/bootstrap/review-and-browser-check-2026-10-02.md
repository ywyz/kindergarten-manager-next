## 审阅发现

### P2 导出中修改范围未使旧响应失效

位置：`frontend/src/views/DailyPlanView.vue:401–410`、`:448–461`；`frontend/src/views/WeeklyPlanListView.vue:147–175`、`:287–303`。

日计划范围/模式 watcher 只清空确认字段，没有递增 `exportSeq`；周计划范围没有相应 watcher。两处日期控件在请求期间仍可编辑。关闭弹窗、切换班级和卸载已有失效保护，但修改导出范围没有。

复现条件：为范围 A 发起导出，在响应返回前将控件改为 B。A 的 200 仍通过 seq 检查、关闭弹窗并下载 A；日计划 A 的 409 仍可将 A 的 facts 和 expected_context 写入正在显示 B 的弹窗。这是前端请求与当前选择不一致，不是服务端按错误范围查询，也不意味着服务端确认保护被绕过。

建议：沿用既有请求序号机制，范围/模式变更时使进行中的请求失效，并清理属于旧范围的确认/错误；保证旧请求的 finally 不清除新请求 loading。用可控制响应顺序的检查覆盖旧 200、旧 409、旧错误与新请求交错。此轮为静态控制流确认，尚未执行浏览器复现。

## 本机与浏览器实测

| 层 | 结果与证据 |
| --- | --- |
| 外部浏览器发现 | `cua.getState()` 返回浏览器发现错误 `nodeRepl.fetch request failed` |
| Edge 自动连接 | 重置 cua 会话后显式连接 Edge，仍同样失败；可看到 Edge 进程，不能据此推定扩展已连接 |
| 内置浏览器 | 显式选择 `iab` 成功创建并读取 about:blank 标签页；全局发现失败不等于内置浏览器不可用 |
| Windows 回环闭环 | 临时 Node HTTP 服务仅绑定 127.0.0.1、随机端口；内置浏览器实际读取标题“本机浏览器连接诊断”和“本机连接成功”。这是诊断页，不是产品页 |
| 项目服务 | Windows HTTP 请求 5173 和 8000/health 均被拒绝；内置浏览器访问 5173 返回 ERR_CONNECTION_REFUSED；检查时未见 5173/8000/13386 监听 |
| WSL | 沙箱内外 `wsl --list` 均提示未安装 WSL；这仅描述当前命令执行上下文，与 10 月 1 日记录不同，不能据此宣称用户已卸载原环境 |
| 产品验收 | 没有本轮产品下载、落盘文件、ZIP/哈希或 Word 逐页证据 |

诊断时项目错误页转为 data URL，复用该页导航受到工具 URL 策略阻止；未放宽策略，在同一已连接内置浏览器新建诊断标签页后正常读取回环服务。临时服务设定 120 秒自动退出，最终已核实进程退出码为 0。诊断页已请求关闭，项目错误页关闭受到同一 URL 策略限制，未标记为保留标签页。不变更项目端口、系统代理、防火墙、浏览器配置或全局 MCP。

## 剩余连接处理

本轮解决了“可否连接任何浏览器”的判断：内置浏览器可用，外部 Edge 仍受阻，未声称已修复 Edge。没有可用的原生桌面控制入口来操作 Edge 扩展/应用设置，也未强制结束用户浏览器或当前 Codex 会话。

[OpenAI 官方浏览器扩展排障](https://learn.chatgpt.com/docs/chrome-extension)建议核对桌面应用版本、重启浏览器、Settings > Computer Use 中的连接状态、扩展所在 profile，并在新对话重试。这里的后续操作需用户在桌面完成；不主动安装新 Skill/MCP 或扩大访问权限。本轮未证实 Edge 的具体根因。
