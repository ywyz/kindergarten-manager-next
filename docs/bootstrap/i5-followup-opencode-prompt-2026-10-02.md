## 2 复现并最小修复导出范围竞态

日计划 `DailyPlanView.vue` 的范围/模式 watcher 只清空确认字段，没有使旧请求 seq 失效；周计划 `WeeklyPlanListView.vue` 日期字段没有相应请求失效逻辑。日期控件在请求过程中仍可编辑。

复现：延迟范围 A 的请求，切换至 B，再释放 A 的响应。分别验证日计划/周计划旧 200，以及日计划旧 409。旧 200 不应下载 A 或关闭当前 B 弹窗；旧 409 不应把 A 的缺项与 expected_context 显示为 B 的确认信息。

沿用现有 seq 机制做最小修复，范围或模式变化时使旧请求失效，并清理旧范围确认与错误。覆盖旧请求 finally 与 B 新请求并行的情况，不能让 A 清除 B 的 loading。保留双击防重、关闭弹窗、切班和卸载行为，不为此引入新的前端测试框架。提供可重复的延迟响应验证证据，不以 typecheck 代替行为验证。若未复现，报告实际原因和代码依据，不机械套用建议。

## 3 恢复独立自动检查

仅在确认的 WSL 项目中按锁文件恢复依赖：后端 `UV_PYTHON_DOWNLOADS=never uv sync --locked`，前端按既定流程 `npm ci`。不要更新锁文件。

使用既有 I5 guard 和隔离 MySQL 8.4/InnoDB 资源，断言端口 13386、白名单测试库、Alembic head；凭据仅限进程环境。运行既有 I5 五组定向单测、后端全量单测、I5 集成、前端 typecheck/build 和 diff 检查。历史参考数量为定向 170、全量 533、集成 30 且 0 skip；报告本轮实际结果及差异。

只在隔离验证环境恢复 API/Vite。核实 Windows 8000/health、5173 以及 Vite /api 代理。不能把回环诊断页、模拟响应或 HTTP 200 当作产品验收。

## 4 完成真实下载和 Word 验收

当前已证实 Codex 内置浏览器可读取 Windows 回环诊断页，但 Edge 自动连接未恢复。先核实实际可用工具。外部浏览器若仍不可控，提供用户可执行的精确步骤；内置浏览器 UI 检查单独记录，不替代 Windows 下载落盘与 Word。

为本轮使用独立案例编号 `R01` 等，并映射旧案例的语义名称；不要复用两张历史表含义不同的 H 编号。

至少覆盖：

1. 普通单日、全空 409 确认、同班只读教师导出。
2. 长过程跨页与新增/替换标红；三份日计划乱序选择后升序合并、每份新页。
3. 调休、六/七列、停课、周范围相交去重、无匹配。
4. 当前/历史确认版本与警示头、未确认 404、跨班与待分配 403、管理员显式班级。
5. 实际选中日计划 32 份、确认周计划 9 份的 422；31/8 边界成功。日期跨度长不代表超限。
6. 双会话 context_changed，包括最新 facts 归零仍须重确认；双击；延迟关闭/切班/卸载；本轮新增的修改范围竞态。
7. 真实中文文件名、字节数、SHA-256、ZIP 完整性；失败不产生文件；object URL 清理。未复现前不要将立即 revoke 认定为根因。

在 Microsoft Word 打开实际下载文件，逐页检查修复/转换提示（Protected View 单列）、打印预览、截断遮挡越界、异常空白页、红字、动态列、快照字段。不要保存改写文件，关闭后复核哈希。每个成功导出核对服务端成功审计数量与非预期业务写入；取消前端接收不等于已取消服务端处理，分开记录。
