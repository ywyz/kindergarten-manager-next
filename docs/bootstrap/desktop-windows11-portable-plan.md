## 1. 下一步与可行性结论

下一阶段优先准备**包含当前备份／恢复能力的完整 Windows 11 内部便携候选**，补齐打包来源、归档、目标环境和手动验收证据。普通源码的实际原生文件操作及 Word 逐页工作，也纳入同一验收清单。程序包构建、静态核验、目标机实际运行、教师体验和公开发行分别记录。

可以在当前 Windows 构建机制作新的完整目录／ZIP 候选；签名证书不是生成候选的前置条件。是否能在另一台 Windows 11 运行仍须核对架构、运行组件、安全策略并实际测试。当前只能承诺准备和核验候选，不能先写“跨机可用”。目标架构尚未核对；本轮既有工具链为 **Windows x64**，若目标为 ARM64，不自动改栈或把兼容层当已验证。

已有完整备份通过 `.kgmbackup` 迁移应用档案、历史和受管照片。包内不携带个人数据库／备份／凭据。换机不复制 Windows DPAPI 材料；AI 密文保留，目标机按既有 P04 重新填写密钥，手工业务应可用。外部另存 Word、外部原图仍由用户另行保管。详见[备份规格 P01–P06](../specs/desktop-backup-restore.md#1-产品决定与集中确认)。

## 4. 构建与静态核验门槛

### 4.1 完整候选

- 沿用已确认的 PyInstaller **onedir／windowed** 路径，不增加安装器、自动更新源或新的打包组件。交接完整产品目录及 ZIP，不能只给主 EXE；使用现有 guard 允许的全新 build 直接子根，显式传参，不覆盖旧 r03 或旧体验目录。
- 来源冻结发生在前端构建和 PyInstaller 之前，结束后再次比较；包含实际生产宿主／维护／备份恢复／AI／更新／迁移／模板／构建代码。源码、只读前端输入和全部写入路径不得相交；临时报告与私有 source freeze 留在已声明私有根，不进入分发目录。
- 明确区分生产模块和验证辅助模块，检查当前 `maintenance_host`、`maintenance_lifecycle`、全部实际 `app.local.backup_*`／`restore_*` 依赖、凭据／runtime、0006及所需旧迁移、受控模板、前端和 Pillow 插件／许可证。不能只按文件名／数量宣称入包或同源。
- 构建实际 UUID 身份，使用已确认版本／schema；记录构建基线 commit、工作区改动及实际内容摘要，不把带变更的构建冒称纯 `91e6a553`。不虚构正式 Release 标签、下载地址、公钥或签名完成。
- 先后验路径并拒绝未知覆盖、祖先／子孙相交、只读输入落在将被清理的输出内、reparse／别名风险；不执行真实破坏性清理作为反例。不改变 Windows 系统保护或长路径系统设置。

### 4.2 不执行产物的独立检查

- B 的静态模式与冻结执行模式明确分开；静态核验不能启动主 EXE、资源探针、更新 helper 或隐含普通窗口。检查器打印“static”不等于满足本条，C 要拦截启动边界证明没有调用。
- 从实际 CArchive／PYZ 读取入口及仓内生产模块，按经核定的结构摘要与当前源比；模板、前端、迁移、许可证和必要二进制逐项核对。缺模块、缺资源、来源列表为空／过期、摘要不符均失败，不能由生产者自报清单单独自证。
- ZIP 清单为相对路径、字节数与 SHA，实际枚举文件必须匹配。解包前拒绝越界／绝对／驱动器路径、链接、大小写或规范化碰撞、重复成员及超出约定资源界限；不能先 `extractall` 再检查路径，也不能把 `..` 归一化掉当合法。
- 不含教师 DB／WAL／SHM、备份包、DPAPI／密钥材料、真实签名私钥、原照片、日志、EVIDENCE、`.env` 或构建机个人绝对路径。合法公开 CA 证书／供应商许可证仍须保留，不用笼统后缀过滤破坏正常依赖。
- 同时记录所有 PE 的实际签名状态；本轮证书未取得，候选明确标“未签名内部测试”。主 EXE 签名、全部代码可信与实际策略放行是不同证据，本轮不执行签名工具。
- 必需结果逐项为明确布尔，缺项／未知／非布尔不能通过；分别报告静态结果、冻结运行、目标机运行及人工确认。前轮“任意422当HMAC通过”“DTO当布尔”“漏比复合主键”等误证不能重现。

## 5. 目标 Windows 11 预检与实际使用

### 5.1 只读预检

D 的预检兼容 Windows 自带 PowerShell，检查系统／架构、候选完整性、WebView2 Runtime、适用的安全策略／签名状态和当前权限；架构必须实测，不把“Windows 11”直接当 x64。根据实际依赖说明系统组件，不随意要求 Python、Node、MySQL、开发工具或管理员模式。未知／访问受拒就记未知，不推断安全策略关闭或候选获准运行。

脚本只读系统，不执行应用、下载／安装、不改注册表／策略／证书信任、不创建防护排除项或移除来源标记。可写报告仅在用户明确选择的独立输出，避免输入／候选／用户数据别名，默认显示最小必要信息。原始诊断私下保留；对外记录不带机器名、SID、用户名路径或 secret。脚本自身受阻时记录实际限制，提供 Windows 设置里的手动查看方法，不使用 ExecutionPolicy Bypass。

### 5.2 实际测试按先后执行

## 6. Codex 审核和完成条件

Codex先审合同与职责，再独立读源／执行关键反例和必要回归，复核真实产物、资源／入口同源及完整性／隐私；失败交原唯一责任方修复直至通过。实际GUI和Word一次一个执行者，自动脚本不能替代人工评价。代码不变的后端848基线可在hash保持时引用；修改宿主、核心、前端时按影响重跑必要检查，不按旧数字填写新通过。

阶段结论必须能分别表达：**当前源码仍通过／内部候选静态通过／目标预检完成／目标普通运行未验或通过／教师体验未验或通过**。仅静态准备完成也应交付可用成果和实际未验项，不能因目标不可访问编造结果，也不重复等待没有变化的签名条件。

通过后由 Codex固定具体文件／blob／预期tree，原 OpenCode普通提交推送桌面分支；不夹带候选、DB／照片／凭据／日志，不修改 main、历史、tag或Release。不为回填本提交SHA造成循环提交。正式签名、远程发送／安装、目标机实际控制、应用真实AI、WebDAV、公开发行均不因本计划自动执行；后续实际授权和条件到位后另记。
